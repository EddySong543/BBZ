当此技能被调用时：

1. **定位目标**：要审查的设计文档（`design/gdd/**` 或指定文件）或某功能设计。

2. **对照设计文档标准检查**（`.claude/docs/coding-standards.md` 设计文档标准 + `.claude/rules/design-docs.md`）：
   - **8 个必填章节齐全**：概述 / 玩家幻想 / 详细规则 / 公式 / 边界情况 / 依赖关系 / 调节旋钮 / 验收标准。
   - **公式**：每条含变量定义、期望值范围、示例计算。
   - **边界情况**：明确"会发生什么"，⛔ 不许"妥善处理"这种含糊。
   - **依赖关系双向**：A 依赖 B，则 B 文档也提到 A。
   - **调节旋钮**：标安全范围 + 影响的游戏方面。
   - **验收标准可测试**：QA 能判通过/失败；⛔ "感觉良好"不算规格。
   - **平衡数值**关联到来源公式或设计依据。

3. **守信息三层分离**：设计意图 / 当前行为 / 架构方向 不可混淆；指出文档是否把"想要的"当成"已实现的"。

4. **输出缺口清单**：逐章列 缺失 / 含糊 / 不可测 / 依赖未双向 的具体问题 + 修补建议。不直接改文档（除非用户要）。

> 注：本技能审"玩法/机制设计文档"；UI 视觉规范走 design-system 技能，别混。
