# BBZ 自动化测试规范

GUT 的目标是保护玩法规则、数据边界和关键交互链，不负责冻结人工调节的美术参数。

## 保留的测试

- 战斗结算、英雄技能、道具、背包、快照与回放等确定性规则。
- 场景能实例化、正式资源可加载、关键节点或公开接口存在。
- 从输入到结果的关键交互链，例如点击移动、阻挡、进入战斗和返回流程。
- 曾真实发生且容易复发的重大缺陷；测试名称或说明应写明受保护的玩家结果。
- 跨组件不变量，例如双方动画循环需要同步时，只验证同步关系，不锁死某个帧率。

## 不进入长期全量套件的测试

- 精确 FPS、透明度、颜色、坐标、持续时间等可由人工反复调节的表现数值。
- Shader 私有函数名、源码片段或节点树实现细节，除非功能无法通过公开状态验证。
- Godot 引擎自身行为、一次性概念稿、已退役方案的否定清单。
- 依赖几十毫秒定时窗口的视觉节拍；这类内容由无截图探针和人工 F6 验收。
- 对同一场景逐节点、逐参数重复断言的“大清单”。

## 场景测试生命周期

1. 场景开发中可以临时增加细节契约，帮助定位正在调整的层、材质和交互。
2. 场景确认后，把细节契约合并为少量公开结果：可加载、关键层存在、核心交互可完成、历史重大回归不复发。
3. 后续手动美术调整不得因为精确参数测试失败；若参数不是玩法规则，就修改或删除测试，而不是反向改回画面。
4. 全量套件必须保持可重复、无截图、无任意等待，并以失败能够指导修复为准。

## 执行

- 全量：`& .\tools\run_godot.ps1 -Mode Test`
- 单文件：`& .\tools\run_godot.ps1 -Mode Test -Target 'res://tests/unit/ui/test_main_menu_world.gd'`
- 单目录：`& .\tools\run_godot.ps1 -Mode Test -Target 'res://tests/unit/expedition'`
- 局部迭代先跑单文件或单目录；准备交付、提交或合并时再跑全量。
