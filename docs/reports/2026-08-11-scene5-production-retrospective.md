# Scene5 制作复盘：金黄稻田

## 1. 最终定位与当前结构

Scene5 是 1920×1080 的金黄稻田战斗场景。它复用成熟 Battle Screen 的人物、UI、输入、战斗反馈和鼠标视差，只在 Scene5 内维护环境素材、层级、光照、风场和战斗响应。

最终环境从远到近为：

1. `Sky`、`SunRayField`、`SkyOverlay`；
2. 单层程序化 `UpperCloud/CloudMain`；
3. `HorizonHaze` 与 `DistantWheat`；
4. 复用正式远麦素材、但独立变形和调色的 `MidFarWheat`；
5. 高密度网格 `FarWheat`；
6. `MidFieldHaze`、`Atmosphere`、战斗平台与人物；
7. `NearWheatLeft`、常驻麦芒和战斗麦芒。

关键视差关系是 `DistantWheat 0.25 < MidFarWheat 0.32 < FarWheat 0.40`。景深来自轮廓、明度、运动频率和视差的共同差异，而不是简单降低某一层透明度。

## 2. 先建立层次，再做统一调色

早期画面只有天空、远景、FarWheat、平台和近景，虽然节点数量足够，但每层都像一张完整贴图，缺少相互遮挡和中间尺度，因此不能只靠全屏调色解决“贴图感”。

有效处理顺序是：

1. 先确认每张正式素材承担的距离角色；
2. 建立明确的远、中远、中、近景轮廓；
3. 用视差、空气透视和细节对比拉开距离；
4. 最后统一金色、粉紫天空和人物受光。

金黄主题不等于所有层都使用同一种高饱和金色。越远的麦田越需要降低暗部对比、减弱棕色描边并混入天空空气色；平台和近景则保留更深的棕色与清晰纹理。全局压暗或全局加金都会缩短景深。

## 3. 麦浪必须同时包含形变和受光

仅让亮金色区域横向扫过，表现的是移动高光，不是完整麦浪。Scene5 最终把麦浪拆成两部分：

- 几何部分：高密度网格顶点产生上下起伏和相位滞后的横向弯曲，根部固定；
- 受光部分：只识别原图已有的亮金像素集，使亮区随波峰迁移，不在暗金底色上绘制可见的透明圆或条带。

`FarWheat` 使用 128×28 网格，轮廓起伏明显；`MidFarWheat` 使用 96×20 网格，波幅、速度和细节更弱；近景使用更大的局部摆幅。这样才能形成“远层宽而慢、近层细而强”的风场梯度。

原 FarWheat 素材中的单株麦穗已经处于向一侧弯曲的姿态。代码可以改变成片轮廓、倾斜程度和波峰位置，但不能真正把绘死的单株麦穗还原为直立姿态。如果以后仍要求单株完整经历直立—弯曲，必须补充中性姿态或两至三帧正式素材。

## 4. 同一素材可以派生景深层，但不能原样复制

直接复制 FarWheat 会暴露相同的麦穗排列和亮色像素块，形成重影。最终通过以下差异把复制层转化为独立的 `MidFarWheat`：

- 放在 `DistantWheat` 与 `FarWheat` 之间；
- 横向拉伸、纵向压缩并错开位置，只让中远景轮廓露出；
- 使用更低透明度和更强空气透视；
- 使用独立周期、相位、波速和较小形变幅度；
- 使用介于两层之间的鼠标视差；
- 仍接入战斗风场，但响应弱于当前 FarWheat 和近景。

因此，复制素材只是节省美术资产的起点。真正产生景深的是“新轮廓边界 + 新视差速度 + 新运动频率 + 新空气透视”四项同时成立。

## 5. 接缝问题先找源像素，不用半透明层掩盖

`DistantWheat` 与 `FarWheat` 之间曾出现一条深金色水平直线。通过逐层隐藏的 A/B 截图确认，直线来自 DistantWheat 原图底缘一至两行不透明像素；早期它被 FarWheat 完全覆盖，后来顶缘透明柔化才将其暴露。

最终做法是只识别并裁掉 DistantWheat 的真实不透明底缘，同时恢复 FarWheat 原图高光。以下做法都不应再使用：

- 在接缝上增加半透明色带；
- 用整层渐变降低 FarWheat 顶缘透明度；
- 用更深颜色覆盖问题像素；
- 未确认来源就继续调整全局金色或亮度。

接缝诊断应先分别隐藏相邻层，确认问题属于哪张源图，再处理最小像素范围。

## 6. 慢速装饰的流畅度不能靠加速修复

Scene5 云层的反复调整证明：装饰物移动慢时出现卡顿，根因通常是时间采样、像素步进或插值方式，而不是速度太低。正确做法是保持装饰级速度，通过连续时间插值让每一帧平滑；不能为了掩盖卡顿而提高速度，让云层抢夺战斗焦点。

当前云层收敛为一个最明显的 `CloudMain`：

- 保留原有程序化轮廓，不重新生成另一种形状；
- 移除内部快速暗块和额外高低云层；
- 只从左向右移动；
- 使用连续运动混合，验证实际画面方向而不是只看速度参数正负号；
- 用较长时间间隔的截图判断位移，不能用相邻两帧判断低速动画。

## 7. 战斗响应需要方向判定和衰减曲线

基础波形响应只根据双方基础行动判断，不读取英雄技能或伤害数值：

- 波对波：两侧同时向中心响应；
- P1 波、P2 大波：从右向左；
- P1 大波、P2 波：从左向右。

响应强度采用“开始快、随后慢”的衰减曲线。中远景、FarWheat、近景和麦芒共享方向，但按距离使用不同幅度。战斗麦芒速度必须慢于早期版本，并复用随机化后的多片资产，避免四片完全相同的麦芒同步飞过。

## 8. 测试应保护语义契约，不复制手工构图坐标

场景制作期间，装饰树、远景、麦穗、云和雾的位置会由 Eddy 在 Godot 中持续手调。测试如果写死这些节点的 offset、position 或 scale，会把已经通过的手工构图误判为回归。

场景收尾时应保留：

- 正式素材路径和必要节点存在性；
- 远到近的节点顺序和视差递增关系；
- 全屏覆盖、无漏底和人物遮挡边界；
- 人物、战斗平台、交互区域等功能基线；
- 风场材质独立性、形变幅度范围和战斗方向判定。

应删除或替换：

- 装饰层绝对坐标和精确缩放快照；
- 已删除节点或被否方案的存在性断言；
- 只验证某次参数实现、却不保护可见行为的测试。

`.tscn` 和 Git diff 已经保存手工构图数值；自动化测试只需要保护不会被肉眼快速发现的结构与行为契约。

## 9. 本轮确认无效或代价过高的方法

- 用半透明圆形、球形或水平遮罩冒充风场；
- 只移动亮色带，却不改变麦田轮廓；
- 整张麦穗贴图做统一左右摆动；
- 增加多层几乎透明、互相抢色的程序化云；
- 为了让慢速云不卡而直接提高速度；
- 原样复制 FarWheat，不改变尺度、调色、相位和视差；
- 用全局压暗、全局加金解决局部层次问题；
- 在没有逐层 A/B 截图的情况下反复猜 Shader 参数；
- 用精确装饰坐标测试冻结仍在手工调整的场景。

## 10. 可复用验收清单

### 构图与景深

- [ ] 至少存在远、中远、中、平台与近景轮廓，不能只靠透明度区分。
- [ ] 相邻麦田层的尺度、视差、对比和运动频率不同。
- [ ] 复用素材时无法一眼识别相同轮廓和亮色块排列。
- [ ] 人物始终比身后中远景更清晰，但不脱离环境光。

### 动效

- [ ] 麦浪同时存在轮廓起伏和亮金像素迁移。
- [ ] 麦穗根部固定，越靠近叶尖形变越明显。
- [ ] 慢速云和麦浪通过时间插值保持流畅，不靠加速掩盖卡顿。
- [ ] 战斗响应方向由较强基础波形决定，并使用先快后慢曲线。

### 边缘与接缝

- [ ] 相邻层逐一隐藏后不存在源图底边直线、黑边或残留色带。
- [ ] 接缝修复只作用于确认过的问题像素，不使用宽泛透明遮罩。
- [ ] 角色阴影与近景遮挡层顺序正确。

### 验证

- [ ] 使用 `tools/run_godot.ps1` 完成 Import。
- [ ] 运行 Scene5 专项验证和完整 GUT。
- [ ] 检查 1920×1080 完整 BattleScreen。
- [ ] 使用多个时间点检查低速云、各层麦浪和阳光。
- [ ] 使用显隐 A/B 截图验证新增景深层确实产生可读差异。
- [ ] 检查波对波、左强右弱、右强左弱三种战斗响应。
