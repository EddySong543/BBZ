## 1. 当前结论

本对话已经完成的不是“100 件道具设计”，而是一套可以继续扩展的地基：

1. 二十件新版道具已经完成五维审批、全池碰撞、纸面冻结和单机原型接入；旧道具保留代码与资源，但不进入新版生产池。
2. 双方序列已经从错误的“左对齐”改为“唯一主行动固定在共同 0 拍”；道具可以排在主行动前后，系统只在缺位处补对齐等待。
3. PvE 已改为敌方先动态生成、校验并锁定完整本回合序列，再向玩家公开；玩家随后规划。
4. 任一出战英雄在一拍结束后确认阵亡，双方所有尚未开始的步骤一起取消；同拍已经启动的步骤仍全部结算。
5. 英雄整体冻结，仅完成 H03、H10、H17、H21 等明确获批的纠错；道具设计不得借机重做英雄。
6. 世界地图已收敛为七个玩法区域、十六张小地图；敌人设计从金穗沃土的晴风稻田开始。
7. 战斗开局取得规则已有一版更新方向：开局填满三个道具框并允许一次免费部分调换，第一回合锁定，第二回合起可用；后续补充花 1 能。该方向已获得口头认可，但尚未形成专项真相源，也尚未接入运行时。
8. 当前真正的设计闸门不是“还缺多少道具”，而是公开序列是否能持续制造两种以上合理解法。若敌人只公开一个攻击或防御，免费防御与回合末被动回能很容易形成固定最优答案。
9. 当前产品只开发 PvE 单机。未采用的扩展方向不得阻塞道具与敌人设计；未来若改变产品形态，另立任务重新审查信息规则。

## 2. 状态分层：不要把提案、纸面通过和运行时混在一起

### 2.1 已冻结且已有运行时原型

- 二十件新版道具及其当前名称、文案、费用、耐久、形状和价格。
- 新旧道具池隔离：新版入口只使用二十件池；旧道具不删除，保留复用可能。
- 道具与基础行动组成统一序列。
- 共同 0 拍行动锚点、对齐等待和同拍完整结算。
- PvE 敌方先锁定并公开本回合完整序列。
- 出战英雄死亡时双方后续步骤共同截断。
- 荆棘护腕由二耐久降为一耐久后的数据。
- H03 当前机制、H10 攻击强化、H17 技能名、H21 简化文案及相关结算边界。

### 2.2 已确认方向，但尚未形成完整专项规格或运行时

- 战斗开始时从真实背包填满三个道具框。
- 开局一次免费部分调换；可换任意子集，被换出的实例不能在同次调换中再次出现。
- 开局三件第一回合锁定，从第二回合起可用。
- 第二回合起，每回合最多花 1 能开启一次三选一并只补一个空框；不自动补充，不设付费重抽，新取得件仍下一回合可用。
- 敌方遵守相同的取得、费用、耐久和合法性规则。
- 敌方采用传统游戏 AI：合法候选生成、硬校验、个性化评分、近优候选中的受控随机、锁定公开；不依赖外部模型，也不读取玩家未提交操作。
- 敌人战斗装备和携带战利品分账；战利品在遭遇生成时固定，越早击杀不会得到更多货。
- 每个英雄最多一件装备；装备独立于战斗道具。红色收藏品偏非战斗收益或持续产出，白绿合成材料暂不扩成完整系统。
- 小怪可巡逻、追逐或搜索，玩家可以绕行、引开或等待；地图威胁可以高，但实际战斗频率保持中等。

### 2.3 尚未通过，必须在下一对话继续验证

- “公开序列困境门”：怎样保证公开信息不是答案表。
- 晴风稻田完整敌人生态、具体数量和每张地图的敌人子集。
- 三个普通敌人、两个精英和最终 Boss 的正式机制。
- 敌人评分因子、候选序列语法、随机带宽和难度梯度。
- 中低频战斗下的正式回合长度；目前只有建议区间，没有实测。
- 装备的精确定义、红色装备数值边界、探索装备生效者和叠加规则。
- 是否需要任何白色、绿色通用材料；当前默认不做，除非先出现明确消耗端。
- 公开序列若仍退化为固定答案时，是否启用“防 / 大防回合不获得回合末被动能量”等系统级备选。该方案仅是后备测试项，不是定稿。
- 新取得规则会改变旧的低 UID 成型概率，必须重新计算；旧 `PLAN 3 / PLAN 4` 概率不能直接沿用。

### 2.4 与本设计对话分离的 UI / 美术事项

- 仍有九件新版道具的正式资产、名称或表现调整等待用户后续导入与说明。
- 道具图鉴已提出加入价格和占格；能量左上、耐久右上的视觉语言尚未最终通过。当前最新耐久图标由用户提供，能量与耐久仍需统一尺寸并绑定道具框，避免右半页错位。
- 稀有度和属性条需要上移；占格只画手绘风格格子，不显示“占格”文字和“可旋转”字样；道具框内图像要统一视觉尺度并避免短柄铁钩等超框。
- 新版道具原图方向由外部资产决定，Godot 图鉴内不再统一旋转；背包内仍按形状支持旋转。
- `assets/sprites/items` 已按旧版 / 新版分流；一格基准为 32×32，长物件源图按格子比例准备。
- 战斗 UI 的能量和耐久角标尚属独立 UI 验收项。
- 这些属于 UI / 资产任务，不应挤占下一轮敌人与道具机制设计。

## 3. 本对话的完整演进

### 3.1 先把旧池降为历史材料

早期出现过旧 73 / 71 件、运行时 114 / 163 件等不同计数。它们分别来自历史审计、旧生产池和素材登记，不是新版通过池。最终规则是：

- 历史机制可以重合，重合本身不构成否决理由。
- 旧设计若天然符合当前序列语法，可以重新提交。
- 任何回归件都必须重新经过机制、费用、耐久、占格和价格五维审批。
- 旧代码不必删除；只要新版生产入口与旧池隔离，就可以保留复用价值。

这一步的教训是：碰撞表是“相似机制索引”，不是“禁止重合清单”。设计身份应由当前规则与实际选择决定，而不是由谁先写过决定。

### 3.2 第一批失败：复杂度和语言先于玩法失控

纸鹤、魔力壶、放血骨针、锈雨瓶、炼金天平等第一批暴露了三个根本问题：

1. 名称像机制标签或硬拼词，不像世界中自然存在的具体物件。“锈雨瓶”需要设计者解释，说明名字本身失败。
2. 玩家文案使用限定词和逻辑分支，读者必须看例子才能理解。
3. 基础池过早承担复杂规则，抬高入门门槛并占用后续扩展空间。

用户给出的纸鹤改写“选择我方一名队友，下一件道具改为作用于他”，以及锈雨瓶改写“双方出战英雄失去全部护甲”，确立了后续文案标准：一句普通中文说清目标和结果，不在描述里展示设计者的推导过程。

这批最终没有进入二十件池。可理解的机制片段不等于整件通过。

### 3.3 五件基础标尺把数值问题暴露出来

磨刀石、裂纹小盾、血药、银币、传送卷轴成为第一组真正完成五维的基础标尺。过程中发生了几次关键纠错：

- 磨刀石与 H05 龙御极表面重合，但道具是有限耐久、公开占框、逐次付费的临时接口；英雄是可反复改变打法的身份。因此允许共存。
- 裂纹小盾最初 1 费只给 1 甲、占格又大，属于机制简单但整卡巨亏。它证明不能只凭感觉填费用和尺寸。
- 血药的费用必须与大防、治疗溢出、保留基础行动的价值一起比较，不能用固定“1 能等于几点生命”换算。
- 普通切换是 0 费但占唯一基础行动；传送卷轴把它变成额外步骤，所以 1 费合理，3 费明显过高。
- 银币后来更名为瓶装能量，但仍是只减少下一件道具 1 费的零费连接件，不减少基础行动费用。

由此形成费用锚：0 费只做严格受限的连接和搬运；1–2 费是主力；3–4 费是局势件或构筑核心。高费用、低耐久、大占格和高金币都不能为一个不可反制机制免责。

### 3.4 运力、耐久与价格从“装饰数字”变成独立平衡杆

最初出现了占格和价格数量级严重失真：70 格背包里，简单基础件占用过多；按当时价格又会让普通满包轻易达到千万。随后固定：

- 主背包 70 格，保险箱 9 格，总运力 79 格。
- PvE 还要为食物、恢复、探索用品和战利品留空间，不能把 79 格都当战斗卡槽。
- 常规物件以 2–4 格为主；当前最大普通单品为 9 格。
- 形状是初始形状，背包中可以旋转；占格只承担空间价格，不发展邻接、朝向或连线机制。
- 长期目录耐久目标是 D1 55%、D2 35%、D3+ 10%。高耐久意味着更少格子换更多次功能，因此天然有远征价值。
- 常规金币密度约为 0.2 万–2.5 万 / 格；百万撤离应接近满载且整体质量较高。
- 满耐久价、残损价、战斗强度和市场稀缺性分开计算。

这一步的核心教训是：五维不是给机制补四个数字，而是五个彼此独立、共同决定携带价值的系统。任何一维失真都会让简单机制变成陷阱或必带品。

### 3.5 建立账本后，历史碰撞不再阻塞基础件

候选账本记录每件道具的当前状态、历史相似机制、费用、耐久、形状、价格、真实顺序、英雄交互、三件同名上限和反制。其目的有两个：

1. 防止旧稿、口头版本、运行时名称相互覆盖。
2. 找出机制网络中的孤岛、万能枢纽和重复身份。

用户随后明确：旧设计允许重合，只有当前完整五维不成立才应否决。账本因此从“防撞车”转为“可追溯的相似机制索引”。

### 3.6 分批基础件建立了二十件纵切池

基础件优先覆盖进攻、防守、能量、节奏、目标、护甲交换、转换和局势清除。研究《杀戮尖塔》《炉石传说》《宝可梦》等作品后，吸收的是结构原则，不是复制关键词：

- 简单单件可以通过持续局面和多目标选择形成复杂度。
- 连携应复用公开接口，而不是不断新增私有资源。
- 队伍、站位、生命与目标分布能把一次伤害拆成多个决定点。
- 公开信息只有在同时存在多项损失时才会形成取舍；只有一项威胁时容易变成答案题。
- 未来行为可以通过敌人身份和状态推断，但不必把整场固定脚本全部公开。

期间还有几个重要否决：

- 独立飞刀直伤绕开波 / 大波和防 / 大防，只能靠生命或护甲硬吃，没有明确反制，因此退出池。
- 护身符和魔法箭袋相当于额外增加一次基础结算点。由于游戏只有五种基础行动加一个主动技入口，它们可能过强；先暂缓，等具体怪物能提供清楚反制后再决定。
- 炼金坩埚由 T2 下调为 T1；食铁虫由 T1 上调为 T2。机制不变，修正的是数值与定位。
- 酸液陶罐改为 2 费，复苏石改为 3 费。
- “下一次……”可以存在，但不能成为批量制造顺序的唯一模板；当时二十件中已有八件该结构，后续应主动降低比例。

### 3.7 阶段五证明了小池能形成网络，但也暴露枢纽风险

二十件池阶段五的原始统计为：

- T1 12 件、T2 5 件、T3 3 件。
- C0 4 件、C1 11 件、C2 3 件、C3 2 件、C4 0 件。
- D1 11 件、D2 7 件、D3+ 2 件，正好是 55% / 35% / 10%。
- 合计 39 格、满耐久总价 53 万、平均约 1.36 万 / 格。
- 严格二件连携边 47 条，`C2(2)=95%`，顺序参与率 `S2=95%`，最大接口族 `Fmax=34%`。
- 五个真实三件链模板覆盖九件道具，三件链参与率 `C3=45%`，替代件率 `A3=80%`。

这些数字说明地基可以成网，但不能掩盖两个结构警报：

- 瓶装能量连接所有正费用道具，是有意的通用枢纽；不能把它的边数当作十六种不同机制深度。
- 猎鹰羽毛只有一个严格道具搭档，扩池时应补目标接口，而不是再加一个万能产能件。

二十件时没有 4 费道具不是缺陷。费用档不是收集图鉴，不能为了覆盖数字强行保留不合格内容。

### 3.8 实装和资产更名没有改变内部 ID

二十件以 `v2_` 内部 ID 接入单机原型。旧 ID 和旧代码保留，便于复用；玩家可见名称和资产逐步更换。此处最重要的工程教训是：稳定内部 ID 与玩家可见名称分离，能让美术和文案迭代不破坏存档与逻辑引用。

UI 调整过程中曾把道具设计、图鉴排版和预览图混到同一对话。用户明确纠正后，设计对话只继续英雄、道具和与之直接相关的整体玩法；图鉴和战斗框视觉应单独处理。

### 3.9 “左对齐”是一次应当更早发现的底层错误

旧规则把两边序列从左侧对齐。例如：

```text
原错误： [道具 A, 波] 对 [防]
结果：   道具 A 对 防；波 对 空
```

这会造成玩家明明选择了防，却因为对方多放一个前置道具而“防空防”。正确规则改为：

```text
拍位： -2      -1      0       +1
我方： 道具 A   道具 B   大波    道具 C
敌方： 等待     道具 D   波      等待
```

每方唯一主行动固定在共同 0 拍，前后道具按相对距离排列，缺位由系统补等待。等待不是玩家步骤，不收费、不触发效果。

这次纠错带来的设计纪律是：任何顺序规则都必须先拿最小反例测试基础动作是否仍相遇。复杂 Combo 不能建立在错误的跨玩家时间坐标上。

### 3.10 英雄交互纠错必须以真实结算为准

本轮明确修正或重申：

- H02 的强化波按“大波”结算，会消费大波类增益。
- H13 把大波拆成两次独立的波，不再算大波；等待中的一次性波 / 攻击增益只由第一段消费一次，不复制到第二段。
- H03 采用方案一：每失去 2 点生命，自身波 / 大波造成的攻击伤害增加 1；不再使用延后机制。
- H10 不再制造游离于波 / 大波之外的主动直伤。现在积累剑气并可在攻击时消耗全部：2 点使波穿防，4 点使波 / 大波穿大防；不额外加伤。
- H17 技能名改为“无我亦无穷”。
- H21 文案为“指定敌方一名队友，立即打断并替换敌方出战英雄。”它是共同 0 拍内明确批准的打断例外。

教训是：不能用“看起来像同类”代替动作身份。波、大波、拆分波、额外伤害和独立结算点会进入完全不同的反制管线，必须逐一写清。

### 3.11 出战英雄死亡后，双方后续步骤共同截断

用户最初直觉是：角色死亡就应强制结束本回合。最终规则采纳这一方向，并采用对称截断：

1. 同拍双方已经启动的步骤全部完成。
2. 处理死亡拦截、阵亡、击杀和队友死亡钩子，直到状态稳定。
3. 若任一当前出战英雄确认阵亡，双方尚未开始的后续步骤全部取消。
4. 被取消道具不付费、不耗耐久、不写使用历史。
5. 后备英雄单独阵亡不截断；结算后进入强制换人或终局。

早先“道具属于玩家，所以英雄死后仍应继续”的论证忽略了战斗节拍和玩家直觉。若一方出战位已死亡，继续播放后置道具会让换人、目标和胜负反馈变得割裂；对称截断则把“能否在 0 拍前完成准备、能否在 0 拍击杀以取消双方尾段”变成可读的策略。

### 3.12 完整公开敌方本回合序列解决猜拳，但没有自动生成策略

旧口径并不是“结算也不公开”，而是双方在选择时不知道对方计划，提交后按公开序列共同结算。助手曾把“选择时隐藏”和“结算时公开”混为一谈，造成重复落盘。随后用户重新开放规则：若最终胜负仍由隐藏的波 / 防决定，道具与排序再复杂也可能被一次猜错全部覆盖。于是 PvE 改为：

`敌方取得道具 → 动态生成合法序列 → 锁定并公开 → 玩家取得与规划 → 玩家提交 → 共同拍位结算`

它解决了两个问题：

- 玩家不会因为无法获知的关键二选一而否定前面的全部规划。
- 道具顺序、目标、能量和死亡截断可以成为有意选择，而不是押注后的附属修饰。

但它也暴露了更深的问题：公开信息若只有单一威胁，就会成为答案表。白板上：

| 敌方公开主行动 | 玩家基础答案 | 玩家回合后资源倾向 |
|---|---|---|
| 防 / 大防 | 攒 | 安全获得 2 点净能量 |
| 波 | 防 | 安全并获得 1 点净能量 |
| 大波 | 大防 | 玩家净耗 1，敌方净耗 2 |
| 攒 | 攻击或一起攒 | 才出现较明显选择 |

因此，真正的根因不是“公开太多”，而是三个条件叠加：

1. 玩家稳定后手。
2. 免费防御能硬解普通攻击。
3. 敌方一回合通常只提出一个损失点。

个性化评分 AI 只能决定敌人提出哪一道题，不能把一道只有唯一答案的题变有趣。隐藏 0 拍也不是首选，因为那会把最决定胜负的部分重新变成猜拳。

### 3.13 当前推荐的“公开序列困境门”

敌人设计应先使用以下标准，而不是立即修改公共能量：

- 每个普通敌人都有一个公开、可积累、不能长期无视的威胁或进度。
- 压力回合至少同时影响生命、能量、护甲、队友、站位、道具耐久或未来威胁中的两项。
- 同一公开序列至少存在两种理性应对，并承担不同代价：安全解、贪资源解、消耗品 / 打断解等。
- 本回合完整公开，但未来回合只通过敌人个性、冷却状态和场面推断；不把整场固定模板交给玩家背板。
- 纯波 / 防可以作为喘息拍，不能成为敌人的主要循环。

三个已经走通过的最小示例：

1. 收割机器人若本回合结束时没有受伤，就进入“高速”；高速时下一次波按大波结算，受伤后退出。面对公开的波，玩家可以防住但让它高速；也可以以波换血打断；还可以石灰粉后进攻，花道具和能量换无伤打断。
2. 低血匪徒公开 `-1 普通魔力药水 → 0 波 → +1 银质护臂`。防可以保血却让它留下护甲；波可以换血击杀并用死亡截断取消护臂；石灰粉后波可以花更多资源无伤击杀。
3. 敌人公开 `0 防 → +1 简易治愈法杖`。玩家可以攒并接受敌方治疗后备，也可以用大波穿防并争取击杀截断治疗，或把攻击改向其他目标、保存资源处理下一轮。

若三个普通敌人仍无法稳定通过该闸门，才进入系统级 A/B 测试。第一候选是“选择防 / 大防的回合不获得回合末被动 1 能”，但这会重算二十四名英雄、二十件道具和全部能量曲线，必须单独审批。

### 3.14 参考游戏真正提供的不是表面规则，而是决策结构

- 《炉石传说》用多个可持续存在、各有生命和攻击目标的随从分摊伤害与资源，使玩家不断决定清场、抢血、交换还是保留单位。可借鉴的是“同时保不住所有价值”，不是照搬卡牌或棋盘。
- 《暗黑地牢》让多名角色同时在场，技能受前中后排和目标排位限制。可借鉴的是站位与队伍生命共同制造代价，但 BBZ 不必复制四人同屏或完整排位系统。
- 《宝可梦》的深度不只来自属性克制，而来自队伍覆盖、招式选择、换人节奏、持续生命和信息判断。单次克制关系只是局部，整场资源分配才决定胜负。
- 《杀戮尖塔》让玩家看到当前意图，但未来行为仍受敌人状态和规则驱动；不同敌人迫使同一牌组改变资源优先级。可借鉴的是“当回合可规划、未来可推断”，不是固定模板背板。
- 《Into the Breach》证明完整预告攻击也能有深度，前提是玩家同时保护多个单位、建筑、位置和任务目标，无法用一个防御动作全部解决。
- 普通骰子、牌型游戏与《Balatro》的对照说明：随机媒介本身既不保证浅也不保证深。它们拥有更多组合、长期资源和多个评分出口；BBZ 的风险恰恰是所有操作最后收束为一个波 / 防终判。

因此参考游戏的共同答案不是“再加更多选项”，而是让同一回合同时存在多个无法全部满足的目标，并让本回合选择改变之后几回合的局面。

### 3.15 敌人、地图、掉落和装备开始形成同一套 PvE 闭环

当前敌人方向：

- 普通敌人：一句话可懂的独特问题，尽量复用公共动作、能量、护甲、目标、站位和未来威胁。
- 精英：一个独有机制加两项相互牵制的压力。
- Boss：战斗级规则、阶段变化或场地目标，不只是更高血量和更长固定脚本。
- 行为由合法序列生成器与个性化评分决定；已有固定候选序列只作为示例和测试，不是整套行为。
- 敌人可以有道具偏好，但不能因为目前只有二十件就给每个世界身份硬塞违和道具。身份机制先成立，道具只改变其解题方式。
- 战斗负载受费用和耐久限制；额外携带战利品在遭遇生成时固定。战斗中用掉道具不会让战利品减少，提前击杀也不会凭空多出货物。

地图与战斗节奏方向：

- 每个大区先定义约 6–8 个生态角色，再为小地图选子集，不统一要求每张图十二种敌人。
- 一次晴风稻田远征可出现约 6–8 个游走遭遇组；标准路线实际打 2–3 场，深入路线 4–5 场，清图上限约 6–7 场。
- 小怪可巡逻和规避，降低被迫超高频战斗。
- 因实际战斗频率下降，单场可延长到能产生多个决策转折；建议起点是教学 3–4 回合、普通 4–6、大型敌组 6–8、精英 7–10、Boss 10–14，但最终以实测为准，不能靠堆生命拖长。

装备与高价值物方向：

- 战斗道具是可排序、逐次付费、消耗耐久的物件。
- 装备每名英雄最多一件，持续改变该英雄或探索规则，不占战斗道具的语法位置。
- 红色收藏品偏撤离价值、营地触发或有上限的持续收益，不做无限实时挂机产出。
- 顶级红装可以触碰“伤害 +1”级别，但要定义为每次完整基础攻击总伤害 +1，而不是每段伤害 +1，避免多段攻击指数放大。
- 白绿材料系统只有先出现明确合成目标、产出节奏和背包取舍后才值得加入；当前最多保留一种通用废料，不建立多色材料链。

## 5. 当前规则总表

### 5.1 公共能量

| 项目 | 当前值 |
|---|---:|
| 初始能量 | 1 |
| 默认上限 | 10 |
| 回合末被动 | +1，供下回合使用 |
| 攒 | 0费，步骤内立即+1 |
| 防 | 0费 |
| 波 | 1费 |
| 切换 | 0费，占唯一主行动 |
| 大防 | 2费 |
| 大波 | 3费 |
| 道具 | 0–4费，每次使用重新支付 |

前缀能量必须逐步合法。前一步产生的能量可以支付后一步，后一步收入不能倒付前一步。

### 5.2 取得与框位

最新已认可方向见 2.2；它尚未替换旧专项文件。正式落盘时必须明确：开局抽样来源、部分调换后的无放回边界、三个框是否必须填满、第二回合起每轮最多补几次、没有空框时能否开启、敌人是否完全对称、死亡与战斗结束时实例如何归还。

在这份修订完成前，旧“开局空框、每回合免费三选一”的概率报告只能解释历史基线，不能作为新规则的最终成型率。

T1 / T2 / T3 都是可以直接进入同一取得入口的成品。当前不设通用图纸、固定合成、白绿材料必修链或统一升金路线；个别事件或物件未来可以拥有自己的制作规则，但不能变成所有道具的共同前置。

### 5.3 五维和平衡

- 每件同时审批机制价值、逐次使用费、耐久、固定初始形状 / 格数和金币价格。
- 稀有度不机械绑定任何一维。
- 0 费件不能单独稳定产生正收益或无损循环。
- 1–2 费件承担主力；3–4 费件承担局势改变，但不能用费用掩盖无反制。
- 三件同名必须计算总费用、总使用次数、占格、公开框占用和最坏结算。
- 每件必须有不依赖指定英雄的用途。
- 满耐久和每个残损状态分别定价；临时件可显示真实估价，但不可兑现。

### 5.4 顺序与 Combo

- 顺序深度来自已经改变的能量、护甲、生命、状态、目标、站位、耐久、框位或公开承诺。
- 不用“若攻击前 / 后”硬写两个分支。
- 若一种顺序永远优于另一种，或先用等于浪费，不得称为顺序博弈。
- “下一次”不是禁词，但不应成为主力模板。
- 每条 Combo 必须走完费用前缀、持续时间、站位、合法目标、相对拍位、同拍规则、死亡截断和可见反制。
- 两件都加伤、所有产能件都能付费、同属一个标签，不自动构成 Combo。

### 5.5 命名与玩家文案

- 名称必须像自然存在的具体奇幻物件，文化气质保持中性，不硬拼伪古风或西幻术语。
- 玩家文案原则上只有一句普通中文；不看例子也能理解。
- 先写清“作用于谁、发生什么、何时生效”，再删字。
- 基础件只表达一个核心功能；复杂度放在物件之间和敌人问题之间。
- 对用户汇报必须简洁、易懂；长细节放文档，但关键判断不能只埋在文件里。

## 7. 本对话最重要的经验与教训

### 7.1 先证明基础决策成立，再扩内容

二十件道具可以形成漂亮的网络指标，也可能被一个基础“防”全部压过。内容数量、Combo 数和策略深度不是同一件事。任何扩池前都应先问：玩家是否面对至少两个不能同时保住的目标？如果没有，新增道具只是增加答案的写法。

### 7.2 公开信息不等于策略深度

隐藏关键动作会产生猜拳；完整公开单一威胁会产生查答案。策略来自公开信息下的资源冲突、多目标压力、未来后果和位置选择。正确目标不是“公开多少”，而是“公开后仍有哪些东西无法同时做到”。

### 7.3 动态 AI 不能补救单调题目

评分系统能让敌人根据血量、能量、护甲、队伍和冷却选择不同序列，但若每条序列都只有一个硬反制，玩家仍只是识别标签。先设计有取舍的题，再设计评分系统挑题。

### 7.4 简单单件，复杂组合

基础件的一句话越直观，越能在多个敌人和队伍环境中复用。把复杂度塞进一件道具，会提高阅读成本、减少搭档并压缩未来空间。复杂度应来自公共接口相互作用、顺序、目标和敌人状态。

### 7.5 “额外结算点”是最高风险权限之一

独立直伤、额外波、额外防都可能绕过五种基础行动和一个主动技的稀缺结算位。它们不能只靠费用、耐久或占格平衡，必须先证明存在明确反制和环境需要。

### 7.6 道具和英雄可以表层重合，但不能权限同构

有限耐久的一次窗口可以触碰英雄已有接口；稳定、可重复、无需公开准备的完整循环仍应属于英雄。判断重合时看频率、成本、持续时间和反制，而不是只看文案里是否都有“+1 伤害”。

### 7.7 任何顺序规则先跑最小反例

行动锚点的错误证明：先画复杂序列并不能替代基础对攻测试。以后每次改时间轴，至少先检查 `[道具, 波] 对 [防]`、双方同拍致死、0 拍前后换位、0 拍击杀截断和同拍建立 / 清除状态。

### 7.8 文档必须区分当前真相与历史原因

本对话多次出现旧取得方式、旧左对齐、旧道具名和当前运行数据并存。新文档应明确标注“历史”“已冻结”“已实现”“仅方向”“待验证”。重复落盘不是问题，互相都声称自己是当前真相才是问题。

### 7.9 对抗式审查是设计职责，不是用户兜底

用户提出方案时，助手不能只帮忙细化。应主动寻找：

- 是否存在稳定支配策略；
- 是否有最小反例；
- 是否把旧问题换了形式；
- 是否用内容补系统缺口；
- 是否与费用、拍位、死亡、目标和英雄身份真正兼容。

本轮助手没有及时指出左对齐导致防御失效，也没有在首次提出完整公开时立即白板推导免费防御的答案表，这是明确失误。之后所有核心规则提案都应先做对抗式审查再赞同。

### 7.10 展示方式也是设计效率的一部分

复杂审批卡可以留在文件；聊天中应先给一句效果、五维短表、一个真实顺序、一个组合和一个反制。用户不应从长段落里寻找结论。重要风险必须直接说，不能只写进文档。

同时要检查最终渲染，不让 `**` 等 Markdown 标记原样显示给用户。格式错误本身虽不改变机制，却会显著降低长审批内容的可读性。

## 8. 仍需重点观察的风险

1. 公开序列答案表：当前最高优先级。
2. H21：2 费、每局两次、确定打断公开的基础行动并强换人，若敌人压力集中在 0 拍会成为固定答案。
3. H08 + 银鳞甲：公开安全回合可能让低费大防留存稳定循环。
4. H10：公开防御等级提高剑气穿防兑现率，需验证是否让防御敌人只有唯一解。
5. H02：公开攻击会提高成功防御和升级波的稳定性，但其升级状态也会成为敌人下一轮可读状态。
6. 复苏石：连续复活链和 1 血后备的换位价值。
7. 瓶装能量：通用费用枢纽，扩池不能继续靠它制造虚假连携率。
8. 猎鹰羽毛：严格搭档不足。
9. 耐久比例：荆棘护腕调整后 D2 偏少，后续自然补齐。
10. 开局三件和付费补充：旧低 UID 概率全部需要重算，且要检查是否反而让小背包更稳定直奔 Combo。
11. 战斗延长：必须靠多个决策转折，不能靠高血量、固定循环和背板。
12. 随机战利品：必须与敌人战斗道具分账，避免“先杀更肥”或敌人用掉大红导致掉落价值波动。
13. 装备：全伤 +1 必须限定每次完整攻击总量，防止 H13 等多段结算放大。

## 9. 最大盲点

本对话中用户最大的盲点，是一度把“消除隐藏猜拳”近似等同于“增加策略深度”。完整公开确实修复了玩家无法掌控胜负的问题，但如果敌方每回合只提出一个威胁，玩家作为后手就会从猜拳转为查答案：看到波就防，看到防就攒，看到大波就大防。

更深一层，是曾试图用更多道具、更多顺序和更聪明的敌人评分来解决一个基础决策结构问题。内容只能放大已经存在的取舍，不能稳定地替一个没有取舍的底层循环制造深度。

值得说明的是，用户后来亲自发现并提出了这个问题；本轮更严重的责任在助手：面对左对齐和完整公开两个核心改动时，没有第一时间用最小反例和支配策略审查进行对抗性验证。

下一轮最重要的习惯应是：每次改变底层规则，先寻找一条跨局面都成立的固定最优策略。只要存在，就先修决策结构，不扩内容。
