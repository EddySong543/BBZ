## 1. 当前一句话结论

道具系统已经完成规则层封板：

`主动免费三选一 → 取得结果公开并锁定本回合 → 下一回合起可用 → 使用时支付该件费用 → 与基础行动共同排入行动序列`

这套规则是 **PvE 与未来 PvP 通用规则**，不再讨论“PvE 是否沿用”。当前尚未完成的是具体道具内容、统一序列 UI 与运行时迁移，不是基础规则审批。

## 2. 本轮对话从头到尾的演进

### 2.1 从旧池和 73 件身份审计开始

最初工作从现有英雄、旧道具池和 `2026-08-21-hero-item-identity-boundary-audit.md` 开始。该审计把当时 114 件实装道具分为：73 件标准候选、29 件来源池、10 件待重写、2 件冻结。

随后明确了两点：

- 73 只是一次英雄—道具权限审计得到的上限，不是新版 Demo 的最终清单；不能合并稀有度，也不能只报一个压缩后的代表列表。
- 剩余旧道具可以暂时隐藏，但资源、脚本与注册信息应保留，并能按 ID 单件恢复；不能依赖翻 Git 历史找回。

对话中还出现过“当前 71 件”的中间口径，反映的正是冻结、移出来源池和“首要 73”标签之间的真相源漂移。71 与 73 都已经是历史计数，不能再用其中任何一个代替新版清单。

后来决定“全部重新设计”后，旧 73 件与旧 114 / 163 件进一步降为历史素材和撞车表。任何旧件若要回归，必须按当前完整审批卡重新提交。

### 2.2 传说道具取得方式反复绕路

先后讨论过图纸铸造、蓝紫合成、双紫合成、T2 消耗能量进化、直接携带 T3 等方案。结论是：

- 图纸和固定配方过于绕，学习成本高；
- 通用升级线会鼓励玩家直奔金色，并让中低档道具退化为燃料；
- T1 / T2 / T3 成品都可以直接作为真实战备资产进入同一候选系统；
- 不设通用图纸、统一合成公式或固定升金路线；个别事件、商店或道具以后可以拥有自身的制造 / 转化效果，但不是系统必修课。

真正解决“开局抽到传说就建立巨大优势”的，不是再套一层解锁，而是后来确定的 **免费取得、锁定一回合、使用时逐件收费**。T3 仍要承担公开、框位、使用费、耐久、资产风险与对手绕行。

### 2.3 PvP 背包与匹配只是历史方向

曾讨论过 12 胜制、背包价值上限、场后事件 / 商店路线、相近战力优先匹配和以小博大。这个方向说明金币价值、单格价值与匹配战力不能混为一个数字，但它不再是当前产品任务。

当前产品只推进 PvE 单机；PvP 功能已经通过总开关休眠，联机源码和测试保留。单机 Demo 完成后若恢复好友对战，再单独审批房主权威、网络同步、匹配与连续 Run，不让这些问题阻塞道具内容。

### 2.4 发现旧道具只有“放大波波攒”，没有足够操作感

对旧池组合的审查发现：许多道具只是加伤、加能、加盾、攒层或针对另一状态。它们可以配合，却很少改变玩家这一轮的判断，所谓 Combo 常常只是数值叠加。

关键诊断是：波波攒每回合原本只有一个操作点和少量公共动作。照着这五个分支不断做差异化，最终只会得到更多“放大波 / 攒”的按钮。道具需要新增的是 **操作时机与结算顺序**，不是更多封闭资源。

从炉石等游戏吸收的不是场面规模，而是“同一组资源按不同顺序打出会产生不同结果”。从 Backpack Battles 等构筑游戏吸收的是反复复用公共接口和“来源 → 转换 → 兑现”，而不是邻接、朝向、攻速、冷却或自动循环。

### 2.5 顺序设计从伪顺序走向真实状态变化

早期曾把“若攻击前使用”“若攻击后使用”写进道具，或举出只有唯一正确顺序的例子。用户明确否决了这些做法：

- **合格方向**：破魔矢、蜕毒蛊、回声符。前一步真正改变了伤害、状态分布或可复制对象，后一步读取新状态。
- **不合格方向**：噬铁虫·重设计、回锋鞘·重设计。它们只是为顺序硬写 `if / else`。
- **伪顺序**：魔晶与坩埚。如果先用魔晶等于白白浪费、后用绝对更赚，这不是博弈，只是正确答案测试。

最终原则是：

- 效果默认只影响其结算后的事件，不追溯已经完成的步骤，因此玩家文案一般不写“此后”。
- 好顺序要让 `A → B` 与 `B → A` 在不同合理局面中各有用途，而不是一边永远亏。
- 顺序差异必须来自已经改变的能量、生命、护盾、状态、目标、道具位置、耐久或公开承诺。

### 2.6 交互从“统一结算”改为可编排序列

道具采用拖拽施放：

- 按住左键拖出但未松开，只是本地预览，不发生使用；
- 在合法区域松开，才把该道具加入本回合待提交序列并播放本地反馈；
- 玩家继续加入道具或基础行动，形成例如 `[道具 A, 波, 道具 B]` 的行动序列；
- 松手后的撤销、重排、非法区域回弹和目标选择手势仍属于后续 UI 设计，不影响机制封板。

回合结算必须按权威事件流重新播放道具和行动动画，并提供动作列表。否则长序列结束后，玩家无法知道能量、耐久和状态为何变成当前结果。

### 2.7 双方行动序列与统一术语

2026-09-03 对抗复核后，跨玩家坐标改为“双方唯一主行动固定在共同 `0` 拍”；各自主行动前后的步骤仍保留原顺序与距离：

```text
拍位： -2      -1      0       +1
P1：   道具 A   道具 B   大波    道具 C
P2：   等待     道具 D   波      等待
```

这样防与攻击一定在 `0` 拍相遇，前置道具数量不能制造“防空防”。同一拍中双方已经开始的步骤都完成；网络到达顺序、玩家编号和内部遍历顺序都不能制造先后手。

主行动内部继续沿用既定子顺序：双方先付费，普通切换先完成，即时主动技随后完成，攻击伤害最后落账。H21 只对五种基础行动保留同拍打断；H17 / H22 等已经启动的主动技不会被同拍伤害或 H21 静默吞掉。

正式术语为：

- **行动序列**：一方本回合排好的完整步骤；
- **行动位**：双方同时结算的一处位置；
- **对齐等待**：为保持共同 `0` 拍而补出的空位，不收费、不触发，也不属于玩家提交步骤；
- **延后**：系统在一方下一真实步骤前插入一个空行动位，不取消、不替换其原步骤。

H03 的旧序列延后只能影响 `0` 拍后的少量步骤，已经失去主体价值，当前重新进入方案审批；旧实现暂留兼容，不代表机制继续通过。

### 2.8 英雄机制纠错

英雄整体设计保持当前定稿，本轮只修复过明确不成立或过强的个案：

- H06：英雄图鉴的“受到攻击使其获得毒素”保持不变；效果图鉴改为“中毒英雄被大波命中时，引爆并清除全部毒素”。这样普通攻击可以积累，大波负责兑现，不会刚挂上就被下一次任意攻击立刻清空。
- H20：`触邪【羊】攻击命中敌方英雄时，直到下回合结束，使其获得脆弱。` 本回合挂上，下一回合若再命中可以兑现；没有继续进攻则自然消失。
- H03：旧“对攻抢速”和后来的“命中后延后”均不再作为通过方案；保留进攻身份，等待新方案审批。

这些修正进一步确认：英雄负责反复改变打法，道具只提供一次窗口、桥接或兑现，不能让任意阵容无条件复制英雄完整循环。

### 2.9 第一轮全量重设计暴露语言与核心池问题

决定无视旧道具、重新设计核心 T1 后，首批提案主要失败在以下方面：

- 名称像抽象机制标签或硬拼的二三字词，不像奇幻世界里真实存在的物件；
- 玩家文案是压缩数学句式，不看设计解释就无法理解；
- 核心 T1 强依赖 H06、H20、H11 / H12 等特定英雄或少数状态，没有对应英雄就成为空道具；
- 所谓 Combo 没有检查持续时间、站位和合法目标，例如把短时脆弱移给无法被攻击的替补；
- 机制依赖大量“下一次 / 下一个”，把所有顺序深度都做成延期标记；
- 为了塞进档位，频繁增加“最多 X 点”等上限，既难读又像人工刹车。

命名与文案标准由此明确：

- 名称首先是自然、具体、有奇幻感的物件，例如“残缺的佛像、盗版太极图、爆裂卷轴、毒药瓶、不动明王甲、不死鸟的羽毛”；
- 不限制东方或西方，也不限制“XX 的 XX”，但不能公式化批量命名；
- 玩家文案必须是一句普通中文，直接说明选择谁、发生什么、何时兑现；
- 物件逻辑要与效果相符，不能像“一瓶倒流的圣水使攻击不造成伤害，因此治疗”这样靠解释搭桥。

“下一次”并非禁词，但不能成为顺序设计的唯一工具。永久状态变化、即时资源变化、目标改变、框位移动、耐久消耗、交换和公开承诺都可以自然制造先后差异。

“贪财鬼的盾牌、会发芽的魔力种子、巫医的红蜡烛、没有指针的罗盘、会学舌的魔法书”等曾被评价为可继续发展的基础模板，但并未因此获得完整五维审批；它们和“借温烛”等中规中矩的连接片段都只能作为灵感，不能在新对话中直接标记通过。

### 2.10 第二轮纵切样本再次失败，进一步提高审批门槛

15–20 件跨档纵切的试设计仍未通过，典型问题包括：

- **封魔瓶**：只有 H09 摧毁 / H22 清空时有意义，重复犯“核心件依赖特定英雄”的错误；
- **鬼市当票**：只是把道具放回背包，却被高估为 T2；
- **黑市账本**：机制可探索，但示例中的两种顺序一边明显更优，不是有效博弈；
- **饮血戒指、记仇的盾牌**：为了限制梯度写成长句和上限，不如直接、自然的基础效果；
- **替命金币**：例子没有走通真实结算；
- **半碗忘川水、颠倒坩埚**：基础池文案过长、关键词过多；
- **空铠甲**：费用高、占格大、耐久低且效果弱，五维共同决定其性价比失败。

因此，这一整批不能视为通过。个别机制片段即使“可探索”，也只能作为下批灵感，必须重新提交完整五维卡。

### 2.11 五维平衡从遗漏项变为硬门槛

道具不能只报机制。每件正式候选必须同时提交五维：

1. **机制价值**：裸用下限、普通常态、理想 Combo 峰值和它改变的选择；
2. **逐次使用费**：`0–4` 能，每次使用都重新支付；
3. **耐久**：实体能使用几次，以及每多一次的边际价值；
4. **占格**：固定形状和格数，只承担背包空间价格；
5. **金币价格**：正常显示价值、可兑现价值、满耐久价、残损曲线和单格价值。

三项关键纠错：

- 能量、伤害、治疗和护盾没有恒定汇率，只能规定价值范围并按场面评估；
- 耐久不随稀有度上升，要看重复一次是否更强、是否形成循环，以及物件名是否支持复用；
- 占格不随稀有度上升。搜打撤允许强力、昂贵又紧凑的高单格价值珍品，占格是独立平衡杆，不是惩罚高稀有度的表格。

临时件仍显示同名、同耐久物品的正常估值，只通过“临时”标记说明不可出售 / 带出；其可兑现价值为 0，战斗能力照常计算。

### 2.12 金币量级与搜打撤经济

旧金币基准过小，已整体上调。成功撤离的初始目标为：

| 撤离结果 | 带出总值目标 |
|---|---:|
| P25 | 8万–12万 |
| P50 | 20万–30万 |
| P75 | 45万–65万 |
| P90，大赚 | 90万–120万 |
| P99 | 250万–400万 |
| 极端 Jackpot | 800万–1000万 |

“百万撤离”是明显的大赚，“千万撤离”是极端软上限。金币贵不能证明战斗内超模合理；匹配战力、机制价值与市场价格是三套不同指标。

### 2.13 抽取问题最终被一个基础改法解决

经过指定选取、稀有度限制、升级、合成和不同匹配方案的反复讨论，最终采用：

1. 玩家主动决定本回合是否抽取，不自动抽；
2. 每回合最多一次，抽取本身免费且机会不累计；
3. 有空公开框时，从真实背包合法 UID 中无放回展示至多 3 件；选择 1 件或放弃，候选不刷新；
4. 选中件进入公开框并锁定本回合，从下一回合起可用；
5. 使用时支付该道具自己的 `0–4` 能费用，多耐久件每次都付；
6. T1 / T2 / T3 使用同一入口，没有通用升级门。

这直接把“取得广度”和“战斗强度”分开：玩家可以持续接触道具、发展构筑，但不能把新抽到的强件当成无信息即时爆发。

免费取得是有意的重心选择：在每回合固定获得 1 能的基线下，如果抽取仍花 1 能，它会与「波」等价竞争，显著降低玩家主动抽取的频率、拖慢两件 / 三件链，并把体验重新拉回基础波波攒。抽取免费让游戏更偏向道具搭配；锁定一回合、公开框、使用费、耐久和背包风险负责限制战力，因此“免费取得”不等于“免费效果”。

当前确认：这不是 PvP 专属方案，而是 PvE / PvP 通用基础规则。先前文档里“PvE 是否沿用待审批”的表述是路线整理错误，现已纠正。

### 2.14 能量与检索基线已经完成

当前白板：初始能量 1；回合末被动 `+1` 供下回合使用；「攒」在行动步骤即时 `+1`；「波」1 费、「防」0 费、「大波」3 费、「大防」2 费、「切换」0 费但占行动。

道具费用为五个整数档：

- 0 费：严格受限的连接、搬运或风险工具；重点防无损循环；
- 1–2 费：主力区间，与本轮公共行动直接争能；
- 3–4 费：正式的局势件和 build-around 空间，可以改变局势，但不能无反制结束对局。

每回合最多取得一件并锁一回合，因此单件最早第 2 回合、两件链最早第 3 回合、三件链最早第 4 回合完整可用。

50 / 75 / 100 是总目录规模，不直接进入单场成型率公式。新道具尚未设计时，只能先建立结构覆盖目标，不能伪造实战 Combo 概率。真实成型率要等 15–20 件纵切通过后，代入实际可抽 UID、兼容件数量和携带方案计算。

### 2.15 PvE 优先与阶段 0

最终产品路线调整为：先完成有深度的单机 PvE，不要求当前同步开发 PvP。理由不是否定好友对战，而是：

- PvE 可以复用行动序列、道具构筑和背包经济；规划阶段双方看不到对方本回合提交的序列，双方确认后在结算阶段公开完整序列并逐行动位播放，部分 Boss 可以在规划前额外公开意图；
- 单机更适合当前项目规模，不需要先承担服务器、房间迁移、NAT、中继和长期运营成本；
- 未来好友对战仍可采用玩家电脑作为权威主机，但在单机 Demo 完成后另立任务。

阶段 0 已完成：主菜单只保留远征；匹配、BP、局域网大厅、段位和 PvP 战绩不可达；直接进入旧 PvP 场景也会被守门；联机源码、测试和旧战绩数据保留。

## 3. 当前定稿规则

### 3.1 设计身份

- 英雄决定玩家反复怎样打；道具决定这一轮怎样准备、连接或兑现。
- 核心道具必须在没有特定英雄时仍有独立用途，并能连接多名英雄和多件道具。
- 只对毒素、脆弱或某一英雄技能有用的适配件，可以留给后续扩展池，不能占第一批核心语法位。
- 道具可以短暂借用英雄权限，但不能稳定复制英雄完整生产—连接—兑现循环。

### 3.2 机制与 Combo

- 优先复用波 / 大波、攒、能量、防 / 大防、生命、护盾、命中、切换、目标、公开道具框、背包和耐久。
- 不为凑 Combo 新增幸运、热量、攻速、冷却、宠物、邻接、朝向或另一套封闭资源。
- Combo 必须改变玩家或对手的实际行动选择；“两件都加伤”不自动构成 Combo。
- 每个宣称的 Combo 都必须走完持续时间、站位、合法目标、费用前缀与实际结算。
- 好顺序来自真实状态变化；拒绝硬编码前后 `if / else`、唯一正确顺序和“先用等于浪费”的伪题。
- 一定随机性和广度可以在 Demo 扩池阶段加入，但第一批纵切首先验证公共语法和可读反制。

### 3.3 名称与玩家文案

- 名称必须先像一个真实、具体的奇幻道具，再体现气质；不限定文化方向或固定句式。
- 禁止抽象机制名、硬拼伪古风词和批量公式化的“XX 的 XX”。
- 文案原则上一句话，普通中文，不看解释也能理解。
- 先说清目标、效果和时点，再删字；不能为了短而压缩成数学句。
- 名字、物理形态、耐久和机制必须符合直觉。

### 3.4 稀有度与价值

- T1：机制价值通常 1–2，核心件通常高于 1；简洁不等于低价值。
- T2：机制价值通常高于 2，连接多个公共轴或改变一次计划；不能只是 T1 数值翻倍。
- T3：机制价值通常高于 3，并相对 T1 / T2 产生质变；可以是 3–4 费局势件。
- 稀有度不固定使用费、耐久、占格或金币，也不要求高档严格支配低档。
- 不设通用图纸、材料合成或升金路线。

### 3.5 取得、锁定和使用

- 每回合行动规划前，玩家主动决定是否打开一次免费三选一；不自动抽取。
- 必须有空公开框；当前基线是 3 个公开框，开局为空。
- 候选来自真实背包实例，按 UID 无放回抽取；不足 3 件时展示全部，不补假件。
- 候选固定，无免费刷新；选择 1 件或放弃，都会消耗本回合机会。
- 取得结果公开，选中件锁定本回合，从下一回合起可用。
- 每次使用支付自身 `0–4` 能费用并扣 1 耐久；合法使用即使被反制或收益为 0，也不退款。
- 有剩余耐久的占框件不能免费替换；耐久归零后按清理时点腾框。
- 当前 Demo 不含付费重抽；未来若增加，按新规则重新审批。

### 3.6 行动序列与表现

- 道具和唯一基础行动共同组成行动序列，可在行动前后任意交错。
- 双方唯一主行动固定在共同 `0` 拍；其他步骤保持相对位置逐拍结算，同一行动位已经开始的双方步骤都完成。
- 对齐缺位由系统补成无费用、无触发的等待，前置道具数量不能让攻击绕开防御。
- 权威效果可以插入“延后”，但客户端 / 玩家不能主动提交空行动位。
- 每个道具步骤固定为：合法性与当前能量检查 → 付使用费 → 扣耐久 → 结算效果。
- 前一步产生的能量可以支付后一步，后一步不能倒付前一步。
- 回合结算必须播放道具相关动画，并提供动作列表；本地 PvE 与未来服务器 PvP 使用同一事件语义。

### 3.7 五维、背包与经济

- 每件候选必须同时提交机制价值、逐次使用费、耐久、固定占格和金币价格。
- 耐久按重复使用的边际价值与物件逻辑决定，不按稀有度分配。
- 占格只承担空间价格，不产生邻接、朝向、连线或图案奖励。
- 强力、高价、紧凑的珍品可以成立；昂贵、笨重、低耐久不能替无反制超模免责。
- 临时件显示正常估值，但可兑现价值为 0；战斗强度照常计入。
- 金币、匹配战力和单次机制价值必须分开评估。

## 5. 反复出现的工作失误与纠正方法

| 失误 | 以后怎么做 |
|---|---|
| 已定规则被新计划重新列为待审批 | 每次开始先读当前唯一标准；只列真正未决项 |
| 把 15–20 件纵切误缩成 13–15 件 | 可以分批约 5 件审批，但最终总量不变 |
| 机制先行，遗漏耐久 / 占格 / 金币 | 第一版提案就提交完整五维卡 |
| 用档位表自动决定耐久和占格 | 逐件看边际价值、物理逻辑和单格身份 |
| 核心道具绑定 H06 / H20 等英雄 | 先证明无该英雄时仍有用途，再讲英雄 Combo |
| 示例只做文字联想，没有走结算 | 按费用、顺序、持续时间、站位、目标逐步演算 |
| 为顺序硬写前后分支 | 删除分支，检查前一步是否真正改变公共状态 |
| 两种顺序中一边永远更赚 | 不把它当博弈；重新设计或只承认它是操作常识 |
| 名称与文案依赖设计说明 | 用具体物件名和一句普通中文重写，再独立盲读 |
| 用“最多 X 点”给超模效果打补丁 | 重做效果结构、费用、耐久或反制，不堆限制句 |
| 过早扩到 50 / 75 / 100 件 | 先让 15–20 件纵切通过纸面和原型验证 |
| 用 Git 分支模拟不同游戏阶段 | 用固定种子、场景预设、调试入口和状态夹具；分支只隔离代码方案 |
| 隐藏旧内容等于删除 | 保留资产与 ID，用显式启用名单控制投放，可单件恢复 |
