# Scene3 制作复盘：初晓高山剑冢

## 1. 最终目标

Scene3 的最终画面定位是“初晓时分、云海之上的高山剑冢”。它沿用成熟战斗场景的角色、UI、交互与鼠标视差，只重新设计场景专属的美术层级、平台、光影和环境动效。

最终保留的主要组成如下：

- 冷灰青天空与暖色地平线。
- 多层远山、左右中远景山体和近景悬崖。
- 三层反向错动、持续翻腾的云海。
- 半露太阳、呼吸光晕和从云层底部向上展开的主阳光。
- 主战斗锁链和三条不同深度的装饰锁链。
- 角色脚部锁链接触遮挡与分段接触阴影。
- 两侧杂草局部摆动、稀疏漂浮光点、低频剑刃星芒。
- 稀疏出现、带翅膀并从云海跃出的飞鱼群。

## 2. 正确的制作顺序

### 2.1 先锁定共享战斗契约

新场景首先复用 Scene1、Scene2 已成熟的角色展示、UI、切换交互和鼠标视差。场景制作默认只改环境节点、材质和参数，不重新设计 BattleScreen 行为。

Scene3 中角色位置属于受保护的构图参数。角色与锁链发生穿插时，正确做法是移动主锁链、锁链前缘遮挡和接触阴影这一整组平台节点，而不是移动角色来迁就背景。

### 2.2 再处理正式资产

导入图不能直接带白底进入场景。正式流程是：

1. 将临时导入图转换为真透明背景。
2. 清理浅色边缘污染和孤立白点。
3. 按有效内容裁切，减少透明空区。
4. 通过 Godot 导入并检查透明边角。
5. 场景只引用 `assets/scenes/scene3` 中的正式资产，不引用 `assets/import`。

白点修复应尽量精确到确认过的源像素或局部遮罩。使用宽泛的亮度阈值会误删剑刃、草叶和飘带的正常高光。

### 2.3 建立深度，再统一颜色

先按远近关系建立以下层次，再做颜色匹配：

1. 天空与叠层天空。
2. 最远山脉。
3. 远景细链与通天链。
4. 左右远山。
5. 剑冢和中景装饰链。
6. 三层云海与底部封口。
7. 主锁链、角色接触层和左右悬崖。

远景不能直接“变淡到消失”。远山需要保留比天空更明确的明度差和轮廓，同时降低饱和度、对比和暗色描边。Scene3 的统一基调是冷灰青环境配合地平线暖光，不能让近山偏绿、远山偏高饱和青蓝。

### 2.4 最后增加动效和奇幻细节

动效按“先大结构、后小点缀”的顺序添加：

1. 云海反向流动、上下翻卷。
2. 主阳光与太阳呼吸。
3. 山体和悬崖受光。
4. 草叶局部摆动。
5. 漂浮粒子和剑刃星芒。
6. 飞鱼群和远景锁链网络。

任何点缀都必须服从战斗焦点。粒子、星芒和飞鱼应当低频、稀疏，并避开角色主要轮廓和 UI 阅读区域。

## 3. 关键技术方案

### 3.1 云海

Scene3 使用独立云海 Shader，避免修改 Scene2 的稳定实现。三层云海使用不同的种子、速度、相位和视差：

- Back 与 Front 向一个方向缓慢流动。
- Mid 反向流动。
- 每层使用量化的大尺度纵向翻卷和局部云瓣起伏。
- 底部使用独立封口层，避免露出天空素材底部颜色。

仅改变水平速度不能产生“翻腾云海”。必须同时改变轮廓高度、局部云瓣尺寸和相邻层遮挡关系。

### 3.2 太阳与主阳光

太阳不能只是一张暖色圆盘。自然融合需要组合：

- 太阳资产本身的阴影、中间色和高光重映射。
- 柔和外晕、核心发光和低频呼吸。
- 云海靠近太阳位置的局部暖色亮边。
- 从隐藏太阳方向沿上半圆向外展开的多束主阳光。

被否决的“夹层阳光”说明：更多光层不等于更自然。额外光束如果压平云海层次、让画面持续过亮，就应完整移除节点、材质和云层受光代码，而不是把透明度降到几乎看不见后继续保留。

### 3.3 锁链平台与接触关系

主锁链是战斗平面，必须保持最高对比和清晰链环。角色站立可信度由三部分组成：

- 主锁链位置与角色脚底基线一致。
- 窄范围锁链前缘在脚部局部覆盖角色。
- 分段接触阴影仅落在链环表面，不形成宽阔地面阴影。

远山细链和通天链网络曾经作为奇幻感增强方案进行过尝试，但链条数量过多时会形成规则栅栏，压过远山和日出焦点。最终方案收束为三条不同深度的装饰锁链。

如果后续再次制作长距离远景链，不能简单横向拉伸一整张纹理，否则链环会变宽；应在 Shader 中重复采样较小链环，再通过低饱和、低对比、雾化、透明度和较小视差建立距离。

### 3.4 局部摆动

桃树和竹叶经验不能理解成“让整张图左右摇摆”。正确流程是：

1. 为选中的草叶或叶片制作颜色分组遮罩。
2. 制作静态底图补片，填补叶片移动后暴露的空洞。
3. 每组围绕独立枢轴做小角度、低帧率、错相位摆动。
4. 主山体、剑和竹竿保持静止。

动画幅度应简约，但运行时必须肉眼可见。完全看不出的参数不算“克制”，而是没有完成目标。

### 3.5 粒子、星芒和飞鱼

Scene3 的两类微光实现不同：

- 普通漂浮光点使用两层 `GPUParticles2D`。
- 十字星芒使用绑定在剑冢上的低频 Shader，不属于粒子系统。

飞鱼使用运行时生成的最近邻四帧图集、固定对象池和抛物线轨迹。最终版本通过放大单条鱼、减少群体数量和加入翅膀摆动，提升了可读性，同时避免形成持续干扰。

## 4. 本轮暴露的问题

### 4.1 参数调整过于保守

早期多次调色、雾化和云海修改只有很小数值变化，运行截图中几乎无法分辨，造成重复返工。

后续规则：

- 第一次视觉调整应产生明确可见的方向差异。
- 先使用足以判断方向的中等幅度，再在截图上回收。
- 不用“数值已经变了”代替“画面已经变了”。

### 4.2 没有先确认效果的真实实现边界

“普通粒子”和“十字星芒”在视觉上是两类效果，但底层不是两套粒子系统。修改前必须先检查节点和材质，不根据画面名称猜实现。

同样，“草摆动”必须先确认哪些像素属于草、哪些属于山体；“夹层阳光”必须先确认用户描述的是哪两层云之间的可见区域。

### 4.3 只看源码，不看运行画面

Shader 参数、节点顺序和测试都可能正确，但目标效果仍可能被云层、锁链或 UI 完全遮住。Scene3 中夹层阳光和白点处理都证明，仅靠源码检查无法完成视觉任务。

每次视觉修改至少需要：

- 无 UI 场景截图，用于检查美术层次和边缘。
- 完整 BattleScreen 截图，用于检查角色、平台和 UI。
- 多个时间点截图，用于检查低频光照、云海和飞鱼。
- 指针视差探针，确保平台与角色世界同步。

### 4.4 测试不能固化被否决方案

测试应保护当前认可的视觉契约，而不是永久保护某次实现。当夹层阳光被否决后，对应测试必须改为确认节点和 Shader 残留已清除。

## 5. 可复用验收清单

### 资产

- [ ] 场景不引用临时导入目录。
- [ ] 透明边角没有白底、黑边和孤立亮点。
- [ ] 运动素材具备遮罩和底图补片。

### 构图与颜色

- [ ] 远山能从天空中读出，但不抢近景。
- [ ] 近山、远山和云海属于同一冷灰青环境。
- [ ] 暖色只集中在太阳、云边和局部受光面。
- [ ] 主锁链始终是最清晰的锁链层。

### 动效

- [ ] 云海存在反向流动和纵向翻卷。
- [ ] 主阳光间歇变化，不形成持续白色扇面。
- [ ] 只摆动选中的草叶或叶片。
- [ ] 粒子、星芒和飞鱼保持低频、稀疏。

### 战斗适配

- [ ] 不为适配背景而移动成熟角色基线。
- [ ] 脚部与平台不存在明显穿模。
- [ ] 接触阴影只落在实际平台表面。
- [ ] UI、角色和主战斗区域不被环境细节遮挡。

### 验证

- [ ] 使用 `tools/run_godot.ps1` 完成 Import。
- [ ] 运行 Scene3 专项测试和全量 GUT。
- [ ] 检查无 UI 与完整 BattleScreen 截图。
- [ ] 检查多个动画时间点。
- [ ] 检查指针视差同步误差为 `0.0`。
- [ ] 提交前检查暂存文件、空白错误和未跟踪残留。
