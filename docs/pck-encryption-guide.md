# 资源包（PCK）加密操作手册（M3d·2026-07-12）

> **目的与边界（先读）**：PCK 加密把"拆包提取脚本/资产"的门槛从"下载一个免费工具"抬高到
> "需要逆向出密钥"。它**不是**绝对防线——密钥必然存在于游戏可执行文件里，有耐心的逆向者
> 终能取出。真正的防线是服务器权威（已建·ADR-004）：破解客户端改不了联机对局结果。
> 本手册属"尽量做到最好"组合拳的一环，发布前执行一次即可。

## 原理

Godot 导出时可用 256 位 AES 密钥加密 PCK 里的脚本与资源。解密密钥必须**编译进导出模板**
（不能只填在导出面板里），所以需要自编译一次导出模板。

## 步骤（发布前执行·开发期不需要）

1. **生成密钥（一次性·妥善保存）**
   ```bash
   # 任一方式生成 64 位十六进制（256-bit）：
   openssl rand -hex 32
   ```
   把结果存在**仓库之外**的密码管理器里（丢了=老玩家存档兼容的重打包麻烦）。

2. **编译带密钥的导出模板**（Godot 官方源码 + SCons·版本必须与项目锁定版一致）
   ```bash
   # Windows 模板（release）：
   set SCRIPT_AES256_ENCRYPTION_KEY=<你的64位hex>
   scons platform=windows target=template_release
   ```
   产物 `bin/godot.windows.template_release.*.exe` 即"专属模板"。

3. **导出配置**（Godot 编辑器 → 项目 → 导出）
   - 该预设的「自定义模板 → Release」指向上一步产物
   - 「加密」页勾选 *Encrypt Exported PCK* 与 *Encrypt Index*
   - 「脚本导出模式」保持二进制 token（4.x 默认）
   - 过滤器把 `*.gd` 之外的敏感数据文件（如 `assets/data/**`）也纳入加密

4. **验证**：导出后用 PCK 提取工具（如 godotpcktool）尝试解包——应报错/得到密文。

## 导出配置可复现性（2026-07-17 审计修复⑤·约定先立·发布期执行）

现状：`export_presets.cfg` 被 .gitignore 忽略（Godot 惯例·本机也尚未创建=项目未到导出期）。
外部审计指出"发布构建不可复现"——**成立，但修法不是把它入库**：该文件会写入 PCK 加密密钥/
签名凭据，本仓库公开，入库=直接泄密（见下方铁律）。约定如下：

1. **首次建导出预设时**，同步手工制作 `export_presets.example.cfg` 入库：完整保留平台/
   资源过滤/模板路径/导出参数，**剥掉** `script_encryption_key`、签名与商店凭据字段（置空）。
2. 真 `export_presets.cfg` 继续忽略；新机器复现 = 复制 example 改回真名 + 从密码管理器填密钥。
3. 导出参数每次变更，example 同步更新（review 时对 diff 一眼可见）。
4. 自动导出流水线（CI/发布脚本）= 发布期另立项（个人项目现阶段不建·任务清单 8 商店/发布线时评估）。

## 铁律

- ⛔ 密钥、含密钥的构建脚本、专属模板 **永不入仓**（.gitignore 已有 build 目录兜底·另存密码管理器）
- ⛔ 别在 CI 日志里 echo 密钥
- 每次 Godot 升级（如 4.7→4.8）需用同一密钥重编模板
- 联机敏感逻辑**不要依赖此加密保密**——该在服务器的逻辑就放服务器（UI 只读守卫已锁）
