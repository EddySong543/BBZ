# 新版道具从20件扩展至100件的分阶段验收计划

> 日期：2026-09-02
>
> 状态：拓展任务一已完成；20件初始纸面池已冻结，下一步为任务二单机最小原型。
>
> 目标：先冻结20件初始纸面池，再通过单机原型和分批审批扩展至50、75、100件。100件是规划终点，不允许为了赶数量降低单件标准。

## 一、完成口径

原阶段五完成，代表“首批20件纵切样本的纸面初设计完成并冻结”，可以进入独立的单机原型规划。

它不代表以下工作已经完成：

- 20件道具的运行时实装；
- 50 / 75 / 100件正式目录；
- PvE敌人、掉落、商店和远征经济；
- 真实对局下的最终费用、成型率与胜率平衡。

## 二、全程统一验收方式

### 1. 每5件一次逐件审批

每件继续完整提交：名称与单句玩家文案、稀有度、机制价值下限 / 常态 / 峰值、逐次使用费、耐久、固定占格、金币价、独立用途、真实换序、道具 Combo、英雄 Combo、可见反制、持续时间、站位、合法目标、能量前缀、三件同名最坏结果和历史碰撞自检。

单件只有同时满足以下条件才进入通过池：

- 玩家文案一句普通中文可以直接看懂；
- 不依赖指定英雄或指定道具也有用途；
- Combo 走完费用、持续时间、站位、合法目标和实际结算；
- 顺序来自真实状态或行动位变化，不靠“下一次”或条件句硬造；
- 费用、耐久、占格和价格同时合理，且考虑70格背包、9格保险箱及非战斗物品空间；
- 不新增只服务少数道具的封闭系统；
- 与历史设计重合不构成否决，只按当前标准判断。

### 2. 每批5件的批次验收

- 更新新版候选账本、全池碰撞表和 Combo 图；
- 说明本批填补的公开接口、玩法维度或实测缺口；
- 复核本批与旧池的交叉连携，不能只在本批内部自成套装；
- 复核费用、耐久、格数、价格密度和机制模板的新增偏斜；
- 输出“通过 / 修改后复审 / 淘汰”清单，不整批默认通过。

### 3. 每累计新增25件的扩池闸门

- 至少70%新件能与旧池至少2件形成有效 Combo；
- 至少25%旧池道具因本批获得1个新搭档；
- 只连接本批的封闭小圈不超过20%；
- 新关键词必须同时有生产端、消费端，并桥接既有公开接口；
- 不能依靠一件万能产能道具虚增覆盖率。

上述比例是报警线，不是制造生硬机制的配额。未达线时先定位缺口、修改或淘汰，不为达标硬写条件句。

## 三、分阶段任务

## 拓展任务一：完成原阶段五，冻结20件初始池

状态：已完成。

工作内容：

1. 检查20件道具各自“三件同名”的最坏结果。
2. 验证主要两件链、三件链和反转顺序后的实际差异。
3. 验证不同英雄组合，但不修改已定稿英雄。
4. 对 `n=2–5` 极小战备计算必成率、付费时点和卡手风险。
5. 专项压力测试复苏石复活链、护甲接口集中和“下一次”模板集中。
6. 为20件补齐 `provides / requires / transforms / counters / timing / cost` 标签，重算首池 Combo 覆盖指标。
7. 对每件给出“保留 / 修改 / 淘汰”结论，并决定是否需要最低合法可抽 UID 数。

验收出口：

- 所有高风险组合均有明确结论和可见反制；
- 所有报警项均已处理或留下有依据的保留说明；
- 若有淘汰件，另行审批替代件，不静默补位；
- 形成冻结的20件初始纸面池，原“道具初设计阶段”正式完成。

完成结果：20件全部保留；三件同名、两件 / 三件Combo、24名英雄交互与`n=2–5`极小战备均已复核。纸面版暂不设置最低合法UID，最低6件 / 9件进入原型A/B测试。完整证据见[`2026-09-02-item-stage5-full-pool-audit-and-freeze.md`](../../reports/2026-09-02-item-stage5-full-pool-audit-and-freeze.md)。

## 拓展任务二：制作20件单机最小原型

状态：下一任务；尚未授权执行。

工作内容：

- 只实装冻结通过件；
- 走通“免费三选一取得 → 公开并锁定 → 下一回合排序 → 逐行动位结算 → 扣费与耐久 → 动作记录”；
- 玩家与AI共用同一本地规则；规划时互不可见，确认后完整序列公开结算；
- 建立合法目标、费用前缀、耐久耗尽、延后、换位和阵亡 / 复活的规则级测试。

验收出口：

- 20件都能在单机完整走通取得、使用和消耗流程；
- 不存在非法目标被接受、费用顺序错误、耐久重复扣除或结算不同步；
- 纸面 Combo 能在运行时复现，纸面与实测差异进入调整清单；
- 形成扩至50件前的真实缺口清单。

## 拓展任务三：从20件扩至35件

执行方式：连续3批，每批5件。

主要目标：

- 优先补原型暴露出的基础接口和反制缺口；
- 降低护甲轴和“下一次”模板的相对集中；
- 审查4费局势件空档；只有存在自然、清楚且可反制的方案才补，不为费用表强行造卡；
- 建立更多来自生命、护甲、能量、站位、目标、实例和行动位变化的直接顺序关系。

验收出口：35件全部逐件通过，且新增件没有形成封闭小圈或英雄专属孤岛；输出35件全池小审计和下一阶段缺口表。

## 拓展任务四：从35件扩至50件

执行方式：连续3批，每批5件。

主要目标：

- 补齐首个Demo目录所需的进攻、防守、恢复、调度、经济、实例操作和局势反制宽度；
- 让每个核心公开接口至少有2个生产 / 桥接端和2个消费 / 兑现端；
- 在第45件时检查“累计新增25件”扩池闸门，第50件时做首个完整目录审计。

50件验收目标：

- `C2(3)≥90%`，搭档数中位数5–8；
- `S2≥80%`；
- `C3` 为50%–65%，有8–12种不同三件链模板；
- `A3≥70%`、`H10≤35%`、`Fmax≤40%`；
- 100%道具有独立用途，无孤立节点；
- 所有有效 Combo 均通过锁定、行动位、合法目标和费用可执行性检查。

这些数值只用于发现结构问题，不会成为凑数审批配额。

## 拓展任务五：50件实测闸门与75件需求单

工作内容：

- 用实际道具 ID 和真实战备重算 `n=2–16` 的看见、取得、就绪、付费和完成概率；
- 在PvE前期、中期、后期以及不同英雄队伍中验证费用、卡手、反制和重复使用；
- 结合敌人、精英、Boss意图与远征掉落，检查是否存在真实结构缺口；
- 复核70格背包、9格保险箱与食物、探索用品、战利品的空间竞争；
- 只把有证据的缺口写成后续25件“需求槽”，不预写具体道具答案。

验收出口：形成50件保留 / 修改 / 淘汰结论，以及50→75的明确需求单；未处理严重离群项前不继续扩池。

## 拓展任务六：从50件扩至75件

执行方式：连续5批，每批5件，只响应任务五确认的需求槽。

75件验收目标：

- 满足累计新增25件扩池闸门；
- `C2(4)≥92%`，搭档数中位数8–12；
- `S2≥85%`；
- `C3` 为60%–72%，有14–20种不同三件链模板；
- `A3≥80%`、`H10≤32%`、`Fmax≤38%`；
- 每个核心公开接口至少有3个生产 / 桥接端和3个消费 / 兑现端；
- 100%道具有独立用途，无孤立节点。

## 拓展任务七：75件实测闸门与100件需求单

工作内容与50件闸门相同，但重点增加：

- 检查机制是否只是低级数值换皮；
- 检查是否出现一件万能枢纽支配大量 Combo；
- 检查高价值、小占格、高耐久是否开始叠成最优装载答案；
- 检查PvE敌人是否只能靠血量、护甲硬抗，而缺少明确道具反制；
- 将仍然存在的结构、内容和PvE生态缺口整理成最后25件需求槽。

验收出口：75件池完成保留 / 修改 / 淘汰审计，严重问题清零，并形成75→100需求单。

## 拓展任务八：从75件扩至100件

执行方式：连续5批，每批5件，只响应任务七确认的需求槽。

100件验收目标：

- 满足累计新增25件扩池闸门；
- `C2(5)≥95%`，搭档数中位数10–15；
- `S2≥90%`；
- `C3` 为65%–78%，有20–28种不同三件链模板；
- `A3≥85%`、`H10≤30%`、`Fmax≤35%`；
- 每个核心公开接口至少有4个生产 / 桥接端和4个消费 / 兑现端；
- 100%道具有独立用途，无孤立节点。

## 拓展任务九：100件全池终审与版本冻结

最终统一检查：

- 单件可读性、独立用途和历史碰撞；
- 费用、耐久、格数、形状、单格价格与残损价格；
- 70格背包、9格保险箱和战斗 / 非战斗装载配比；
- 三件同名最坏结果、两件链、三件链、英雄组合和PvE反制；
- 前期、中期、后期的取得率、付费率、卡手率和完成率；
- 万能枢纽、封闭小圈、英雄专属孤岛、唯一正确顺序和伪 Combo；
- 敌人、掉落、商店、临时件与百万撤离经济中的来源和价值定位。

验收出口：输出100件正式账本、全池碰撞表、Combo图、风险清单、运行时数据表和版本冻结说明。任何未解决的严重离群项都必须先修改或淘汰，不能以“已经到100件”为理由保留。

## 四、当前唯一下一步

拓展任务一已经完成。下一步是任务二：为冻结的20件制作单机最小原型；在用户明确开始任务二前，不实装，也不开始第21件设计。
