## 二、总验收原则

后续所有阶段共用五个总闸门：

1. 可读：普通敌人或基础道具用一句话能说明核心规则。
2. 可算：费用、目标、拍位、同拍、死亡和持续时间能完整结算。
3. 可选：同一公开局面至少存在两种理性方案，不是“正确答案加错误答案”。
4. 可反制：反制改变资源、生命、位置、装备或未来威胁，不能只靠硬吃数值。
5. 可扩展：复用公开接口，不为一件道具或一个敌人新建封闭系统。

只要某阶段出现跨大多数局面成立的固定最优策略，就停在该阶段修复；禁止靠增加下一批内容稀释问题。

## 三、分阶段验收

### 阶段 0：统一当前真相与取得规则

目标：消除“旧免费逐回合三选一”和“新开局三件 + 付费补充”同时存在的真相漂移。

交付物：

- 一份取得状态机专项补充，明确开局抽取、部分调换、锁定、可用回合、空框、每轮补充次数、1 能支付时点、候选无放回边界、敌方对称和战斗结束归还。
- 一份冲突清单，列出需要被新规则覆盖的旧文档段落；只改取得相关内容，不顺手重写其他规则。
- 一份概率影响说明：旧 `n≤4` 两件链、`n≤5` 三件链的历史结论不再直接适用，下一次纵切必须用新状态机重算。

验收门：

- 不重新讨论已通过的方向。
- 开局三个框、第一回合锁定、第二回合可用和后续补一个空框不存在歧义。
- 任何补充仍来自真实背包 UID；不存在复制实例、自动补满或同次调换反复出现同一实例。

通过后进入阶段 1。

### 阶段 1：证明公开序列不是答案表

目标：先证明底层决策结构成立，再正式生产敌人内容。

交付物：

- “公开序列困境门”正式规则。
- 三个晴风稻田普通敌人方向；每个只有一个一句话核心机制。
- 每个敌人至少两个不同战局样本。每个样本完整列出敌方公开序列、双方开局能量 / 生命 / 护甲 / 站位 / 可用道具、至少两条玩家方案和结算结果。
- 一份支配策略审查：尝试用“见波防、见防攒、见大波大防”、H21、银鳞甲、石灰粉和抢杀逐一破解全部样本。

验收门：

- 每个样本至少同时威胁两项价值，例如当前生命与未来强化、出战位与后备、资源与敌方治疗。
- 至少两种方案在不同战局条件下会互换优先级；不能一条永远更好。
- 道具提供第三种付费解或改变代价，不得只是把唯一正确基础动作做得更强。
- 本回合完整序列继续公开；不能通过隐藏 0 拍、偷偷改招或读玩家未提交选择制造不确定性。

若不通过：先改敌人压力结构。连续三种普通敌人结构仍失败时，才提交一个单独的公共规则 A/B 方案；第一测试候选是“防 / 大防回合不获得回合末被动能量”。任何公共规则改动必须重新审计二十四名英雄、二十件道具和能量曲线。

### 阶段 2：冻结晴风稻田生态与遭遇节奏

目标：确定“地图上有哪些敌人、玩家实际会打几场”，避免先写十二套机制再删除。

交付物：

- 金穗沃土大区约 6–8 个生态角色的职责表。
- 晴风稻田子集：普通、精英、Boss、事件敌人和非战斗生物分别占多少。
- 每类敌人的巡逻、追逐、搜索或守点范围；玩家可以怎样绕行、引开、等待或主动接战。
- 一次远征的遭遇组数量、标准路线 / 深入路线 / 清图路线的实际战斗数。
- 单场回合长度目标及“决策转折”来源。

当前建议起点，不视为机械定额：

- 区域生态池 6–8 个角色。
- 一局地图 6–8 个游走遭遇组。
- 标准路线实际战斗 2–3 场，深入 4–5 场，清图上限 6–7 场。
- 教学 3–4 回合，普通 4–6，组合敌人 6–8，精英 7–10，Boss 10–14。

验收门：

- 数量由地图路线和生态职责推出，不统一套“每图十二种”。
- 规避战斗是有效地图选择，不是绕路动画。
- 战斗延长来自至少两个决策转折，不来自单纯增加生命或固定脚本轮数。

### 阶段 3：完成三个普通敌人和评分语法

目标：把阶段 1 的验证方向做成可反复生成但可理解的正式普通敌人。

每个敌人的交付卡必须包含：

1. 正常人类命名、世界身份和一句话核心机制。
2. 它要求玩家权衡什么，而不是它“有什么技能”。
3. 合法候选序列的生成语法；至少三个状态驱动的候选方向，不写死整场轮转表。
4. 评分因子：生命、能量、护甲、目标、我方状态、敌人自身状态和未来威胁各怎样影响选择。
5. 受控随机范围：只在近优合法候选中随机，不能随机自杀，也不能每次都精确最优。
6. 当前完整公开信息和玩家可推断的未来信息。
7. 至少两条完整玩家解法，包括无道具解和道具解。
8. H02、H08、H10、H21、死亡截断和三件同名的风险检查。
9. 战斗负载与独立战利品；道具偏好不能违背敌人身份。
10. 地图行为、战斗时长和掉落定位。

验收门：

- 三个敌人提出三种不同问题，而不是同一攻击模板换名字。
- 评分系统选择题目，但题目本身已通过困境门。
- 玩家能从一句机制和公开序列理解风险，不需要背隐藏权重。
- 普通敌人不引入私有资源条、复杂阶段或长篇例外。

### 阶段 4：两个精英、最终 Boss 与策略纵切

目标：在普通敌人语法成立后，验证更高强度和更长战斗是否仍保持可控选择。

交付物：

- 两个精英：各有一个独有机制，并把两项压力联动；不只是普通敌人数值翻倍。
- 晴风稻田最终 Boss：一个战斗级核心规则、清楚的阶段转换和至少三种可读压力组合。
- 六个敌人共同组成的代表战局集：无道具、单件、二件链、三件链各至少两局。
- 开局三件、部分调换和后续付费补充的实际回合轨迹。
- H21、H08 + 银鳞甲、H10 穿防、H02 强化波、复苏石和死亡截断强测。

验收门：

- 同一公开序列有至少两种合理应对，而且不同阵容、道具和资源会改变优先级。
- 波 / 防仍重要，但不能在绝大多数局面单独压过道具、目标和顺序规划。
- Boss 不能靠固定模板背板，也不能在玩家提交后改招。
- 长战斗中至少出现三次新的决策转折；不是重复同一道题。
- 若纵切失败，先修敌人和取得节奏；不能直接扩池掩盖。

### 阶段 5：接上远征掉落、装备与高价值物

目标：让战斗选择、绕行风险和撤离收益形成闭环。

交付物：

- 敌人战斗负载与携带战利品两套生成表。战利品在遭遇生成时固定，提前击杀不增加掉落。
- 道具偏好权重与掉落价值权重分离；敌人可以偏好某些道具，但仍有大金 / 大红货物空间。
- 红色收藏品的非战斗收益规则，包含触发时点、上限和撤离风险。
- 一英雄一装备的规则草案；区分战斗装备和探索装备，明确谁生效、是否叠加。
- 顶级红装的精确结算单位；“伤害 +1”默认按一次完整基础攻击总伤害计算，不按每段伤害。
- 白绿材料需求审查：没有明确合成消耗端就不建立材料系统，最多保留一种通用废料候选。

验收门：

- 颜色只表示稀有或价值，不同时承担物品类别。
- 装备不进入道具序列，不消耗道具框，也不复制英雄完整身份。
- 持续收益不能形成无限实时挂机产出。
- 70 格主背包、9 格保险箱、战斗用品、食物和战利品之间出现真实空间取舍。

### 阶段 6：从二十件扩到三十五件

目标：只填已被敌人纵切证明存在的结构缺口。

按三批、每批五件审批：

1. 公开序列应对：改变目标、站位、资源分配或未来威胁，不做单纯“看到攻击就减伤”。
2. 非瓶装能量桥接：补即时状态、目标和支付顺序，降低通用减费枢纽依赖。
3. 队伍与持续作战：补后备、跨战续航和战斗 / 非战斗背包取舍。

每件仍提交完整审批卡：

- 名称与一句话文案；
- 稀有度；
- 价值下限 / 常态 / 峰值；
- 逐次费用及与公共行动的冲突；
- 耐久、物件逻辑和重复风险；
- 初始形状、格数和单格身份；
- 满耐久价与残损价；
- 独立用途；
- 真实换序例；
- 道具 Combo、英雄 Combo、敌人局面与可见反制；
- 持续时间、站位、合法目标、费用前缀、三件同名和历史相似机制。

验收门：

- 至少 70% 新件与旧池两件以上形成严格连携。
- 至少 25% 旧件因本批新增一个严格搭档。
- 优先给猎鹰羽毛补搭档，并减少“下一次……”模板占比。
- 不为填满 4 费档、耐久比例或稀有度数量强行通过道具。

### 阶段 7：三十五到五十，再决定是否扩至一百

35→50：

- 加入食物、探索补给和可撤离经济物，真实测试 79 格配比。
- 在连续多场战斗中验证 D1 / D2 / D3+ 的空间效率。
- 用新开局三件规则重算小 UID 战备、Combo 成型和补充频率。
- 接入晴风稻田掉落、商店和事件来源的纸面分布。

五十件闸门：

- 清理重复身份、万能枢纽、无脑公开反制、额外结算点、复活循环、护甲循环和价格密度异常。
- 只有存在明确玩法缺口时才继续扩量。

50→75：

- 精英 / Boss 环境件、替代路线、稀有构筑核心和更多队伍接口。

75→100：

- 长期远征、特殊来源、收藏经济和低频高价值物。

全过程每五件一批审批。100 件只是长期目录目标，不是质量证明，也不是必须一次完成的生产指标。

## 四、每阶段汇报格式

聊天中只报告四件事：

1. 本阶段产出了什么。
2. 最重要的新判断是什么。
3. 哪一项没有通过以及原因。
4. 需要用户确认的具体选择；没有就明确写“无需确认”。

完整表格、概率、碰撞和结算可以落文件。任何会改变下一阶段方向的风险，必须同时在聊天里用普通中文说清楚。

## 五、禁止提前做的事

- 不修改冻结英雄来替敌人设计补洞。
- 不重新隐藏关键基础行动来恢复猜拳。
- 不用固定模板、血量膨胀或作弊式临场改招制造难度。
- 不因已有二十件道具而强迫所有敌人使用违和道具。
- 不创建幸运、热量、攻速、冷却、宠物、邻接、朝向或连线等封闭系统。
- 不提前实装敌人、取得规则、装备或新道具。
- 不把 UI、资产方向和预览图工作带进本设计验收线。
