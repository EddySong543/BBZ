# 远征旧怪清理、居中镜头与战斗同步设计

## 已确认目标

- 删除当前远征中仍在运行的旧十怪、旧概率表、游荡怪和自动拆解战斗，不用另一批占位怪替代。
- 晴风稻田在正式敌人完成前暂不生成敌人；保留通用敌人锚点、遭遇状态与战斗回程接口。
- 角色在地图中心和四角均保持屏幕居中，连续移动时平滑改向，不再因反复重启补间而顿挫。
- 当前远征使用唯一的 `BattleCore`、战斗场景、合法行动、技能、道具和结算流程。
- 远征只保留敌方控制器、初始跨战状态和战后返回地图三个适配点。

## 旧怪清理边界

- 停止 `ExpeditionMapState` 读取旧怪数据和生成旧怪、守卫、Boss、游荡怪。
- 删除旧怪数据、旧概率策略和隔离的怪物模拟原型；同步移除当前设计文档中的旧怪设计真相。
- 删除远征界面的旧怪图签、T级、明牌、避战、巢穴和自动战斗入口。
- 保留布局中的正式敌人锚点、通用遭遇接口和战斗结果回写概念，避免以后重新打通地图与战斗。
- 旧怪移除后，正常游玩地图暂时没有敌人；测试通过手工注入标准战斗会话验证桥接。

## 居中镜头

- 删除中央死区、镜头补间和角色补间的双重驱动。
- 使用单一连续视觉坐标和临界阻尼速度更新；目标改变时保留当前速度，避免连续按键造成停顿或反向过冲。
- 角色和地图位置由同一个取整后的视觉坐标计算，使角色屏幕坐标始终等于固定中心锚点。
- 在逻辑地图四周绘制不可行走、不可交互的浓雾延伸格；不改变 18×14 逻辑地图、寻路、对象或事件数据。
- 停止后吸附到整数像素，保持像素画稳定。

## 统一战斗会话

- 远征选角保存稳定的 `hero_id`，进战时加载并复制真实 `HeroData`；姓名和血量只作为状态，不再作为角色定义。
- 双方完整阵容、种子和初始生命进入公共战斗设置；当前 `BattleCore.setup()` 只执行一次。
- PvE 对手必须从当前 `legal_actions()` 生成标准选择，并通过当前 `apply_choice()` 与 `_resolve()` 结算。
- `battle_pve.gd` 不再构造白板英雄、显示旧怪概率表或手算脱战伤害，只负责远征结果封装和返回地图。
- 本轮不恢复已退役的旧同步分支；避免给个人项目引入不必要的额外状态机成本。

## 验收

- 正常晴风稻田不生成旧怪，旧怪数据与策略不再被生产代码引用。
- 任意镜头动画帧中，角色屏幕坐标保持固定中心；连续输入无过冲、黑边或逐格停顿。
- 远征选入的真实英雄在 PvE 中保留 `hero_id`、当前技能与合法行动。
- 远征与战斗核心的公共初始化和行动结算不再存在两套规则入口。
- Godot 导入、聚焦 GUT、全量 GUT 和 1920×1080 远征/战斗探针通过。
