## 1. 设计目标

道具是围绕「波 / 攒 / 防 / 大波 / 大防」、英雄与背包形成组合的主动计划件。取得必须让对手获得信息窗口，使用必须与核心能量决策竞争，同一回合内的真实结算顺序必须能够改变结果。

本标准已经审批 **通用战斗内取得、公开、锁定、使用费用和权威序列**。这些基础规则在 PvE 与未来 PvP 中共用，不因当前产品转为 PvE 优先而重开。

## 2. 通用局内取得基线

1. **手动抽取，不自动抽取。** 玩家在每回合行动规划前的独立同步抽取阶段决定是否打开抽取；系统不会像自动抽牌游戏一样强制补牌。
2. **每名玩家每回合最多一次免费抽取机会。** 抽取不消耗能量，机会不累计到以后回合。
3. **必须至少有一个空道具框。** 当前基线使用 3 个公开道具框；双方以 3 个空框开局，不预置道具。三个框都被占用时不能抽取。
4. **候选来自自己的真实背包实例。** 系统按 UID 无放回随机展示 `min(3, N)` 个合法实例，玩家选择 1 件或放弃；不足 3 件不补假道具，同名不同 UID 可以同时出现。
5. **候选固定，不得刷新。** 关闭再打开仍是本回合原候选；当前 Demo 基线没有重抽。放弃也会消耗本回合机会。
6. **未选件保留在背包。** 选中的真实实例离开背包并进入编号最小的空道具框；未选实例不损失耐久、不被对手看见，继续留在可抽取储备。
7. **选中后锁定本回合。** 第 `R` 回合取得的道具不能加入第 `R` 回合序列，从第 `R+1` 回合规划阶段开始可用。
8. **候选私密，取得结果公开。** 候选与选择过程不公开；选中的道具进入公开框后才成为场上信息。多人对战时双方在同一权威节拍公开“取得道具 / 未取得”，随后才获得完整行动规划时间。
9. **有剩余耐久的占框道具不能免费替换。** 玩家必须承担槽位占用；耐久归零的框在本回合最终清理时才腾出，最早于下回合重新提供抽取资格。具体效果合法移走存活实例时，原框可立即空出，但本回合抽取阶段已经结束。

因此，“免费”只免除了抽取的能量税，不等于免费战力。玩家仍支付每回合一次的机会、公开一回合、道具框占用、逐次使用费、耐久损耗和真实资产风险。

## 3. 使用费用

- 每件道具有独立的**逐次使用费**，取值为 `0–4` 能；每次实际使用都重新支付，多耐久道具也不例外。
- 大部分道具位于 `1–2` 能。`0` 能主要留给严格受限的连接件、状态搬运或带有明确风险的工具；必须重点审查循环和无损收益。
- `3–4` 能是正式设计空间，不是禁区。能够改变局势、成为整轮计划或 build-around 的道具可以进入这一档，例如梦蝶一类传说道具。
- 使用费不与 T1/T2/T3 机械绑定。稀有度描述机制职责和质变程度；费用描述本次战斗中启动它需要放弃多少核心选择。
- 机制价值不是固定能量汇率。每件道具仍按下限、常态、峰值和反制窗口评估，不能因为“付了 4 能”就允许无反制地结束对局。

## 4. 有序结算与能量支付

玩家提交的是一段统一有序序列，例如：

`[道具 A, 波, 道具 B]`

双方序列从左侧对齐并逐列推进。每列读取双方当前待执行步骤；同列两方已经开始的步骤均完成，列结束后才进入下一列。权威效果可以让服务器在某方下一真实步骤前生成一次等待；等待不由客户端提交，也不改写该方剩余步骤的原顺序。完整边界见 [`2026-08-30-h03-sequence-shift-design.md`](2026-08-30-h03-sequence-shift-design.md)。

服务器在权威状态副本上逐步骤重放。每个道具步骤固定按以下次序：

1. 检查该步骤在当前状态是否合法，以及当前能量是否足够；
2. 支付这件道具本次使用费；
3. 扣除该真实实例 1 点耐久；
4. 结算道具效果；
5. 后续步骤读取已经改变的能量、生命、状态、目标和道具实例。

前一件道具产生的能量可以支付后一件；后一件产生的能量不能倒过来支付前面的步骤。客户端可以预演剩余能量，但费用、效果与耐久都以服务器为准。

当前 P1 测算进一步固定白板时点：每轮被动 `+1` 在本轮最终结算时到账，只能供下回合使用；「攒」的 `+1` 在其行动步骤立即到账，可以支付排在它后面的道具。`0–4` 基线只审批五个整数费用档；半点费用仍未批准。

整段序列若在提交时基础非法，服务器原子拒绝，不执行合法前缀，也不扣能量或耐久。合法道具步骤已经进入权威结算后，即使效果被反制、免疫或最终收益为 0，费用和耐久仍然消耗。

## 5. 稀有度与传说道具准入

- T1、T2、T3 成品都可以作为真实资产装入战备，并通过同一套免费三选一进入公开道具框。
- 不设通用图纸、固定材料配方或统一升级梯子作为 T3 准入门槛。
- 个别道具、事件或商店以后仍可拥有明确写在内容里的制造、交换或转化效果，但它们是独立内容，不是玩家必须背诵的系统规则。
- T3 的风险由使用费、锁定一回合、公开框占用、耐久、真实资产风险、机制反制与候选概率共同承担；不能再靠“先升金”兜底平衡。

## 6. 五维平衡

每件正式道具必须同时填写并联合审核：

1. **机制价值**：裸用下限、普通常态、理想 Combo 峰值，以及它实际改变的选择；
2. **逐次使用费**：`0–4` 能，每次使用都支付；
3. **耐久**：实体能用几次，每多一次会不会重复或放大 Combo；
4. **占格**：固定形状和格数，作为携带与搜刮价格，不与稀有度机械绑定；
5. **金币价格**：正常显示价值、残损曲线、可兑现价值和单格价值。

五个维度彼此独立但联合定价。强力、高价、紧凑的珍品可以存在；昂贵、笨重或低耐久也不能替单场无反制超模开脱。

## 7. 信息、交互与权威回放

- 按住左键拖出但未松开只作本地预览；在合法区域松开才把使用追加到本地待提交序列。
- 本地施放动画只是编排反馈，不提前公开待提交序列，也不作为结算真相。
- 最终提交完整有序步骤；PvE 由本地权威结算器、未来 PvP 由服务器逐步校验费用、实例、耐久、目标和状态，再产生权威事件流。
- 回合结算时必须按权威事件流播放道具、行动、扣费、耐久变化和效果动画，并提供可回看的动作列表；否则玩家无法理解长序列为何得到当前结果。
- 双方序列左对齐并逐列结算；同列两方已经开始的步骤均完成，服务器内部遍历顺序与网络到达速度都不能制造先后手。列间等待只能由服务器权威效果生成，客户端不能提交。

## 8. 当前实现与目标设计的边界

当前运行时已经落地双方左对齐逐列调度器、H03 等待与当前「连环鼓」后续行动；但 UI / 协议尚未完成任意道具与行动的统一排序提交。旧的 1 能补充、免费使用、一次性清槽、旧稀有度过滤、通用 PRE/POST 道具批次和仅保存道具 ID 的背包模型仍然存在，只可作为迁移期测试资产，**不能反向定义新规则**。

剩余迁移至少包括：独立 `DRAW / DRAW_REVEAL / PLAN` 阶段、真实实例 UID、资产归属与当前控制、`REAL / RUN_TEMPORARY / BATTLE_TEMPORARY` 生命周期、逐次使用费、当前 / 最大耐久、`LOCKED / READY / DEPLETED_PENDING` 状态、每回合免费抽取额度、固定候选、任意道具 / 行动统一步骤提交、服务器原子校验、权威事件历史及版本化快照。

旧道具资产不删除。Demo 未启用的旧件保留目录、资源与注册信息，通过显式启用标记隐藏；之后应能按 ID 单件恢复，而不是从 Git 历史找回。

## 9. 通用取得边界已封板

以下规则已经批准，完整状态机见 [`2026-08-30-pvp-item-acquisition-instance-boundaries.md`](2026-08-30-pvp-item-acquisition-instance-boundaries.md)：

- 开局三框为空，第 1 回合正常手动抽取，取得件第 2 回合才可用；
- 合法实例不足 3 件时展示全部，不补假候选；同名不同 UID 可以同时出现；
- 抽取采用“回合开始前置抽取门 → 取得结果公开 → 完整行动规划”；未来 PvP 的抽取窗口初值为 8 秒；
- 耐久归零的框在最终清理时腾空；存活实例被效果移走时可立即腾框，但不能倒回已经结束的抽取阶段；
- 抽取超时放弃，行动超时提交“攒”；断线不停钟，Demo 初始保留席位 30 秒；
- 实例分离资产归属与战斗控制，区分真实、Run 临时和本场临时；战斗内交换不改变永久所有权；
- 复制效果不生成实体；复制 / 生成实体使用新 UID 且默认仅本场存在；
- Demo 暂不开放通用单件偷取或免费弃置 / 销毁按钮。

以上取得、锁定和逐次收费已经是 PvE / PvP 通用规则，不再追加模式审批。付费重抽不在当前 Demo 中；以后若提出，属于新增规则，不能从旧设计恢复。断线、倒计时、重连和服务器 UID 保密仍是未来 PvP 的专项边界，不是当前 PvE 原型的前置任务。
