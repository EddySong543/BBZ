# Scene1 像素流星动效设计

## 目标与边界

在现有 Battle Scene1 夜空中加入克制的像素流星彩蛋。自然出现必须极少，玩家也可在限定时间内连续点击夜空主动触发。不得修改 Scene1 已通过的构图、角色、UI、战斗输入、鼠标视差或其他场景。

## 视觉设计

- 使用程序化 `_draw()`，不引入新的位图资产。
- 完全删除上一版历史点拖尾，不保留逐点采样、逐点衰减或散落粒子。
- 一颗流星是一个整体移动的稳定像素图形：米白核心、冷蓝头部、短而相连的三级阶梯尾巴。图形只包含一组在出生时确定的局部像素块，播放期间局部轮廓和像素数量不变。
- 局部像素块以 4 px 为造型网格；整颗图形的屏幕位移只对齐 1 px，使轮廓保持清晰，同时避免 4 px 跳格造成的明显抖动。所有块共享同一个平移量，尾巴不得相对亮核跳动。
- 单次演出总时长保持约 1.8 秒，定位为小而清晰的远景流星，使用匀速直线运动。
- 前 1.35 秒保持完整可见；最后 0.45 秒继续移动并让整颗流星通过连续平滑曲线从不透明渐变到完全透明。只有透明度已经达到 0 后才结束生命周期，不允许在仍可见时清空图形或隐藏节点。
- 出生区划分为左右各三个高度/横向组合，共六个轨迹带；相邻两次不得使用同一轨迹带，并在带内继续随机起终点。
- 轨迹避开月亮核心可读区，只经过画面上半部。
- 流星层位于 `Stars` 之后、月亮与云层之前，不覆盖角色、屋顶或战斗 UI。
- 同一时刻最多一颗流星，不叠加成流星雨。

## 方案取舍

- 采用：程序化稳定像素图形。无需新增资产，可保持 Scene1 的像素语言，并能用数据验证轮廓稳定和淡出连续性。
- 不采用：`Line2D` 连续光带。其宽度和颜色渐变自然，但整体更接近柔和光效，与本次确认的清晰像素方向不一致。
- 不采用：预制流星序列帧。轮廓控制最强，但需要先产出并验收新资产；当前稳定图形不需要扩大资产范围。

## 组件与数据流

新增 Scene1 专属 `Scene1PixelMeteor` Control 组件并实例化在 `scene1.tscn`：

1. 组件维护自然触发倒计时、点击窗口、点击计数和当前流星状态。
2. 自然倒计时每次在 180–360 秒内重新随机；计时到达且当前没有流星时触发一次。
3. 组件订阅 Scene1 `NightSky.gui_input`，将 NightSky 已接收的鼠标左键位置转换为自身局部坐标；上层战斗 UI 仍拥有更高点击优先级。
4. 只有画面上半部的可见夜空点击计数；UI、角色、屋顶区域不计数，也不消费事件。
5. 4 秒内累计 6 次有效点击时立即触发，并清空点击窗口；超时则重新计数。
6. `trigger_meteor()` 在出生时生成一次稳定的局部像素轮廓；`_process()` 只推进整体位置和整体透明度，不再生成或删除尾迹点。
7. 最后 0.45 秒以平滑曲线计算整体透明度；透明度达到 0 后结束流星状态并停止逐帧处理，避免常驻开销。

组件提供可测试的 `try_register_sky_click()`、`trigger_meteor()`、`is_meteor_active()` 和剩余计时查询接口；随机数使用组件私有 `RandomNumberGenerator`，测试可固定种子。

## 输入与兼容性

- 复用 `NightSky` 原本已经截获的 GUI 点击，不额外铺设输入遮罩；战斗 UI 和已有交互继续优先处理点击。
- 组件绝不调用 `accept_event()` 或 `set_input_as_handled()`。
- 夜空命中区域采用 Scene1 本地坐标和显式高度边界，不依赖当前窗口缩放。
- 保持 `battle_screen1.tscn` 继续加载 `scene1.tscn`，不改默认入口及 `battle_screen.gd`。

## 验证

- 单元测试：6 次有效点击触发；5 次不触发；4 秒超时重置；非夜空点击不计数；活动期间不叠加；自然间隔始终处于 180–360 秒；生命周期约 1.8 秒；局部像素轮廓在完整播放期间签名不变；所有像素块共享同一整体平移；最后 0.45 秒透明度连续、单调下降并在结束前到达 0；连续轨迹带不重复且固定样本覆盖至少四带。
- Scene1 结构测试：组件层级位于 Stars 与 Moon 之间，且鼠标过滤为忽略。
- 无截图运行时探针：加载真实 `battle_screen1.tscn`，模拟夜空连点；跨帧采样局部轮廓签名、整体位置和透明度，确认轮廓不抖动、末段渐隐后才结束生命周期，同时验证原有舞台节点和默认入口仍存在。
- 最后运行 Godot Import 与相关 GUT 测试；不生成或读取截图。
