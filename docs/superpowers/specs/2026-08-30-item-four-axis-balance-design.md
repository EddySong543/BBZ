> **状态：已确认。** 机制价值、逐次使用费、耐久、占格、临时件显示与金币量级已经确认；具体道具仍须逐件审批，运行时尚未迁移。
> **文件名说明：**为避免已有链接失效，文件名暂时保留历史 `four-axis`；正文从 2026-08-30 起已经升级为**五维**，不得再按四维设计道具。
> **范围：**本文件建立机制价值、逐次使用费、耐久、占格、金币价格及生命周期的审查口径，不审批具体道具。
> **优先级：**完整现行规则先看 [`2026-08-30-item-system-current-standard.md`](2026-08-30-item-system-current-standard.md)；涉及五维平衡时以本文为专项真相源。早期固定目录值、固定 1 能抽取、免费使用、按稀有度固定耐久或形状、低金币标尺及临时件显示为 0 均只作历史记录。

## 0. 本轮结论

道具以后必须同时通过五道彼此独立的审核：

1. **机制价值**：一次合法使用在不同局面中的价值范围，是否改变选择并形成真实顺序差异；
2. **逐次使用费**：每次把该道具放进权威序列需要支付多少能量；
3. **耐久**：这个实体能用几次，每多一次使用会增加多少实际价值，名字与物理形态是否支持；
4. **占格**：它支付多少背包空间，属于笨重工具、普通货、紧凑强件还是高单格价值珍品；
5. **金币价格**：它的正常显示价值、可兑现价值、满耐久价格和残损曲线。

五维共同描述一件物品，但不由稀有度统一控制。高费、昂贵、耐用或占格大不能证明战斗内超模合理；反过来，强力、高价且紧凑也可以是搜打撤中有意存在的高价值珍品。

## 1. 统一术语与真相源

### 1.1 五种数值

- **机制价值范围 `V=[V_floor,V_normal,V_peak]`**：分别记录裸用或不利局面的下限、普通构筑中的常态，以及理想 Combo 的峰值。它是比较尺，不是能量汇率。
- **逐次使用费 `C`**：每次权威使用该实例需要支付的能量，当前正式范围为 `0–4`；多耐久件每次都重新支付。
- **最大耐久 `D` / 剩余耐久 `r`**：实体最多和当前还能被权威结算多少次。每增加一次耐久都要单独审查其边际收益。
- **占格 `S`**：物品固定形状实际覆盖的背包格数。形状只承担空间与携带价格，不产生邻接、朝向、连线或图案奖励。
- **显示价值 `P_display` / 可兑现价值 `P_cash`**：玩家看到的正常物品估值与当前能够出售、回收或带出的价值。临时件正常显示同名物品价值，但 `P_cash=0`。

战斗评分是五维之外的额外系统评分，不等于金币价格，也不能用金币价格直接代理单场战斗强度。

## 2. 阶段 0：基础规则收口

### 2.1 成品与通用取得规则

- T1/T2/T3 成品都可以作为真实资产进入仓库和战备方案，不要求所有 T3 先通过通用图纸铸造。
- 当前取得以 [`2026-09-05-item-opening-and-paid-refill.md`](2026-09-05-item-opening-and-paid-refill.md) 为准：开局随机三件、一次免费部分调换；R2起每回合最多花1能开启三选一，只补一个空框，候选不刷新。
- 选中实例进入公开框并锁定本回合，第 `R+1` 回合才可使用；候选私密，取得结果公开。当前 PvE 中敌方结果在同一权威节拍公开。
- 框满不能抽，有剩余耐久的占框道具不能免费替换。完整边界以当前标准为准。
- 这套取得、锁定与逐次收费规则已经通用定稿，不再为 PvE 单独审批。

### 2.2 使用费与扣耐久

每次权威使用先按该道具当前 `C` 支付能量，再扣 1 点物理耐久，随后结算效果。前一件道具产生的能量可以支付后一件；后一步的能量不能倒付前一步。

统一判据是：**只有 BattleCore 产生一次权威的“道具已使用”事件，才扣 1 点耐久。**

| 情况 | 是否扣耐久 | 结果 |
|---|---:|---|
| 按住拖出但未松手 | 否 | 只作本地预览 |
| 尚未形成权威提交的本地编排 | 否 | 不改变实体 |
| 整段提交因基础非法被 BattleCore 拒绝 | 否 | 原子拒绝，不执行合法前缀 |
| 权威重放执行到该道具步骤 | 是 | 扣 1 点，再结算效果 |
| 合法使用后被反制、免疫或收益为 0 | 是 | 已经使用，费用与耐久都不退款 |
| 复制上一件道具的效果 | 只扣复制件 | 不再次消耗原实体，也不复制实体 |
| 重发同一提交 | 最多一次 | 以回合号、序列号和实例 ID 保证幂等 |

耐久降到 0 时，效果结算完成后销毁实体；仍大于 0 时保留在原公开框，不能免费替换，并在下一回合按同一实例每回合一次的规则再次可用。

道具的物理耐久与效果次数必须分开。例如法器的 `remaining_uses` 是实体耐久，而施放后产生的“三次攻击内生效”属于 `effect_charges`；触发持续效果不继续扣物理耐久。

### 2.3 战斗边界、归还与搜刮

耐久跨当前 Run 保留。每场结束固定按以下顺序结算：

1. 完成本场权威战斗；
2. 删除耐久为 0 或被主动销毁的实例；
3. 清除本场临时战斗标记；
4. 剩余实例按原归属返回背包或保险格；
5. 按当前PvE入口处理失败资产与固定战利品，整理下一场战备；不自动搜刮敌方战斗余件或生成临时替代件。

归还不等于战利品：当前PvE敌方战斗负载与固定战利品分账，不能把未用掉的框作为额外掉落。玩家失败后的保留按远征保险规则另行结算。该取得/归还覆盖边界见2026-09-05专项；旧败者搜刮与临时替代语义不在本入口启用。

临时件不能被搜刮、出售、保险或带出，Run 结束全部消失；但其卡面与背包中仍正常显示同名物品的估值，不能显示成 0。

## 3. 阶段 1：机制价值范围

### 3.1 三档审查范围

| 稀有度 | 常见机制价值范围 | 必须承担的职责 |
|---|---:|---|
| **T1** | 通常 `1.0–2.0` | 简洁、可独立使用的基础工具；核心件贴近下限时必须以稳定性、广目标或连接性补足 |
| **T2** | 通常 `>2.0`，不设固定中心与上限 | 连接两个以上公共玩法轴、改变一次计划或提供明显顺序选择；不能只是 T1 数值翻倍 |
| **T3** | 通常 `>3.0`，且必须质变 | 成为一轮计划或 build-around；仅有较高粗数值不自动成为 T3 |

这些范围不是能量兑换表。伤害、治疗、护甲、能量、目标调度、持续状态和规则改写的边际价值随场面变化，不允许用一个固定汇率互换。

### 3.2 单件价值审查

每件道具至少记录：

- 裸用或不利局面的下限；
- 普通阵容与普通资源状态下的常态；
- 理想英雄、道具与顺序组合的峰值；
- 目标不存在、溢出或被预判时的损失；
- 多件同类与一个公共行动组成的最坏爆发；
- 是否真的改变使用顺序、公共动作或对手应对，而不是只有唯一正确顺序。

耐久不直接乘进单次机制价值；它进入生命周期审查。

## 4. 阶段 1：逐次使用费审查

### 4.1 费用范围

| 使用费 | 主要职责 | 重点风险 |
|---:|---|---|
| `0` | 严格受限的连接、搬运或带明确风险的工具 | 无损循环、免费产能、免费复制与序列无限增长 |
| `1–2` | 大部分基础件、主力件和组合件 | 是否挤压或替代「波 / 攒 / 防」的核心选择 |
| `3–4` | 改变局势、整轮计划或 build-around | 蓄能后的无反制终局、领先滚雪球和高费死卡 |

费用逐件决定，不与稀有度机械绑定。T1 可以因高即时收益而收费 2，T3 也可以因极端前置条件而低费；但任何偏离都必须用实际场景说明。

### 4.2 费用审查问题

逐件决定 `C` 时必须回答：

1. 使用它会放弃本回合或未来哪些「波 / 大波 / 大防」路线？
2. 它是独立强件还是组合连接件，费用会不会把两件 / 三件链整体税死？
3. 它是否产能；按实际顺序计算后，是否形成净免费、循环或为后件无限融资？
4. 多耐久重复支付时，后续使用仍值得吗；若不值得，耐久是否只是虚假价值？
5. 领先与落后玩家支付同一费用时，是否造成无法追回的资源滚雪球？

## 5. 阶段 1：耐久审查

### 5.1 耐久不与稀有度绑定

Demo 使用确定性的正整数耐久，不按 T1/T2/T3 设置允许范围或默认次数。可以存在单次使用的 T3 消耗品，也可以存在多次使用的 T1 工具。

逐件决定 `D` 时，必须对第 1、2、3……次使用分别回答：

1. 这次额外使用只是重复原收益，还是形成新的决策窗口？
2. 是否省下重新取得、抽取或寻找同类道具的成本？
3. 是否能连续重复同一 Combo，令收益超线性增长？
4. 在一场战斗或一次 Run 中，实际兑现这次使用的概率有多高？
5. 对手已经看见该道具后，后续使用是更难兑现还是形成持续威胁？

不能用统一的 `单次价值×耐久倍率` 定价。满价与残损价要按该道具各次剩余使用的实际边际价值建立曲线。

### 5.2 名字必须支持次数

- 一瓶药、一张符、单支箭、炸弹等自然指向一次性；
- 药匣、符袋、箭筒、书、盾、甲、罗盘、炉、钟和工具可以自然支持多次；
- 名字不支持重复使用时，应改物件形态或降低耐久，不能用解释强行补洞；
- 名字只是语义门槛，不是数值补偿。

## 6. 阶段 1：占格审查

### 6.1 占格不与稀有度绑定

- T1/T2/T3 均可使用背包当前支持的任意合理形状；不存在默认格数或稀有度占格带。
- 先根据物件本身确定自然形态，再决定它是笨重低密度、普通、紧凑强件还是 Jackpot 珍品。
- 可以有大体积廉价 T1，也可以有单格、高强、高价 T3。高单格价值本身是搜打撤的奖励，不是必须修平的异常。
- 同名道具形状固定，不能在掉落时随机变化。
- 形状仍只承担空间、携带与搜刮取舍，不扩展为邻接、朝向、连线或图案战斗系统。

### 6.2 两个诊断指标

- **生命周期战力密度**：预计可兑现的全生命周期战斗价值 ÷ `S`；
- **金币密度**：当前正常显示价值 ÷ `S`。

二者只用于发现离群道具，不要求同档、同耐久或全池趋同。紧凑强件可以有意形成尖峰；审查重点是它是否通过稀缺、资产风险、战斗评分或对局反制支付了合理代价，而不是强迫增大占格。

## 7. 阶段 1：金币量级

### 7.1 撤离分布锚

金币单位整体上调。以下按**成功撤离时可兑现的带出总值**定义；入场成本与本局损耗另列为净收益，不混在一个数字中：

| 成功撤离分位 | 初始目标 |
|---:|---:|
| P25 | 8万–12万 |
| P50 | 20万–30万 |
| P75 | 45万–65万 |
| P90（大赚） | 90万–120万 |
| P99 | 250万–400万 |
| 极端 Jackpot | 800万–1000万 |

“百万撤离”应是明显的大赚结果，不是普通满包；“千万撤离”是设计软上限。上限通过掉落表、背包容量与极端物品产率形成，不在结算时对超出金额生硬截断。

### 7.2 单格经济层次

初始财物密度可用下列范围建立掉落表，后续以模拟和实测调整：

- 填充货：`0.2万–0.8万/格`；
- 普通货：`1万–2.5万/格`；
- 高值货：`3万–8万/格`；
- 稀有货：`10万–30万/格`；
- Jackpot：`50万–150万/格`；
- 极端单品：允许 `1–2` 格、总可兑现价值约 `600万–800万`，与其他高值物共同逼近千万。

战斗道具价格不再从稀有度、耐久或格数表格自动生成。它由预计生命周期用途、取得稀缺性、市场需求、紧凑性和资产风险共同决定；不同稀有度的价格允许重叠。

### 7.3 临时件与三套价值

- **正常显示价值**：真实件与临时件都显示同名、同剩余耐久物品的正常估值；
- **可兑现价值**：真实件按当前状态计算，临时件为 0；
- **战斗价值**：真实件与临时件都按实际战斗能力计算，不直接照抄金币价；
- **单次机制价值**：继续使用 `V` 范围，不能用高价格证明超模合理。

玩家界面不把临时件显示成 0，只通过“临时”标记和结算规则说明其不能出售、入库或带出。

## 8. 单件道具必须填写的五维卡

| 字段 | 必填内容 |
|---|---|
| 名称 / 玩家文案 | 自然的奇幻道具名；一句简洁人话 |
| 稀有度 | T1 / T2 / T3，以及为什么属于这一档 |
| 机制价值 | 裸用下限 / 普通常态 / 理想 Combo 峰值，关键场面与顺序例 |
| 逐次使用费 | `C=0–4`、为什么属于该档、与核心行动的资源冲突和多件链总费用 |
| 耐久 | `D`、名字为什么支持、每增加一次使用的边际价值与重复 Combo 风险 |
| 占格 | 固定形状、`S`、自然体积与密度身份 |
| 金币 | 正常显示价、可兑现条件、满耐久价与逐次残损曲线 |
| Combo | 至少一组道具组合和一组英雄组合，说明哪项行动选择改变 |
| 反制 | 对手从公开信息能做什么，失败时损失什么 |

只有五维都成立，才能进入后续“小型纵切 → Demo 扩展池”的正式审批。

## 9. 当前实现差距

- `ItemData` 尚无逐次使用费、最大/剩余耐久、满价、固定形状和实例所有权的完整字段；
- 当前 `ItemCatalog` 仍带旧目录估值，旧池尚未按有序施放方向重设计；
- 取得实现状态按2026-09-05专项核对：开局三件与付费补充尚未实装；此处其他旧迁移清单保留历史价值，不再把免费抽取额度当作当前目标；
- AI、UI、协议、快照、断线重连、回放、存档和测试都尚未迁移；
因此本轮完成的是已经确认部分的设计真相与量级标尺，不是运行时完成声明。
