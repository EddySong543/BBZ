# 行动锚点序列设计

> **状态：已按用户纠错批准。** 本文取代“双方序列从左侧对齐”的旧规则；道具与免费切换仍按玩家提交顺序结算，双方唯一主行动固定在共同的 `0` 拍。

## 核心规则

每方合法序列必须且只能包含一个 `action` 步骤。该步骤包括「攒 / 波 / 防 / 大波 / 大防」、普通切换和占用行动的英雄主动技，统一称为主行动。

服务器先找到双方主行动，再把它们放在同一 `0` 拍。主行动之前的步骤从 `-1` 向前排列，主行动之后的步骤从 `+1` 向后排列；某方在完整拍域中缺少步骤时，系统生成一次不消耗资源、不触发效果的对齐等待。

```text
拍位:  -2      -1      0       +1
P1:   道具 A   道具 B   大波    道具 C
P2:   等待     道具 D   波      等待
```

同拍双方已经开始的普通步骤仍完整结算，服务器遍历顺序不得制造座位优势。玩家提交序列保持不变；对齐等待只存在于权威结算结果和回放中，客户端不能提交。

## 为什么必须改

旧左对齐把“各自排第几个”误当成双方的战斗时点。例如 `[道具, 波]` 对 `[防]` 会结算为 `道具 | 防`、`波 | 空`，使正确猜中攻击的防御落空。道具数量因此能够绕过波波攒最核心的攻击 / 防御关系，属于规则错误，不是可保留的顺序博弈。

行动锚点只修复跨玩家坐标，不删除本方顺序：道具在主行动前仍可建立状态、产能或换位；道具在主行动后仍只能读取已经发生的攻击、防御、伤害和站位。

## 边界

- 对齐等待不是玩家行动，不收费、不扣耐久、不算使用道具或执行行动。
- 提交结果保留原始步骤与 `step_id`；结算列额外记录相对 `beat`。
- 同拍道具规则继续从共同开列快照建立结果；本轮没有道具与主行动同拍，因为双方主行动都独占 `0` 拍。
- `0` 拍对齐不推翻公共动作内部的既定子顺序：双方先付费，普通切换先完成，即时主动技随后完成，攻击伤害最后落账。已经启动的 H17 / H22 主动技不会因同拍受击而消失；H17 与 H21 同时发动时，H17 先完成转变，随后才被 H21 替换。
- H21【惊蛰】的现有文案明确要求打断敌方普通基础行动，因此它是 `0` 拍内的已批准中断例外：双方先支付已提交行动费用，惊蛰再取消敌方「攒 / 波 / 防 / 大波 / 大防」且不返能。它不取消普通切换或英雄主动技。
- 上述改变会使 H21 的打断比旧左对齐时稳定，数值风险必须单独复核，但本轮不擅自改英雄数值。
- H03【白额雷音】旧“命中后延后剩余序列”只会影响 `0` 拍后的步骤，已经失去原设计主体，必须重新设计；未选定新方案前不修改 H03 数据与文案。

## 验收

- 四拍示例逐格一致。
- `[道具, 波]` 对 `[防]` 时，防与波都在 `0` 拍并正确挡住。
- 双方主行动前后步骤数都不相等时，原相对顺序不变。
- 对齐等待不进入提交序列，也不产生 H03 的延后事件。
- H21 在共同 `0` 拍仍能取消敌方普通基础行动，但不取消主动技或普通切换。
- H17 在同拍伤害前完成转变，H22 即使同拍阵亡也保留已经发动的火兆。
