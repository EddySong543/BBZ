# H03「白额雷音」序列延后设计

> **状态：已批准；调度器与当前「连环鼓」后续行动运行时已落地，完整任意道具 / 行动统一提交仍待后续迁移。** 本文件固定双方序列如何对齐，以及 H03 如何令敌方后续序列等待一次。现有 PRE / 动作 / POST 旧路径与旧“对攻先制”只保留实现溯源价值，不能反向定义本设计。
> **冲突裁定：**涉及跨玩家序列对齐、同一结算位置的先后关系或 H03【白额雷音】时，以本文为准。道具有序施放、当前道具标准与构筑框架均应链接本文；尚未迁移的 UI / 协议不能反向恢复“双方同时独立、各自管各自”的旧规则。

## 1. 范围与不变项

- H03 仍为 **5 点生命、进攻定位、被动技能【白额雷音】**。
- 当前技能说明为：`尾火【虎】每回合首次攻击命中后，敌方行动序列中立刻获得一个空的行动位。`
- 本轮批准结算模型、技能边界与基础玩家术语；最终动作列表样式和等待动画仍待后续设计。
- 旧“双方攻击时优先结算；击杀则断招”彻底退役。新技能不增加伤害、不取消已经开始的步骤，也不改变敌方剩余步骤的相对顺序。

## 2. 内部术语

以下术语只用于设计、代码、协议和测试：

- **sequence**：玩家提交的一整段有序序列。
- **step**：某一方序列中的一个真实步骤，例如使用一件道具或执行一个行动。
- **column**：双方序列左对齐后，同一横向位置上的一对 step；某一方也可能为空。
- **empty**：该方已经没有剩余 step。empty 不是玩家提交的行动，也不是等待。
- **generated wait**：由服务器权威效果生成的一次等待。它占用一个 column，但不消耗玩家原序列中的 step。

玩家侧统一使用以下术语：

- **行动序列**：玩家本回合排好的全部行动。
- **行动位**：双方同时结算的一处位置。
- **延后**：系统在一方行动序列中插入一个空的行动位；它不是玩家可以主动提交的行动。

H03 文案直接描述结果——“获得一个空的行动位”，不必强行写入术语“延后”。UI、教程和最终玩家文案不使用 `step`、`column` 或 `generated wait`。

## 3. 双方序列的基础结算

双方提交的 sequence 从左侧开始对齐，按 column 从左到右结算。例如：

```text
P1: [道具 A, 道具 B, 大波, 道具 C]
P2: [道具 D, 波,     道具 E]

column 0: 道具 A | 道具 D
column 1: 道具 B | 波
column 2: 大波   | 道具 E
column 3: 道具 C | empty
```

固定规则如下：

1. **逐 column 前进。** 一个 column 完整结束后，才进入下一个 column；前一 column 造成的能量、生命、状态、道具实例与位置变化会被后一 column 读取。
2. **同 column 同时完成。** 两方在同一 column 已经开始的 step 都有权完成，不能因为服务器内部先遍历 P1 或 P2，就让其中一方取消另一方。实现可以串行计算，但最终结果必须满足交换 P1 / P2 后的对称性。
3. **同 column 不追溯。** 某一步骤在本 column 产生的“延后后续序列”之类效果，只能在本 column 完整结束后生效，不能把另一方已经开始的 step 推走。
4. **短序列自然留空。** 一方 sequence 先结束后，其余 column 该方均为 empty，另一方继续按原顺序结算。系统不会为了视觉整齐补入可触发效果的假行动。
5. **客户端序列保持不可变。** 服务器通过每方 cursor 与生成效果状态推进执行；不得通过原地插入数组造成剩余步骤索引、回放或重连结果漂移。

同 column 内更复杂的互相修改仍必须遵守既有内容规则和 P1 / P2 对称测试；本文不为尚未批准的道具新增隐藏优先级。若某件道具必须依赖“同 column 谁先算”才能成立，该道具在补齐对称规则前不能进入 Demo。

## 4. 【白额雷音】触发规则

H03 的一次合法触发必须同时满足：

1. 攻击来源是当前执行基础「波」或「大波」的尾火【虎】；
2. 该整次基础攻击穿过防御门并连接到合法目标，即现有公共语义中的“命中”；
3. 这是该尾火在每回合第一次成功命中的基础攻击。

因此：

- 被「防」或「大防」完整挡住时不触发，也不消耗“本回合首次命中”；若本回合还有额外基础攻击，之后第一次真正命中仍可触发。
- 穿过防御门后，即使伤害最终全部被护甲吸收或实际生命伤害为 0，仍属于命中。
- 道具伤害、攻击型主动技、追击、反击及队友攻击均不触发。
- 多段伤害、额外命中次数或命中 riders 仍只属于同一整次基础攻击，不重复生成等待。

## 5. 等待如何生成

触发攻击所在 column 必须先让双方 step 全部完成。column 结束后：

1. 服务器检查敌方 cursor 后方是否仍有至少一个未执行的**玩家提交 step**。
2. 若有，在敌方下一次真实 step 前生成一次 generated wait。
3. 下一个 column 轮到该方时，先执行 generated wait；该方 cursor 不前进，原下一 step 及其后所有 step 整体后移一个 column。
4. generated wait 完成后，敌方继续按提交时的原顺序执行；任何真实 step 都没有被删除、交换或复制。
5. 若触发 column 结束时敌方已经没有未执行 step，则技能无效：不生成尾部等待，不延长本回合，也不播放一拍只有等待的假结算。

“本回合首次命中”在命中成立时即已发生。即使敌方当时没有剩余 step，本次无效也不会把触发机会保留给尾火本回合可能出现的下一次攻击。

## 6. 同 column 与镜像边界

- **当前步骤受保护：**`尾火攻击 | 敌方道具` 同 column 时，敌方道具照常完成；等待最早出现在下一 column。
- **同拍互攻可双死：**`尾火攻击 | 敌方攻击` 同 column 时，双方攻击都完成。尾火即使在该 column 同时阵亡，只要其攻击已命中，仍在 column 结束后提出等待；之后是否还有有效剩余步骤由正常死亡与序列规则判断。
- **H03 镜像对称：**双方尾火在同一 column 首次命中，且双方均有剩余 step 时，下一 column 双方各 generated wait 一次；不存在 P1 或 P2 座位优势。
- **只延后未开始部分：**已开始的伤害、治疗、换位、扣费、耐久消耗和同 column 动画都不回滚。
- **不制造永久控制：**每名尾火每回合最多成功触发一次；额外行动只有在此前基础攻击均未命中时，才可能成为本回合第一次命中。

## 7. 示例

### 7.1 基础延后

```text
P1: [尾火·波, 道具 C]
P2: [道具 A, 道具 B, 大波]

column 0: 尾火·波 | 道具 A   → 波命中；道具 A 仍完整结算
column 1: 道具 C   | generated wait
column 2: empty    | 道具 B
column 3: empty    | 大波
```

P2 的 `道具 B → 大波` 没有交换，只整体后移一次。

### 7.2 被防住

```text
column 0: 尾火·波 | 防
```

波未命中，不生成 generated wait。若尾火本回合因额外行动还有第二次基础攻击，第二次攻击命中时仍可触发。

### 7.3 无剩余步骤

```text
P1: [尾火·波, 道具 C]
P2: [道具 A]

column 0: 尾火·波 | 道具 A   → 波命中，但 P2 已无剩余 step
column 1: 道具 C   | empty
```

技能不补 generated wait，也不新增 column 2。

## 8. 权威、协议与回放边界

- 客户端只能提交获得授权的真实 item / action step，**绝不能提交 generated wait**。协议第一道门应拒绝任何伪造等待；业务层第二道门再次拒绝。
- generated wait 只由服务器在权威 column 结算后生成，并进入权威事件流。客户端本地预演不得自行决定对手是否等待。
- 权威事件至少要能表达：column 编号、执行方、真实 step / generated wait、H03 来源方、等待目标方及等待实际生效或因无剩余步骤而未生成。
- 动作列表与公开动画只消费服务器事件流。最终玩家术语未批准前，可以保留内部调试标记，但不能把 `step` / `column` 直接当成正式 UI 文案。
- submitted sequence 不因技能而改写。回放必须从原 sequence、cursor 推进和 generated wait 事件得到相同 column；重连或重复消费事件不得生成第二次等待。

## 9. 验收门槛

- 左对齐示例中的 column 配对完全一致。
- 同 column 两方 step 都完成，P1 / P2 交换后结果镜像一致。
- H03 只认每回合第一次成功命中的整次基础攻击，完整防住不消耗机会。
- 等待只出现在触发 column 之后，敌方真实剩余步骤的相对顺序不变。
- 敌方无剩余 step 时不生成尾部等待。
- 双 H03 同 column 命中时双方下一 column 同时等待。
- 客户端提交 generated wait 在协议层与业务层都被拒绝。
- 权威回放、断线重连和本地离线结算对同一输入产生同一 column 事件序列。
