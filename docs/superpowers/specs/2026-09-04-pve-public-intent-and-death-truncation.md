# PvE 敌方公开序列与死亡截断

> **状态：已批准并实装。** 本文取代旧资料中“普通 PvE 双方私密规划、确认后才公开”的描述；未启用的模式不由本文提前决定信息规则。

## 1. PvE 规划顺序

每回合进入玩家规划前，敌方按当前权威战局动态生成本回合完整序列，并立刻提交、锁定。随后界面向玩家公开敌方每一步及其相对拍位，玩家再安排自己的道具、切换与主行动。

固定流程是：

`敌方取得道具 → 敌方生成并锁定序列 → 公开敌方序列 → 玩家取得道具与规划 → 玩家提交 → 按共同动作锚点结算`

- 敌方锁定后不能读取或响应玩家本回合尚未提交的选择。
- 玩家拖动、撤销、换位、取得道具或改变目标，都不能触发敌方重算。
- 敌方序列必须通过与玩家相同的费用、目标、实例、耐久和“唯一主行动”校验。
- 公开信息使用相对拍位，例如 `-1拍 生锈的飞镖｜0拍 波｜+1拍 普通治疗药水`。
- 调试器主动改写战局或强制指定敌方行动时可以显式重锁；这是测试入口，不是正式对局中的反应式 AI。

双方主行动仍固定在共同 `0` 拍。公开敌方序列改变的是决策信息，不改变动作锚点、同拍结算或本方步骤的原相对顺序。

## 2. 逐拍死亡检查

每一拍按以下顺序完成：

1. 双方该拍已经启动的合法步骤全部结算；
2. 处理本拍产生的死亡拦截、死亡、击杀与队友死亡 hook，直到状态稳定；
3. 检查双方当前出战英雄；
4. 若任一出战英雄已经确认阵亡，双方所有尚未开始的后续步骤一起取消；
5. 结算结束后进入既有强制换人或终局流程。

因此，同拍互相攻击仍会全部命中；不能因为内部先遍历到一方，就吞掉另一方已经启动的步骤。明确写明“打断”的 H21 等规则仍可在同拍内部取消行动，它属于技能效果，不属于死亡截断。

## 3. 被取消步骤

- 尚未开始的道具：不支付使用费、不扣耐久、不写入使用历史，也不产生效果。
- 尚未开始的主行动、普通切换与免费切换：不执行；免费切换只保留截断前已经完成的站位结果。
- BattleCore 生成的对齐等待和延后等待不是玩家步骤，不记录为被取消内容。
- 原始提交序列保持不变；权威结果额外记录 `sequence_truncated` 与逐步 `sequence_step_cancelled`，供回放和 UI 解释。

## 4. 例外与边界

- 仅后备英雄阵亡时，照常处理其死亡 hook，但不截断双方序列。
- 回合开始时的到期伤害若令当前出战英雄阵亡，视为发生在第一拍之前：本回合尚无步骤启动，因此整段序列取消。
- 致死拦截若成功令英雄继续存活，不视为确认阵亡，不触发截断。
- 若死亡发生在最后一拍，没有后续真实步骤可取消，只进入死亡换人或终局。
- 强制换人仍沿用现有结算后选择流程；截断发生在权威核心，换人界面不参与判定。

## 5. 验收契约

- 玩家获得控制权时，敌方序列已经提交并可见；玩家规划期间重复检查不会改变它。
- 一方在 `0` 拍阵亡时，双方 `+1` 拍道具都不收费、不耗耐久、不留使用记录。
- 双方在 `0` 拍互相击杀时，两次伤害都落账，再一起取消后续步骤。
- 后备英雄在第一拍前被到期伤害击杀时，出战英雄仍可走完整序列。
- 出战英雄在第一拍前被到期伤害击杀时，双方首拍及之后步骤全部取消。
