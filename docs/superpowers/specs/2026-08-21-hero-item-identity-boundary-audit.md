## 0. 裁定摘要

当时的问题不是 24 名英雄全部缺乏差异，而是通用道具长期侵入了英雄应独占的设计权限。当时英雄只有一条技能；道具却不占行动、使用免费、同回合不限数量，并覆盖施毒、脆弱、切换惩罚、强制登场、伤害分摊、额外行动和全体技能失效。这里的“使用免费”是本次审计当时的旧前提，现已由逐件使用费取代；身份边界结论仍然有效。

本审计采用已通过的方向：

> **英雄决定玩家反复怎样打；道具决定这一轮怎样准备、连接或兑现。**

审计后的首轮目标分布如下：

| 对象 | 裁定 | 数量 |
|---|---|---:|
| 英雄 | 保留为身份锚点 | 17 |
| 英雄 | 保留骨架、收紧边界 | 3 |
| 英雄 | 优先重设计 | 4 |
| 道具 | A·公共地板池 | 22 |
| 道具 | B·软适配战备池 | 36 |
| 道具 | C·传说图纸池 | 15 |
| 道具 | D·移至怪物 / 事件 / NPC / 藏品等来源池 | 29 |
| 道具 | E·重写后再决定池位 | 10 |
| 道具 | F·冻结，不进入可用池 | 2 |

因此，现行 114 件中暂定 **73 件进入标准 PvP 构筑体系**（A+B+C），其余 41 件不再稀释标准通用池。73 不是最终平衡数字，而是第一轮权限审计后的上限；实测仍可继续削减。

- `design/items-list.md` 中未实装储备、历史否决与序列化道具不计入 114 件。

- 旧记录中的 h24 死亡产能已经过时；本审计采用现行“降低能量上限换行动减费”。
- 本文裁定池位和权限，不直接修改 `ItemCatalog`、英雄资源或运行规则。

## 2. 权限边界

### 2.1 英雄权限

英雄至少应占有下列一项长期权限：

1. 改写一个公共动作的可选分支、目标、支付或结算。
2. 建立队伍反复使用的生产端、连接端或兑现端。
3. 迫使对手持续改变可读、可规避的出牌选择。
4. 以一条强规则例外配一项真实代价和明确绕行方式。

只有“触发后获得数值或附加标准状态”不足以形成英雄身份。

### 2.2 道具权限

标准池道具只承担以下职责：

- **窗口**：本回合或一次机会内改变计划。
- **桥接**：把已有来源转成另一种公共资源。
- **兑现**：消耗已积累、已公开或可预判的成果。
- **补缺**：提供安全但不形成长期引擎的填隙价值。
- **系统操作**：抽取、升级、回收、锁定等操作优先放在 NPC、事件或其他来源池。

标准池道具不得稳定复制英雄循环、永久占有英雄规则、无条件增加完整行动，或把所有英雄技能整体关闭。

### 2.3 临时借用英雄级权限

只有传说图纸、Boss 战利品或特殊事件道具可以短暂借用英雄级权限，并必须同时满足：

- 次数或回合有限；
- 使用前公开；
- 有真实构筑成本；
- 对手仍有绕行；
- 不直接复刻某个现行英雄的完整循环。

### 3.1 英雄处理顺序

1. **先保护已成立身份**：h04 / h06 / h07 / h11 / h18 / h21 相关碰撞道具先改写或移池。
2. **再重做四名弱身份英雄**：h01 → h12 → h20 → h09。顺序优先解决经济位同质化，再解决状态与干扰位。
3. **最后收紧三个骨架**：h02、h06、h19。不得在道具边界仍未处理时用加 rider 的方式“增强”。

## 4. 道具池裁定

### 4.1 池位代码

| 代码 | 池位 | 规则 |
|---|---|---|
| **A** | 公共地板池 | 简单、稳定、一次性或单回合；不要求特定英雄也不建立长期引擎 |
| **B** | 软适配战备池 | 仍对所有英雄合法，但由背包战备、收藏和构筑成本控制，不进入最小地板 |
| **C** | 传说图纸池 | 只能沿升级 / 图纸路线获得；允许有限 build-around |
| **D** | 来源池 | 从标准池移出，改由怪物、事件、NPC、藏品或特殊战利品提供 |
| **E** | 重写 | 当前权限与英雄碰撞或破坏公共博弈；重写前不进入标准池 |
| **F** | 冻结 | 结构违背核心公理，不再投放；保留数据便于历史追踪 |

## 6. 来源分池

来源分池不是把道具锁给某个英雄，而是控制“哪类高权限内容从哪里进入一局”。

| 来源 | 应提供的内容 | 本轮迁移示例 |
|---|---|---|
| 公共地板 | 基础攻击、防御、治疗、能量与净化答案 | 先手、后手、护甲、生命 / 法力药水、圣贤书 |
| 战备收藏 | 跨轴桥、读心件、一次调度和明确 build 组件 | 回马枪、盗版太极图、抵锋扣、分寸尺、双生咒符 |
| 传说图纸 | 有次数、代价和反制的 build-around | 龙息、赊命券、噬心钉、遗愿灯、停龙剑 |
| 怪物 / Boss | 主题强规则、穿透核心系统、遭遇级答案 | 心脏掌握魔法、周天罡气、锁泉塞、青元宝莲 |
| 事件 | 高方差、对称把戏、整局状态变化 | 赌徒硬币、均能斗、梦蝶、独用封 |
| NPC / 工坊 | 抽取、升级、保价、回收、复制与补给 | 随身熔炉、点金石、换签筒、回购券、应急箱 |
| 藏品 | 长周期定向生产或收藏能力 | 聚宝盆等永久自动道具引擎 |

所有玩家仍使用同一套公共战斗语法；区别来自战备选择和所得来源，不来自英雄专属物品列表。

## 7. 实施顺序

### 阶段一：只处理投放权限

1. 从标准候选池与默认战备中冻结 `连环鼓`、`息灵铃`。
2. 把 29 件 D 类道具移到明确来源标签；来源功能尚未实装时先不投放，不用通用抽取临时代替。
3. 把 10 件 E 类道具从标准投放中暂时移除，保留资源和逻辑文件。
4. 将标准构筑上限收口为 A+B+C 共 73 件。

这一阶段不同时重做英雄，避免池变更和英雄变更混在一次平衡结论里。

### 阶段二：保护英雄身份

1. 先重写十件 E 类道具并逐件重新过权限闸门。
2. 再收紧 h02、h06、h19；其中 h06 必须在毒药瓶新方向稳定后审查。
3. 最后依次重设计 h01、h12、h20、h09；每名英雄单独经历三方向、碰撞表、组合与反制审查。

### 阶段三：来源内容与怪物设计

1. 怪物首先承担“遭遇规则”和“战利品来源”，不按可招募英雄的对称标准设计。
2. 每只怪物只引入一项清楚的遭遇压力；奖励道具与该压力的主题呼应，但不能成为唯一解。
3. NPC / 事件 / Boss 池分别实现后，再把 D 类道具逐批接入；不得一次全放回。

## 8. 验收标准

### 8.1 英雄

- 不看道具时，玩家可以用一句动词性描述说清该英雄怎样改变出牌。
- 至少一个具体队友会因为该技能改变公共动作选择，而不只是获得更多数值。
- 对手至少有一条可见、可执行的绕行。
- 三件标准池道具不能在多回合内复刻该英雄的完整循环。
- 除少数签名英雄外，不增加专属资源条或长期 UI 记忆负担。

### 8.2 道具

- A 类一眼能懂，失败时不会让整回合失去基础行动。
- B 类必须指出来源、转换和兑现中的位置；“泛用加数值”不能冒充组合件。
- C 类必须有次数、条件、构筑成本或失败代价中的至少两项。
- D 类有唯一且已实现的来源；无来源时保持不可投放。
- E 类重写后不得再与现行英雄保持“同触发＋同收益”。
- F 类不得出现在抽取、战备、怪物掉落、调试默认阵容或图鉴可用状态中。

### 8.3 池与对局

- 英雄阵容应先暴露大致战术方向，道具只改变执行路线和时机。
- 对手从公开道具框仍能获得至少一回合电报；迷雾类效果不进入标准竞技池。
- 标准池不得再出现额外完整行动或全英雄技能关闭。
- 标准池每增加一件道具，必须同步检查 24 名英雄与最坏三道具组合。
- 一轮试玩后若玩家首先用道具名而不是英雄名描述队伍，视为身份审计未通过。

## 9. 非目标

- 不建立 24 套英雄专属道具池。
- 不给每名英雄扩成四技能或独立卡组。
- 不引入天气、元素克制、暴击、攻速、宠物、邻接或朝向系统。
- 不用复杂 `if/else`、更多层数或专属标记伪造差异。
- 不在本审计中决定四名待重做英雄的新机制；它们必须分别进行下一轮三方向设计。
- 不因本轮分类直接删除任何资源文件；先从投放端隔离，保证可恢复和可复审。
