# 开局三件与付费补充：取得状态机补充

> 日期：2026-09-05。状态：已通过方向的纸面收口，尚未实装。
> 本文只覆盖取得、锁定、公开框与战末归还。费用、英雄、二十件道具、共同0拍和死亡截断不变。
> 优先级：本文覆盖旧标准中开局空框、每轮免费抽取的段落；总入口仍是 `2026-08-30-item-system-current-standard.md`。

## 1. 已批准规则与必要边界

- 每战开始，从本方真实战斗背包按 UID 等概率无放回随机取三件，直接填入三个框；不是连续三次三选一。
- 开局有且只有一次免费部分调换。选择要换的框后一次确认，一次随机补回相同数量；不是替换候选三选一。
- 三件第一回合全部锁定，第二回合起可用。第一回合没有额外补充机会。
- 第二回合起，每方每回合至多支付1能，打开一次固定三选一，只补一个空框；新取得件下一回合可用。
- 不自动补充、不付费重抽、不累计机会、不开放免费弃置、替换或销毁存活框内物件。
- 敌方完全遵守同一取得、锁定、费用、耐久和 UID 规则；敌人偏好只影响如何选，不改变抽样概率。

沿用现行“没有最低合法 UID、不得补假件”的边界：真实合法实例不足三件时，开局装入全部 `min(3,N)` 件，余框为空。三框填满是库存足够时的规则，不能解释为凭空生成或强制最低三件。N=0 仍可进行基础战斗。这是库存不足处理，不重新开放取得方向。

## 2. 实例与集合不变量

`B` 是尚在背包的合法实例集合；`S[0..2]` 是公开框；`M` 是本次调换隔离区；`C` 是候选 UID 引用列表。

合法实例必须属于本方本场战斗储备、是已启用战斗道具、耐久大于0且未在任何框或隔离区；普通战利品不进入 B。主背包与保险箱来源元数据保留，本文不额外开放新的来源容器。

- 同一 UID 同时只能在 B、S、M 中的一个位置；C 只引用 B，不复制实例。
- 同名不同 UID 是不同物件，可以同抽、同场，最多占三个框。
- 物品从背包进入框时保留原所有者、来源容器、格位与剩余耐久；物理空间保留归还位置，进入框不等于已经消耗并释放背包空间。
- 本轮不生成任何 REAL、RUN_TEMPORARY 或 BATTLE_TEMPORARY 实体。旧临时件来源与复制权限不能借取得修订自动开启。

## 3. 开局状态流

`战斗储备快照 → 随机装框 → 一次部分调换/保留 → 双方最终结果公开 → R1锁定 → R2就绪`

1. 保存两边真实储备快照、UID 与来源；抽取 `h=min(3,N)` 个不同 UID，按抽样顺序进入0、1、2号框。
2. 令初始三件集合为 I，剩余储备 `B0=B\I`。调换只能从 B0 取替换件。
3. 玩家选择 I 的子集 K，`|K|≤min(h,|B0|)`。例如总库存4件，只能换一个框；不能选三个后暗中只换一个。
4. 确认时先把 K 隔离到 M，再从 B0 一次无放回抽 `|K|` 件，分别填回选中框；全部完成后才把 M 返回 B。
5. 初始 I 中的任一 UID 都不能在此次替换抽样出现。新替换件也不能再次调换；取消选择只可发生在确认前。
6. 选择保留、或无合法替换件时，直接结束调换阶段。不消耗能量或耐久。
7. 双方各自结束开局调换后公开最终框；候选与被换出物件不新增公开。敌方在看到玩家最终调换结果之前先完成自己的开局选择。
8. 所有最终框设 `acquired_round=1, ready_round=2`。本场第一回合无法把它们放入序列；初始团队能量仍是1。

## 4. R≥2 的付费补充事务

顺序沿用已批准公开时点：

`回合开始到期处理/必要强制换人 → 敌方补充或跳过 → 敌方校验并锁定完整序列 → 公开 → 玩家补充或跳过 → 玩家规划提交 → 共同拍位结算 → 最终清理`

开启前必须同时满足：R≥2、有 EMPTY 框、B 非空、当前团队能量≥1、本轮未开启/放弃/跳过补充。LOCKED、READY、已使用但仍有耐久及 DEPLETED_PENDING 都不是空框。

| 状态/事件 | 权威变化 |
|---|---|
| 未开启即跳过 | 不收费，关闭本轮补充入口；进入规划后不能回头补充 |
| 满足条件后开启 | 原子扣1能，记本轮已开启，缓存从当前 B 无放回抽出的 `min(3,|B|)` 个 UID |
| 重复开启请求/暂时收起 | 返回原候选，既不重复扣费，也不换候选；只有明确选定或放弃才结束此阶段 |
| 选择一个候选 | UID 从 B 移入编号最小的 EMPTY 框；`ready_round=R+1`，结果公开；其余候选留 B |
| 已开启后放弃 | 不退款，本轮不能再开；所有候选留 B |
| 非法选择/重复提交 | 不增加收费或实例；无效选择保持原事务，成功事务只提交一次 |
| 没有合法候选/空框/能量 | 不开启、不收费；不得拿后续「攒」或药水来倒付开启费 |

1能是**开启候选时的系统费用**，不是道具使用费，也不是主行动费：瓶装能量、H14生命代付、H24行动减费均不能减免；不耗道具耐久，也不占拍位。先扣完它，再校验本回合行动的能量前缀。

一次候选列表内部无放回；未选件、开局换出件以后可以在不同回合再次出现。没有“整场不再出现”的隐藏排除池，也没有同次调换反复抽到原件。

敌方取得的新件也只能下回合用。敌方锁定后，玩家开启补充、放弃或改计划均不能令敌方重算。此信息先后是公开PvE已经批准的非对称性，不能为了“敌方对称”把它改成同步盲选。

## 5. 框与死亡

- `EMPTY → LOCKED(R+1) → READY`；开局三件同样到R2才READY。
- 一个 UID 每回合最多使用一次。实际使用扣使用费与1耐久，剩余耐久大于0则留框，下回合可再用。
- 耐久归零进入 DEPLETED_PENDING，本回合最终清理时才成为 EMPTY；本回合不能补。
- 英雄阵亡不销毁团队框。每拍确认出战位阵亡仍截断双方未开始步骤；取消的道具不扣费、不扣耐久，先前已经支付的补充开启费不退。
- 后备单独阵亡不截断；新取得件不会因换人、出战位阵亡或复活而提前解锁。

## 6. 战斗结束与归还

先完成同拍、死亡与终局结算，再清理耐久归零实例和本场效果。剩余真实实例按原 UID、原所有者、当前耐久返回其本场储备来源（包括原保险位置）；归还只是取消战斗容器占用，不恢复耐久，也不产生战利品。

战斗胜利后，玩家仍在同一远征中：HP不自动回满，道具残损保留。失败/放弃的物品保留再服从远征与保险规则；归还不能把本应丢失的物品救回仓库。

敌人战斗负载与遭遇生成时已固定的携带战利品分账：未使用的敌方框不自动额外掉落，用完敌方道具也不扣减固定战利品。旧五维文档的“归还后搜刮败者剩余道具、生成临时替代件”不适用于此PvE入口，不通过本次归还重新启用。

## 7. 可复核轨迹

| 检查 | 结果 |
|---|---|
| N=0/1/2/3 | 装0/1/2/3件；均无替换储备，不生成UID |
| N=4，初抽A/B/C，储备D，换B | 最终A/D/C，B回储备；同次不可能抽回B |
| N=6，初抽A/B/C，换A/C | 从D/E/F取两件填0/2框；B保留；A/C在替换完后回储备 |
| R1「攒」 | 1→2→回合末3；三件仍未使用，R2三件READY |
| R2「波」使用一件D1 | 先逐步正常付费，终清腾一个框；R2不能倒回补充 |
| R3补充前2能 | 开启2→1；新件R4可用；本轮仍可支付1费波，不能支付2费大防 |
| R3补充前0能但有魔力药水 | 不可开启；药水在序列中所得能量只供之后步骤，不反向购买候选 |
| 有两空框、开启一次 | 只填一个，另一框继续空；本轮不得再扣1能填第二个 |
| 三件D2首次用完 | 三框仍占用；不能补充，不能免费丢弃不想要的工具 |
| 0拍致死，双方+1药水取消 | 药水保留费与耐久；本轮之前已付补充费仍已支出 |

## 8. 概率与实现状态

旧 PLAN3两件链、PLAN4三件链概率仅为历史。开局三件把最早READY统一提前到R2，但支付与合法目标仍可能更晚；后续新增件再受1能、空框和一回合锁定限制。具体重算与冲突清单见 `../../reports/2026-09-05-item-acquisition-conflicts-and-probability.md`。

只读核对：当前 `BattleCore.begin_item_v2_draw()` 仍是旧免费候选，未检查1能；`configure_item_v2_backpacks()` 仍按目录ID创建原型实例，最低UID测试档还可能补入测试物件。这不是真实资产闭环。当前二十件目录与共同拍位原型已存在，不能据此声称新取得已经落地。本轮不修改运行时。
