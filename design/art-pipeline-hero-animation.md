> 剪纸/骨骼绑定（原主推）**已放弃**——见下方「决议变更」。
> **关联**：`design/heroes.md`（英雄设计）、`prototypes/juice_test/`（视觉验证原型）、`assets/sprites/heroes/`（美术目录）。

## ⚠️ 决议变更（2026-05-25）：剪纸绑定 → A 方案

本文档原主推**方案 2（剪纸/骨骼绑定）**，是在 2026-05-24 brainstorm 时、**尚未看到真实立绘尺寸**的前提下做出的。

**2026-05-25 拿到真立绘后推翻**：`h01.png` 仅 **128×128**，人物高约 **60px**，手臂宽约 **8px**。在此尺寸下：
- 剪纸绑定**旋转手臂会糊**，破坏像素质感；
- 屏上人物只有指甲盖大小，**根本看不清手臂动作**，绑定收益趋近于零。

→ **放弃剪纸绑定**，改采**方案 3 的增强版 = A 方案**：立绘整张不切，攻击全靠**代码 juice + 武器分类斩击特效**叠加表现；idle 用真帧动画。下方第 2 节起的方案分析**保留作为决策推理记录**，但最终结论以本节与第 5 节为准。

## 0. 约束前提
- 个人开发者，英雄池最终 46 个（当前实装 34 = 12 生肖 + 22 塔罗；**星座 h35-h46 暂停**）；**立绘已生成**。
- 每英雄**独立武器** → 攻击/技能动作无法简单复用同一套位移。
- 观感目标：理想是《杀戮尖塔》级独立动画；现实底线 = **能做完**。
- 品类：同时回合制 1v1 对拼 + 3 英雄切换。
- 终局可能上**手机端、prefer 竖屏**。
- **真实立绘尺寸**：128×128、人物 ~60px、手臂 ~8px（**像素小图**，决定了下方方案取舍）。

## 1. 核心认知（先纠正问题定义）
- 真正瓶颈不是"缺场景"，是 **per-hero 逐帧 spritesheet 模型**（46 × idle/attack/hit/defend/defeat/技能 ≈ 276 套），solo 做不完，且本品类不需要。
- 参照：**StS 自己也没全做**——玩家 5 角色才有逐帧，敌人多为少帧 + 程序化位移。
- **打击感 = juice**（顿帧 / 震屏 / 闪白 / 粒子 / 数字 / 音效），写一次全员复用，比逐帧更划算。**这一条正是 A 方案的核心支柱。**
- **同时结算是省力红利**：双方"向中心对冲 → clash 闪光"的演出**只编排一次**，不分先后手，省一半动画。
- **小尺寸像素立绘**：人物只占屏幕指甲盖大小 → 不需要、也看不清精细的肢体动画；攻击表现的重量放到**特效与全屏 juice** 上更有效。

## 2. 五个方案（从重到轻 · 决策推理记录）

**方案 1 · 全员逐帧手绘动画（理想 / StS 级）**
- 做法：每英雄手绘 idle/attack/技能等帧序列。
- 短板：**46 个 solo 基本做不完**（StS 才 5 个玩家角色，你是 9 倍）。→ 理想但否决。

**方案 2 · 剪纸 / 骨骼绑定（Cutout Rig）← ⛔ 已否决（2026-05-25）**
- 做法：把静态立绘切块绑骨架，用通用动作模板摆动，武器随手臂块差异化。
- **否决理由**：真立绘仅 60px 人物 / 8px 手臂，**旋转 limb 发糊、破坏像素感、屏上看不清**，绑定收益趋近于零。曾是主推，看到真尺寸后推翻。

**方案 3 · 静态立绘 + 代码 juice + 特效（无 rig）← ✅ 选定（A 方案）**
- 做法：立绘**整张不切**，攻击靠代码表现 + VFX 叠加，不切块不绑定。
- 原"短板=不区分武器动作"已被解决：用**按武器分类的斩击特效**区分（刀光/枪刺/杖砸 VFX 不同），人物本身不挥手也**不假**——屏上只指甲盖大、看不清手臂。
- 每英雄工作量：极低（用现成立绘，0 额外肢体美术）。→ **当前正式管线**。

**方案 4 · 卡牌对决桌**
- 短板：**改变了"舞台上两人对打"的构想，缺人物演出**——想避免。

**方案 5 · 极简头像 + UI 演出**
- 最省但最不"游戏场景"。→ 排除。

## 4. 支撑系统（A 方案的全套省力杠杆）
1. **通用 juice 层**：前冲 + 白闪(shader) + 震屏 + 后退弹动 + 顿帧 + 伤害数字——写一次，全员复用。已在 `prototypes/juice_test/` 验证。
2. **按武器分类的斩击特效**：每英雄武器归 1 类（见附录 A），同类复用同一套**程序化斩击 VFX**。不同武器靠"斩击特效不同"区分，人物不需挥手。
3. **idle = 真 16 帧动画**（`AnimatedSprite2D`，4×4 / 256px 表），已接入验证（Eddy 通过）。**静态 + 呼吸 shader 作保底**（0 额外美术也能"活"）。
4. **hit / 防 / 阵亡 / 攒 = tween + 共享 VFX**：0 额外英雄美术。
5. **AI 当加速器**：批量分目录 / 切 idle 表 / 生成 .tres / 生成方形头像（脚本能帮）。⚠️ **生成不了图片素材本身**（见下）。
6. **分级投入**：全员廉价档；最多 0-3 招牌英雄后期开小灶。
7. **MVP 先单英雄走通管线**（h01）→ 验证好玩 → 批量。
8. **管线朝向无关**：同一套立绘 + juice，横屏(PC) / 竖屏(手机) 都能用，只重排舞台与 UI。

### 特效能力边界（重要）
- **Claude 只能写代码，生成不了图片素材**。
- **AI 做不了像素挥砍特效**（帧不连贯 / 网格不齐 / 透明通道问题）——Eddy 直觉正确。
- **程序化特效（Claude 做，免费）已被认可**：刀光就是代码画的（`prototypes/juice_test/slash_vfx.gd`）。
- 若要**像素颗粒感**的挥砍：买通用素材包（一包覆盖 46，不定制）。
- 特效精修**暂缓到新美术导入之后**。

## 5. 推荐结论（现行管线）
**A 方案 = 静态立绘 + 代码 juice + idle 帧动画 + 武器分类斩击 VFX + 第 4 节全套支撑系统。**
- 取舍：非逐帧、非绑定；攻击靠特效与全屏 juice 表现，不靠肢体动画。
- 收益：**重复劳动几乎归零**——每英雄美术仅需立绘 + 头像 + idle 表 3 张图，其余全代码复用。
- 验证：`prototypes/juice_test/`（juice_test.tscn/.gd + 程序化刀光 slash_vfx.gd + hit_flash.gdshader），Eddy 评"远超想象"，2026-05-25 验收通过。

## 附录 A · 武器 → 斩击特效分类（5 类）

> A 方案下，武器**不再驱动肢体动作**，而是**决定斩击 VFX 的形态**。同类武器复用同一套程序化特效。

| 类别 | 斩击 VFX 形态 | 武器 |
|------|------|------|
| A 横挥/劈砍 | 弧形刀光 | 长刀、弯刀、剑、死神镰刀、匕首、金刚狼爪、铁链 |
| B 突刺 | 直线穿刺光 | 长矛、三叉戟 |
| E 重砸/拳 | 冲击波/震纹 | 空手、指虎 |
| C 远程/投掷 | 飞射轨迹 | 飞刀、金币、玫瑰 |
| D 举持/吟咏（施法） | 法阵/光柱 VFX | 法杖、权杖、竖琴、号角、2 杯子、提灯 |
| 特例 | 单独定制 | 狮子（生物伙伴，前扑/挥爪特效） |

> D 类多为辅助/施法英雄，"攻击"=举物件 + VFX，最省（连挥舞都不用）。

## 6. 美术导入流程（A 方案落地）

**每英雄美术 = 仅 3 张图**：`hXX.png`（立绘）+ `hXX_portrait.png`（头像源）+ `hXX_idle.png`（idle 表，4×4 / 256px）。

**导入步骤**：
1. **Eddy** 把 34 英雄（12 生肖 + 22 塔罗）的 3 张图改名为 `hXX.png` / `hXX_portrait.png` / `hXX_idle.png`，全部丢进 `assets/sprites/heroes/_incoming/` 一个文件夹。
2. **Claude** 写脚本自动：
   - ① 分目录：`_incoming/hXX.*` → `assets/sprites/heroes/hXX/`；
   - ② 批量抠图（立绘背景近纯色 → 色键抠图，如需要）；
   - ③ 批量生成方形头像（`tools/gen_thumbnails.gd`，色键抠图 + 人物 bbox + 顶部方形裁切）；
   - ④ 生成 34 个 `hXX_idle.tres`（idle 统一按 4×4 / 256px 网格切，自动跳空帧）。
3. 美术填进 v4 战斗台（`prototypes/battle_v4_ui/` 已留 `portrait_path` 接口）→ 正式带画面试玩。

> ⚠️ **现状**：仅 `h01/` 有图，`_incoming/` 批量导入尚未发生（等 Eddy 丢图）。
