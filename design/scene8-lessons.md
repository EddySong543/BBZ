# Scene8「天光镜湖」制作复盘与后续契约

## 1. 最终定位

Scene8 是雪地中的微亮极夜镜湖。核心不是“冰封地面”，而是仍在流动、反射极光的深蓝湖水；浮冰、岸冰、远山、雪地和冰晶只负责建立空间与交互。最终画面应同时满足：

- 夜空澄澈、微亮，不是空白纯黑，也不是灰雾笼罩。
- 极光是视觉主题，但缓慢、柔和地融入天空，并在湖面形成可读倒影。
- 湖面以水为主，近中远层次来自形状、密度、透视与反射变化，不能只靠三段明显变色。
- 独立浮冰平台必须处于同一水面与镜头平面，不能因视差、攻击推近或接触效果产生悬空感。
- 用户手动调整过且已通过的节点位置、缩放、构图和层级属于保护契约。

## 2. 工作过程回顾

### 2.1 框架与素材接入

最初复用 Scene1 的夜空、星空与成熟战斗场景接口，依次接入平台、远山、左右近景以及后续冰川、雪地和补充远景。接入素材时应先保留可编辑的直接节点，避免增加阻碍 Inspector 手调的包装层；用户手调完成后，后续优化只能围绕其构图做融合，不能重排 Transform。

### 2.2 湖面、岸冰与浮冰平台

早期湖面主要失败在三点：浮冰像长方形堆叠、湖岸没有贴合远景资产、近中远仅靠生硬变色。后来改为由远岸资产透明像素推导湖面占用拓扑，并让水、岸冰、反射和点击判定共享同一空间依据。岸冰采用薄曲线和少量破碎边缘，湖中保持大面积开水。

平台悬空感不是单个阴影参数能解决的问题，而是水线、吃水暗边、侧壁、接触碎波、平台位移和相机响应的联合问题。无论静止、鼠标移动、短促震动还是攻击推近，平台、水面接触层、倒影与上方角色必须保持一致的运动关系。

### 2.3 极光的多轮返工

程序生成的横向光带、密集同频动效和过度花哨的多条曲线均被否决。ref47 只适合帮助理解“横纵交叉、方向变化、末端渐隐”的构图语言，不能替代对目标像素形状的精确观察。ref48 成为最终静态基准后，正确流程应是：

1. 先锁定静态轮廓、色块比例、底部薄曲线与像素连续性。
2. 区分参考图里的极光像素和树木、山体造成的遮挡，不把黑色遮挡复刻成镂空。
3. 对红圈问题逐像素修补，只修局部连续性，禁止整块删除或大面积自动填充。
4. 静态形象通过后再制作覆盖整幅极光的缓慢动效，不能只让部分区域动，也不能让所有区域同频摆动。

这段返工最重要的教训是：像素参考的“精准复刻”首先是形状与色块关系，不是机械复制整张参考图。树、山和遮挡属于参考环境，不属于极光本体。出现第三次同类黑洞问题时，应停止继续凭肉眼补丁，改用像素掩码、连通性和曲线边界检查。

### 2.4 夜空、星星与整体亮度

纯黑背景使极光像贴图，统一提亮又容易变成灰蒙蒙的雾。最终方向是澄澈微亮的极夜：顶部保持冷蓝黑，远山交界到极光区域增加克制、非直线的绿色空气辉光，用局部色彩扩散连接极光与天空，而不是简单梯度或全屏雾化。

星星不能使用均匀的大方块网格。应保留细小、疏密不均、亮度分级的星点，避免规则尺寸、规则间距和明显贴图重复。

### 2.5 远景与近景联调

远景纵深不能靠降低透明度制造，否则重复素材会互相透出并暴露叠层。应保持不透明像素，通过轻量的色相偏移、对比保留、亮度控制和极光受光建立距离；同时保留素材原色，避免灰化。远景曾先被压得看不清，随后又过亮抢眼，说明远景和近景必须联合调节，不能分别追求“更暗”或“更亮”。

近景也不能简单整体压暗。正确目标是让雪面高光、冰晶颜色和暗部体积仍可读，并让近景雪地与左右资产在层级、色调、边缘和视差上连成一体。冰川与湖面交界处应通过岸线形状、薄冰和接触过渡解决，不能用不相干风格的冰块盖住问题。

### 2.6 粒子、碎光与冰晶交互

Scene8 粒子多次失败的原因包括：粒子过小看不见、速度不明显、风格偏离 Scene1-7。最终以 Scene3 的粒子结构为基准，只修改为适配极光的混合色和缓慢下落方向。项目通用原则是：稀疏表示减少数量，不是把粒子缩到不可见；1920×1080 下远景先以 8–12 px、近景先以 14–24 px 为可读基线，再通过数量控制克制感。

左右冰晶自动扫光被否决，最终改为鼠标点击触发的晶面火花。命中范围必须来自六簇冰晶的真实像素，不得仅用矩形区域近似；石头、积雪和透明边缘都不能误触。用户红笔圈选应被视为精确掩码证据，而不是大致提示。

### 2.7 湖面与平台点击彩蛋

湖面点击最终采用小型透视像素涟漪，并同步影响极光倒影。底部按钮、道具轨和其他战斗 UI 必须先于场景反馈拦截点击。涟漪采用动态事件纹理保存，每次有效点击追加独立事件；不设固定槽位，新涟漪不得刷新、覆盖或顶替旧涟漪。

平台点击撒下小冰屑并进行短而快的局部震动；多次点击低概率触发一次更大的震动和永久中央纵向裂纹。裂纹是从下向上生长的一条像素化大缝，不是多个小缺口、大洞或把平台劈成两半。这里需要分别验证“生长顺序”和“最终几何方向”，因为屏幕坐标 Y 轴向下，二者很容易被实现成相反效果。

### 2.8 Scene8 专属镜头响应

Scene8 的浮冰平台和复制远景使通用视差暴露出问题。解决方式不是修改所有场景，而是在共享 `BattleStage` 中提供可选的 Scene8 层级覆写：鼠标横向视差与攻击/对焦推近分别配置，未设置的旧场景继续使用原参数。Scene8 中湖面、接触层、平台和景观在攻击推近时保持同一世界平面，天空仍保持稳定。

### 2.9 人物极光光影

Scene1 的人物夜色调不能直接沿用。Scene8 人物需要在整体偏暗的基础上保留可读轮廓，并用克制的绿、青、紫极光受光连接角色与环境。角色光影不能独立追求鲜艳，必须与天空、倒影和平台亮度一起验收。

## 3. 主要错误模式与止损规则

1. **参考没看清就程序化重构**：先做像素结构分析，再写生成逻辑；静态未通过前禁止添加动效。
2. **用大块删除代替局部修复**：这会制造新缺口并必然返工。逐像素修复时必须保留已通过区域。
3. **只调单一参数解决系统问题**：平台悬空、极光贴图感、远近失衡都需要联动检查相关图层。
4. **连续调参但运行时完全不变**：一次明显参数尝试仍无变化后，应转向排查输入、材质、节点、事件和渲染链路。
5. **用透明度做远景**：重复资产会穿帮；优先使用不破坏 alpha 的色彩与对比映射。
6. **把“克制”理解为不可见**：粒子、倒影、涟漪和受光首先必须可读，再减少数量、频率或强度。
7. **矩形碰撞近似像素物体**：冰晶等不规则可交互对象必须基于 alpha/掩码做精确命中。
8. **忽略坐标系导致方向反复**：裂纹、下落粒子、斜向碎光都要同时断言时间顺序和最终方向。
9. **为了让探针通过而改已通过画面**：探针阈值落后于用户手调构图时，应更新验收契约，而不是移动素材。
10. **Scene8 修复影响成熟场景**：所有独有输入、视差、推近和后处理都必须显式局部化，并做 Scene1-7 回归。

## 4. 推荐的后续工作流程

1. 阅读本复盘、Scene8 当前场景说明、相关测试和探针。
2. 查询开源像素场景/官方 Godot 实现，提炼结构规律，不照抄表面形状。
3. 记录当前用户通过版本的节点 Transform、材质关键值和像素边界。
4. 每轮只处理一个可验收主题：静态形状、色彩融合、动效、输入或镜头。
5. 先用明显诊断值验证运行链路，再收敛到最终强度。
6. 使用 Godot 日志、几何断言、alpha/像素数据和不落盘探针验证；不得生成验收截图。
7. 验收后把该视觉或行为写成测试契约，保护用户手调构图与其他 Scene 的成熟行为。

## 5. 当前通过版本的保护清单

- ref48 风格的极光静态轮廓、色块比例、底部连续薄曲线及慢速全幅动效。
- 澄澈微亮极夜、克制天际绿色辉光和细小不规则星野。
- 以水为主的深蓝镜湖、岸线拓扑、极光倒影与浮冰水面接触关系。
- 现有远山、冰川、雪地、左右近景的手调 Transform 与不透明素材表现。
- Scene3 风格、缓慢下落且有极光映色的雪粒子。
- 六簇冰晶的精确点击范围及晶面火花反馈。
- 湖面无限并存涟漪、UI 点击拦截、平台小冰屑/震动和低概率永久纵向裂纹。
- Scene8 专属鼠标视差与攻击推近覆写；Scene1-7 默认行为不变。
- Scene8 人物极光光影及其与环境亮度的整体关系。
