> **性质**：本文件记录暗批最后四只（h21–h24）的设计定稿与历史落地过程。
> （h13–h20 的设计正文目前活在各 skill 的 doc-comment；本文件先承载 h21–h24，待实装时转入 skill 头注。）
>
> **⚠ 2026-07-30 规则更新**：下文“6 维 × 2”“只能各填 1”的内容仅作历史溯源，**不再是设计约束**。英雄现采用进攻 / 防守 / 经济 / 调度 / 控制五种唯一主定位，机制先行、定位后判、人数不设配额；真相源见 `design/heroes-schools.md` §3。
> **当前主定位**：h21 枭阳 = 控制 / h22 毕方 = 控制 / h23 天狗 = 控制 / h24 并封 = 经济。旧 `.tres team_role="防守"` 与 `dimension="防御"` 仍为 UI / 道具加权技术标签，迁移前保留。
>
> **设计标准（Eddy 反复定调，连否多版后固化）**：
> 1. **一眼看懂** = 改一条规则的极简机制（像暗蛇"对手不能主动切换"），⛔无上限数值、⛔无 on-hit 触发链。
> 2. **有趣（首要 · 非被动光环）** = 玩家有主动 agency、能创造 combo 时刻、有来回 yomi；纯被动 debuff 光环 = 无聊 = 砍。
> 3. **广 combo** = 反制面 / 使能面广，泛连携引擎，自身平庸、强度在搭配。
> 4. **平衡（PvP）** = 有清晰对手出口、自身脆 / 有代价。
> 5. **形态新** = 不撞全 roster 已有原语。
> 6. **方法论**：产出前先推演 ① combo 够不够广 ② 好不好玩，两关都过才定稿。

## h21 枭阳【惊蛰】· 控制 · HP4 ✅定稿

- **机制（主动技）**：占动作 · 费 **2 能** · 每局 2 次 · **须暗猴亲自出战才能放**。强制对手换人，把对手藏在后排的英雄揪到台前（**你指定换谁上**），并取消原出战英雄尚未结算的基础行动；该行动已支付的能量不返还。已完成的切换或主动技能不倒退。
- **共享原语 = 目标选择**：当前规则下你只能打对手出战；猴让你揪出该打的那个（脆皮 carry），**使能你方整条进攻线**。
- **combo（广）**：揪出脆皮 + 全队 burst 秒杀／配暗羊【罪已昭】脆弱放大集火／配房日【十方无次第】延续任意目标集火。
- **连携边界**：影狩只在娄金出战时监听切换；惊蛰发动时枭阳必须出战，因此二者不会同时触发，不列为现行 combo。
- **趣味 / yomi**：主动设局——读对手藏了谁、挑时机揪、配合集火；对手被迫纠结"还敢不敢藏脆皮"。是暗蛇的**阴阳对子**（蛇锁在原地 / 猴拽出原地）。
- **平衡**：主动技占动作 + 费能 + 每局 2 次 + 须出战（暴露 HP4 脆皮）；对手出口 = 摊平血量 / 速攻点死猴 / 换回去。**备用刹车**：揪出者只强制暴露 1 回合、下回合可自缩回（除非被锁），试玩若猴 + 蛇连环过线再启用。
- **强度评估（客观）**：中等偏强，强在"作废出战保护 + 主动精准"；最尖的角 = "你指定换谁"，用"须出战才能放"平衡，保趣味不阉割。

## h22 毕方【焚天火兆】· 控制 · HP5 ✅定稿（🔄 2026-08-08 方案3重设计）

- **玩家文案**：下一回合结束时，双方失去全部能量。
- **机制（主动技）**：占行动 · **免费** · 每局 **2 次**。发动回合不清能量；下一回合的行动、道具、死亡收益、遗物与被动产能全部完成后，双方共享能量同时归零。
- **全局期限**：火兆属于战局而非某个英雄。毕方换人、阵亡、沉默或被烛阴转变均不取消；同一时间全场只能存在一个火兆，不能叠加或刷新，结算后才可再次发动。
- **共享原语**：给双方建立公开的**资源截止线**，把下一回合所有付费动作变成“现在兑现还是作废”的共同决策，而不是单方面删能量。
- **Combo / agency**：h05 可把即将消失的能量投入强化「波」；h08 可提前买下「大防」，未挡到攻击时把价值保留到归零后；h07 可免费切换至更适合消耗能量的英雄；付费道具也获得明确的提前兑现窗口。对手同样可以花能量打「大波」「大防」或道具，也可以接受损失选择免费行动。
- **定位裁定**：主要改变双方对共享能量的使用时限，限制并重排对手选择，因此归 **控制**；延迟一回合只是时序标签，不是旧“节奏维度”。旧 `.tres team_role="进攻"` 与 `dimension="节奏"` 继续作为迁移期兼容字段，不单独改动。
- **边界 / 平衡后置**：本轮按批准方案原样实装，不凭旧胜率追加护甲、伤害或费用。当前旋钮只保留费用 0、每局 2 次、HP5；强度另开平衡阶段评估。
- **⚠ 溯源**：初版【空过存行动→双动作】、二版【2 能穿防大波】、三版【蓄力获得护甲·我方下一次攻击穿大防】均已退役。2026-08-08 起现版为全局能量截止线，技能名【焚天火兆】沿用。

## h23 天狗【天光长蚀】· 控制 · HP6 ✅定稿（2026-08-09）

- **机制（被动）**：天狗【狗】的「波」或「大波」造成伤害时，等量降低敌方能量上限（最低到3点）。
- **规则边界**：削减量读取完整伤害管线后实际落在目标生命上的伤害；被「防 / 大防」挡住、护甲或替身吸收的部分均不计算。合并进该次「波 / 大波」伤害的道具加成计入，飞镖等另行造成的道具伤害不计。一次基础攻击只结算一次上限削减，双生咒符等额外 on-hit 不重复；主动技、追击、反击和溢出伤害均不触发。
- **动态上限**：团队默认能量上限 10 点，最低可降至 3 点。上限下降时不删除当前已有能量；若当前能量高于新上限，超额部分仍可正常消费，但在降到上限以下前所有后续得能均为 0。
- **共享原语 / Combo**：把基础攻击的实际伤害同时转成长期资源压制。牛金可把下一次「波」升级为「大波」，亢金可额外支付 1 能强化「波」；这些公共攻击强化会同步扩大伤害与上限削减，而不要求队友认识天狗专属状态。
- **对手博弈**：用「防 / 大防」挡住攻击即可完全阻止削减；也可在上限尚未压低前花掉存量能量，避免后续产能被卡住。最低 3 点确保对手始终保留「大波」的完整选择。
- **定位裁定**：技能不直接保护己方，而是持续收窄对手的资源容量与蓄爆路线，因此现行主定位改判为 **控制**。旧 `.tres` 防守 / 防御字段仅暂作 UI 与道具兼容，不代表现行定位。
- **退役链路**：旧【御凶·替补顶替致死伤害】及其护甲、反击、次数和 AI 替补资产已全部移除，不与现机制并存。

## ⚠ 连带变更 · 光版鬼金 h08 重设计【不坠神言】· 防守（团队后备防御）✅定稿

- **历史起因**：原 h08【替罪·致死救援】曾与天狗旧护主同质；两者后来均已退役。2026-08-03 起鬼金回到更贴近波波攒底层动作的防御博弈。
- **机制（被动）**：鬼金【羊】的「大防」未挡到攻击时，由我方保留至下一回合结束。
- **规则边界**：“攻击”只指基础「波 / 大波」；状态属于队伍、换人后仍在、不可叠加，连续空放刷新期限。下一回合的「防 / 大防」优先，后备大防只在其未挡住时补位；穿大防攻击不会消费，但也不会延长持续时间。
- **主定位 = 防守 · 机制标签 = 延迟兑现 / 团队后备**：把一次落空的大防变成之后任一队友都可利用的防守资源，不再建立独立治疗轴。
- **共享原语 = 防御延迟兑现**：先用大防试探，再将未兑现的防御留给下一回合的换人、蓄势或进攻；实际挡住后仍触发统一成功防御钩子，可继续喂牛金等组合。
- **趣味**：鬼金玩家决定何时用 2 能购买下一回合的安全窗口；对手则决定立即攻击、暂缓一回合，还是用穿大防手段越过。
- **羊祭司意象**：祭司发出的祷言当下未被回应时仍会悬留一回合，为羊群留下短暂而明确的庇护。
- **和天狗现版对比**：鬼金保留未兑现的「大防」，直接经营己方防守资源；天狗则靠自身基础攻击压低敌方能量上限，属于资源控制。两者不再共享救援引擎。

## h24 并封【待命名】· 经济 · HP6 ✅机制定稿（2026-08-09）

- **玩家文案**：并封【猪】在队时，我方可以降低1点能量上限，使本回合所有行动少消耗1点能量（最低到3点）。
- **机制（被动）**：并封存活且未被沉默时，无论在场或未出战，均为我方本回合最终行动开放一项可选付费变体。真正结算行动费用时，先永久降低 1 点团队能量上限，再将该行动的总费用降低 1 点；一回合只有一个最终行动，因此无需另写“每回合一次”。
- **原子边界**：只有当前能量上限不少于 4 点、且行动最终费用大于 0 时可以选择；能量上限 3.5 点不能用半点上限换完整 1 点减费。取消、改选、强制回退为「攒」或 0 费行动都不扣上限；降低上限也不会删除已经持有的超额能量。
- **共享原语 / Combo**：技能改写的是全队统一的行动付费接口。龙御极的 1 点额外费用会计入本回合行动总费用，可由并封抵扣；天不葬则在并封减费后，把剩余费用改由蚩尤生命支付。普通「波」「大波」「大防」和正费用主动技都能使用，队伍会持续权衡“保留未来容量”与“提前兑现当前强拍”。
- **对手博弈**：上限损失永久且公开；若被防守读中或高费行动没有兑现，己方会带着更低的后续产能容量继续战斗。最低 3 点确保基础大波仍保留完整支付路线。
- **退役链路**：旧【吞尽八荒】的死亡产能、并封自我回血、`death_energy_bonus()` 及对应死亡扫描与事件均已移除，不与现机制并存；旧名仅在数据中临时保留，待本轮命名确认后替换。
