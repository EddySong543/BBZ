# 远征模式 — 怪物系列规范（子文档 A）

> **状态：v0.1 草稿（2026-07-05）·待 Eddy 审。** 上级文档：`design/gdd/expedition-mode.md` §3.2。
> 框架已拍板（七系列·各系列自有呈现·首发=明牌博弈系+动词考官系）；**本文所有具体数值=草稿**，待批后进原型、再经 sim/试玩校准。
> 命名注：怪物名均为占位（走大白话+奇幻调性，不占英雄技能的诗意命名空间），可整批替换。

---

## 1. 总纲（对所有系列生效的硬规）

1. **规则层锁死**：怪物的"动作"只能是六动词（波/防/攒/大波/大防/切换）的子集；数值参数（HP/伤害/能量）自由。怪物可以带**被动技能**（复用英雄被动/status 机制），但被动不得引入第七动词。
2. **明牌必须是真的**：任何向玩家展示的信息（概率表/动词清单/循环节拍）必须与实际行为严格一致——展示是承诺，不是演出。⛔ 禁止"诈表"。
3. **能量诚实原则**：怪物付不起的动作不得出现在展示信息里（见 §3 公式·可支付归一化）。
4. **怪物即遭遇**：单怪=一场遭遇的默认形态；1vN 怪群（经济体系等）后续版本再开。
5. 怪物伤害与玩家同坐**统一伤害阶梯**（普通→穿防→真伤），防挡普通、大防挡穿防及以下，与 PvP 一致。

## 2. 首发系列一：明牌博弈系 🎲（Eddy 亲定）

### 呈现

每一拍双方选招**之前**，怪物头顶显示本拍**出招概率表**（仅列非零行，含精确百分比）：

```
┌ 赌徒蟾 ────────┐
│ 波   40%       │
│ 攒   40%       │
│ 防   20%       │
└────────────────┘
```

### 规则

- 怪物每拍从当前概率表**真实采样**一个动作（有种子·可复现·可 sim 验证）。
- **表是状态的函数**：概率表可随怪物状态（HP 阈值/能量阈值/回合数）在**预设表**之间切换；切换当拍立即更新显示，并给一次明确演出（如"变脸！"飘字）。
- 表切换规则本身**不明牌**（玩家通过试探和重复遭遇学会"它半血会变凶"），但切换后的表永远诚实。
- 玩家的对策空间：算期望（40% 大波要不要防）、盯触发器（它能量快够大波了）、控制节奏（在它凶表期间龟、温表期间贪）。

### 与 PvP 的关系

博弈系练的是**期望值直觉与风险偏好**——PvP 里"他有 3 能，60% 概率憋大波"的判断，在这里被显式化为可反复练习的题目。

## 3. 首发系列二：动词考官系 📏

### 呈现

怪物头顶显示**动词清单**（它这辈子只会哪几招）；行动模式为**固定短循环（2-4 拍）**，循环内容不直接明牌，但设计上必须 2-3 个循环内可被肉眼识别（配合动作前摇演出，参照毕方【焚天火兆】蓄力预告的既有语汇）。

### 规则

- 每只考官怪=**六动词的一个子集+一个固定循环**，把一门"课"考到极致。
- 循环是确定性的（同一怪永远同一循环），玩家学会即毕业——考官系天然承担**教学关**职责，首发部署在地图浅层。
- 可挂一条被动（复用现有 status 机制）制造进阶考题。

## 4. 首发怪物表（10 只·数值全部 🔶草稿）

> 数值锚（玩家侧·冻结地基）：波=1 伤耗 1 能｜大波=2 伤穿防耗 3 能｜防免费挡普通（⚠动作层无回血·治疗只在道具层）｜大防 2 能挡穿防及以下｜攒+1 能｜被动+1 能/拍。
> 分层目标：T1 小怪 6-12 拍｜T2 精英 12-18 拍｜T3 Boss 18-25 拍（估算公式见 §5）。

## 5. 公式（Formulas）

### 5.1 可支付归一化（能量诚实原则·硬规）

设预设表各行概率 `p_i`，可支付标记 `avail_i ∈ {0,1}`（当前能量 ≥ 该动作费用）：

```
p'_i = p_i · avail_i / Σ_j (p_j · avail_j)
```

- 显示与采样都用 `p'`。示例：赌徒蟾凶表 大波60/波20/防20，能量只有 2（付不起大波 3 能）→ 实际显示 波 50/防 50。
- 边界：若 Σ=0（理论上防/攒免费恒可支付，不会发生），兜底=100% 攒。

### 5.2 表切换

```
当拍开始时：按优先级从上到下检查触发器（HP≤阈值 / 能量≥阈值 / 回合≥N），
命中第一条 → 激活对应预设表 → 立即更新显示 + 播放切换演出。
```

同拍只允许一次切换（防止连锁抖动）。

### 5.3 遭遇时长估算（分层校准用）

```
预计拍数 ≈ HP_怪 / DPS_玩家期望
DPS_玩家期望 ≈ 0.7~0.9 伤/拍（2026-07-05 校准修订：会解题玩家的拆解效率远高于原估 0.4-0.6——
  读循环白打、防-防-大波经济循环、穿防惩罚全是高效线；原草稿 HP 因此普遍上调）
```

示例：HP5 小怪 ≈ 6-7 拍 ✓ 落在 T1 目标带（6-12 拍·校准 v6 实测双管蟹中位 6）。

### 5.4 明牌真实性验证（进验收·2026-07-05 口径修订）

对每只博弈系怪跑 **≥2000 拍**采样：`|实际频率_i − 显示概率_i| ≤ 2pp`。
统计注记（校准实测教训）：500-1000 拍的采样方差本身就有 ~2pp（1σ），旧"500 拍 ≤2pp"口径统计上站不住；
且引擎实现为**从显示表直接采样**——诚实性是结构保证，本验证实为管线冒烟测试。

## 6. 边界情况（Edge Cases）

- **怪物能量不足**：付不起的行按 §5.1 归零重归一化——显示与行为永远一致，⛔ 不允许"显示大波但实际改出波"。
- **表切换与采样同拍**：先切换后采样（切换在拍首结算）。
- **玩家 buff/debuff 改变怪物数值**：只改伤害结算，不改概率表本身；若未来引入"干扰概率表"的道具，须显示修改后的表。
- **K5 缠杀藤在玩家仅 1 人时**：不生成（出现条件=队伍≥2）；若战斗中队友死亡只剩 1 人，被动照常（此时=惩罚减员，属预期）。
- **铁壳龟死锁**：它不攻击、玩家也可以不攻击——不存在强制结束；离开战斗（逃跑规则→地图子文档）或耗时自亏（危险度时钟在走），不做额外兜底。
- **Boss 阶段切换与概率表切换同拍**：阶段优先，切换后重新检查表触发器。

## 7. 调优旋钮（Tuning Knobs）

| 旋钮 | 草稿值 | 影响 |
|------|--------|------|
| 概率表显示精度 | 精确百分比 | 降为模糊档（高/中/低）可整体提高博弈系难度 |
| 表切换演出时长 | 一拍内 | 太长拖节奏、太短玩家漏看 |
| 考官循环长度 | 2-4 拍 | 越长越难识别，>4 拍不建议（记忆负担） |
| 怪物 HP 分层 | 3-5 / 8-10 / 18-20（2026-07-05 校准定稿） | 直接控制遭遇时长，联动危险度时钟压力 |
| 被动能量（怪侧） | +1/拍（与玩家同） | 降为 0 可做"饿肚子怪"变体，升高做高压怪 |
| 部署深度表 | §4 部署原则 | 教学曲线陡缓 |

## 8. 验收标准（Acceptance Criteria）

- [ ] 10 只首发怪全部可在原型中遭遇并完成战斗，六动词之外零新增动作。
- [x] 博弈系明牌真实性：≥2000 拍采样偏差 ≤2pp（§5.4·2026-07-05 口径修订；原型 v6 大样本 0.2-1.5pp 过）。
- [x] 遭遇拍数带：原型校准 v6 十怪全落带（先知玩家口径·prototypes/expedition/out_calibration.md）。
- [ ] 可支付归一化生效：怪物能量不足时显示表中不出现付不起的行。
- [ ] 表切换当拍显示即更新，且有可感知演出。
- [ ] 考官系循环确定性：同一怪同种子两次战斗行为逐拍一致。
- [ ] T1/T2/T3 实测遭遇拍数落在 6-12/12-18/18-25 带内（±20%·sim 统计）。
- [ ] K5 在 1 人队伍时不出现；K3 战斗可随时脱离（规则见地图子文档）。

## 附：monsters.json 数据模式（`assets/data/expedition/monsters.json`）

每条目键=怪物 id（`系列前缀+序号_驼峰名`，如 `b1_coinSparrow`）。字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 显示名（占位·可整批替换） |
| `series` | ✅ | 系列 id：`gamble`（博弈）/`exam`（考官）·后续系列扩这里 |
| `tier` | ✅ | 1/2/3（HP 分层与掉落档） |
| `hp` | ✅ | 基础 HP（地图侧半点制·进战 ×2 转战斗整点） |
| `kind` | ✅ | 驾驶员策略：`odds`（概率表）/`multiTable`/`cycle`/`turtleRule` 等（expedition_monster_policy 消费） |
| `tables`/`cycle` 等 | 按 kind | 策略参数（见各系列章节） |
| `art` | 可选 | **美术挂点（2026-07-07·任务 I）**：立绘资源路径（SpriteFrames `.tres` 或单图 png）。缺省=程序化像素图签占位（tier 图形×系列色）。MJ 素材到位后逐怪加此字段即替换，零改码（消费点=battle_screen `_pve_monster_frames`） |
| `deferred` | 可选 | 暂缓实现的机制备注（仅文档性·代码忽略） |
