## 1. 设计哲学

### 1.1 核心流程

```
角色形象 → 机制原语联想 → 跨维度服务能力验证 → 合格设计
```

- **角色形象先行**：每个英雄围绕主题（12 生肖）的角色形象出发
- **机制原语发散**：从形象联想 1~2 个机制原语
- **跨维度验证**：原语组合必须能为至少 2 个维度提供 combo 钩子，单一服务的设计不通过（产出可复用共享原语 = 英雄铁律）

### 1.2 反模式

- ❌ **自上而下维度填空**：先定维度标签，再找英雄填 → 模板僵化
- ❌ **单一体系服务**：一张卡只在一个维度/阵容有用 → 主题轮换即报废
- ❌ **过度复杂技能**：多技能、文字超过 3 行 → 玩家心智超载

### 1.3 参照系

| 正面参照 | 设计原则 |
|----------|----------|
| MTG Lenticular Design (Mark Rosewater) | 一张卡对不同玩家呈现不同深度 |
| Slay the Spire 通用资源原语 | 用资源比例区分套牌，不用模板区分 |
| 皇室战争 Multiple Use Case | 每张卡至少 2 种用法 |
| MTG Flexibility Theory (Reid Duke) | Power = Raw Strength × Flexibility |

| 反面参照 | 警示 |
|----------|------|
| 炉石近年"主题套牌强制绑定" | 每张卡服务单一主题，版本轮换报废 |

### 1.4 关键约束：同时回合制 ≠ 信息博弈

⚠️ **波波攒的同时回合制结算意味着没有"预测对手动作再反应"的窗口**。所有玩家盲选，双方点击确认后立即结算。

因此**禁止设计以下类型的机制**（AI 设计英雄时常见的幻觉）：

- ❌ 出"假动作"误导对手
- ❌ "试探"对手下回合动作
- ❌ 强制"暴露"对手动作
- ❌ "锁定预判"双方公开

唯一合法的"信息博弈"是**结算时的目标选择**——例如"真假分身"：攻击时必须选目标，真假位置每回合随机打乱（发生在结算阶段，非动作选择阶段）。⚠️ 此机制原由 h09 紫火承载，2026-05-21 重做后腾空，目前无英雄实装，留作未来娱乐流英雄槽。

## 2. 三层结构

```
Layer 0: 机制原语字典  (开放清单，~40 个，可随新英雄扩张)
   ↓
   每个英雄 = 1~2 个原语组合，单技能呈现 ≤ 3 行
   ↓
Layer A: 主导维度  (6 个: 进攻/防御/能量/节奏/状态/干扰)
   每个英雄 = 单一主维度标签 (minor 倾向归道具)
   ↓
Layer B: 阵容定位  (3 种角色: 核心 / 辅助 / 独立)
   每个英雄给出"在 X 体系里担 Y / 在 Z 体系里担 W"跨档说明
```

> **2026-06-26 重写**：本节原为「6 主导流派（控制/快攻/爆发/防反/轮转/娱乐）+ 子型细分」，
> 已被 `design/heroes.md` / `design/heroes-redesign.md` 落地的 **6 维度分类法**取代。
> 每个英雄 = **单一主维度标签**（"该英雄最清晰表达的一件事"·minor 倾向归道具）。

| # | 维度 | 核心动词 | 玩家幻想 | 典型 kit 信号 |
|---|------|----------|----------|---------------|

| 2 | **防御** | 挡 / 护盾 / 保命 | "你打不穿我和我的队伍" | 分级整体挡 / 护盾分发 / 致死守护 |

| 4 | **节奏** | 切换 / 额外动作 / 时间 | "我比你多动一拍" | 免费切换 / 登场触发 / 行动存储 |

**设计配额规则**：新英雄优先填空维度 / 同维度内的空白触发面；同维度已有 2 只时第 3 只起严防"换皮同质化"（必须换触发面：光环 / 阈值 / 被击反应 / 切换 / 主动技 / 月相循环等）。

> **跨维度 trait（非维度，是横向手段）**：**韧性 / 经济 / 续航**——可服务任意维度，不单列维度。经济现主挂能量维度（耀夜流晖 h01 / 北冥归墟 h13 / 祸兮福倚 h12）；**续航子轴（替补回血）由光版鬼金【牧野回春】h08 落地**（已实装·替补每回合回 0.5HP；另有道具 暖玉 / 药水 / 续命香）。
> **衔接 / 润滑（辅助 trait）**：「上一回合发生 X → 本回合得到 Y」式 delta-trigger 润滑剂。⚠️ 从严：① 触发 X 须为通用事件（掉血 / 用能 / 切换 / 出某动作；❌ 禁专属触发）② 须留操作 agency（非纯 ticker）③ 即时回报（本 / 下回合见效）。**全池 1-2 个封顶**（做多成 ticker 聚堆 = 新同质化）。属 Layer B 辅助 + 跨维度手段，**非新维度 / 非新原语**。
> **机制空白追踪**：附盾给队友（已落地 = 牛金山岳为屏）/ 中毒引爆（翼火灵蚀噬魂）/ 剑气印记（昴日金乌淬锋）/ 续航子轴 替补回血（已落地 = 鬼金牧野回春 h08）/ 死亡产能（已落地 = 暗猪 h24 吞尽八荒）等均已开张；仍空 = 伤害转移、HP 链接、娱乐维度随机目标（原 h09 化身已迁出腾空）。详见 §5 原语字典各维度。

### 3.2 平衡：维度不是克制 RPS

旧「6 流派克制三角」属已废的流派框架。**维度层不设显式克制 RPS**——波波攒的博弈在**每回合 攻 / 防 / 攒 的盲选 yomi（动作层）**，不在维度层。维度的平衡靠三根支柱：

- **二元整体挡 + 穿透三档**：防 / 大防 vs 穿防 / 穿大防 / 真伤（见 `build-design-framework.md` §4.6）——进攻维度想打穿防御维度靠破防降级 / 受授权的穿大防 payoff / 资源剥夺，不靠"更大的数字淹没"。
- **系内加算 · 系间乘算**（连携主定理·见 `build-design-framework.md` §6）：同维度内线性叠加、跨维度乘算放大 → 反"总钥匙"固化，鼓励跨维度 combo。
- **单主标签 + 挤槽警报**：同维度英雄强制差异化触发面，避免"感觉一样"。

## 4. Layer B: 阵容定位

> **状态注记（2026-07-04 复核·Eddy 批 A 方案）**：本节 = BP 搭配思考的**设计参考层**，
> 无实装标签——英雄数据上落地的分类只有 6 维度（`HeroData.dimension`·T2 加权抽卡在用）；
> 实装组队逻辑 = `DraftAI`（HP 派生三角色：坦克 HP≥6 / 灵活 HP5 / 脆皮 HP≤4·HP 曲线组队）。
> 将来阵容协同立项时再决定是否按维度重写本节。

| 定位 | 队伍中的功能 | 经典 kit 信号 |
|------|--------------|---------------|
| **核心** Core | 后期主输出，需要队友铺路 | 大量加伤 / 蓄能爆发 / 后期 Carry |
| **辅助** Support | 给队友提供资源/掩护 | 加速能量 / 切换附盾 / HP→资源 |
| **独立** Solo | 自给自足，不依赖阵容协同 | 反伤 / 受伤获能 / 高 HP 持久 |

### 阵容档案（不是英雄标签）

**阵容档案 = BP 阶段的搭配模式**，描述 3 个英雄如何组合：

- **单核体系**：1 Core + 2 Support（辅助为核心铺路）
- **双核体系**：2 Core + 1 Solo（双输出，依赖能量分配）
- **轮转体系**：3 个围绕切换打的英雄（节奏维度向）
- **独立体系**：3 Solo（每个英雄独立作战）

### 跨档使用提示

设计新英雄时考虑"在 X 档案里担 Y / 在 Z 档案里担 W"——同一英雄在不同阵容担不同角色才符合 Lenticular Design。（设计提示·不要求逐英雄成文；现状仅 redesign.md 部分英雄设计依据里有零星"不单核"标注。）

## 5. Layer 0: 机制原语字典

### 5.1 维度 1：资源操作

| 原语 | 含义 |
|------|------|
| 能量加速 | 增加能量获取速率 |
| 能量转换 | 用 X 资源换能量 |
| 能量盗取 | 直接扣对手能量 |
| 能量预存 | 存能量到下个英雄/下回合 |
| 能量冻结 | 让对手能量本回合不可消费（🈳 2026-07-06 退回空槽：烛阴曾落地一版·大轮 29.5% 弃——锁钱锁不住免费「防」·教训=否定型干扰必须动到免费动作才有账） |
| 能量上限调整 | 临时改 MAX_ENERGY |
| HP 回复 | 恢复己方 HP |
| HP 转移 | 把 HP 给队友 / 抽队友 HP |
| 生命链接 | 造成伤害时回血 |
| 过载 / 透支 | 本回合 +X 能、下回合 -X 能（先享后还，非延迟回报）|

### 5.2 维度 2：动作改造

| 原语 | 含义 |
|------|------|
| 动作替换 | 选 X 实际执行 Y |
| 动作升级 | 波→大波 / 防→大防 |
| 动作降级 | 强制对手大波→波 |
| 动作复制 | 出的动作执行 2 次 |
| 动作折扣 | 某动作 -1 能量 |
| 动作禁用 | 让对手某动作下回合不可选（烛阴 h17 v4 曾落地·2026-07-09 批⑤转强制动作后此槽复空） |
| 强制动作 | 强制对手出特定动作（✅已落地=烛阴 h17【阖眸成夜】v5·2026-07-09：锁"其施放拍用过的动作"=下拍只能重复它·付不起兜底攒） |
| 免费切换 | 不消耗切换成本 |

### 5.3 维度 3：结算改造

| 原语 | 含义 |
|------|------|
| 加伤放大 | 普攻基于条件 +X |
| 伤害免疫 | 单回合无伤 |
| 伤害减免 | 受伤 -X（非全免）|
| 伤害反弹 | 受伤反伤攻击者 |
| 伤害延迟 | 本回合伤害下回合结算 |
| 伤害转移 | 把受伤转给队友 / 对手其他英雄 |
| 伤害固定 | 不论原数值固定为 X |
| 首次保护 | 本局第一次致死伤害不结算 |
| 致死阈值改写 | HP=0 不死，HP=负 X 才死 |
| 易伤 / 破绽 | 标记对手，其下次/本回合受攻击 +X 伤（放大队友输出）|
| 资源倾泻伤害 | 消耗全部/X 能量 → 造等量伤害|
| 自伤换减免 | 主动扣自身 HP → 换伤害减免（预付式防御 / 卖血流闭环）⚠️ 减免非免疫·需 cap |

### 5.4 维度 4：触发器

| 原语 | 含义 |
|------|------|
| 登场触发 | 切换登场瞬间 |
| 离场触发 | 切换离场瞬间 |
| 死亡触发 | 自身死亡瞬间 |
| 死亡叠加 | 队友死亡获永久增益 |
| 回合触发 | 每 N 回合 |
| 临死触发 | HP=1 时被动激活 |
| 击杀触发 | 击杀对方英雄时 |
| 能量耗尽触发 | 能量=0 时 |
| 阈值切换 | HP 低于 X% 形态改变 |
| 超杀 / 溢杀 | 击杀且有溢出 → 溢出转移给下个被迫登场的敌方英雄（穿透击杀）|

### 5.5 维度 5：状态附加

| 原语 | 含义 |
|------|------|
| 附盾 | 吸收 X 伤害 |
| 中毒 / 持续伤害 | 每回合受 X 伤害 N 回合 |
| 燃烧 | 不能回血 / 加伤 |
| 沉默 / 净化 | 去除目标 buff 或 debuff |
| 不可选目标 | 隐身，本回合不能被攻击 |
| 嘲讽 | 强制对手攻击自己 |

### 5.6 维度 6：信息博弈（仅 1 项）

| 原语 | 含义 |
|------|------|
| 假目标 / 分身 | 攻击需选目标且真假随机（结算阶段）|

⚠️ 见 §1.4 关于同时回合制的约束。**此维度只有这一条**，所有"假动作 / 试探 / 暴露 / 锁定"机制都是设计幻觉。

### 5.7 维度 7：团队协同

| 原语 | 含义 |
|------|------|
| 队友登场赠礼 | 队友登场时给当前英雄 buff |
| 死亡赠礼 | 自身死亡时给替补加 buff |
| 召唤替补 | 召唤额外作战单位 |
| 链式联动 | 与同维度/同关键词队友共振 |

### 5.8 维度 8：连锁 / 节奏

| 原语 | 含义 |
|------|------|
| 连击奖励 | 连续 N 回合同动作奖励（**已实装·反向**：h04 房日=敌方连续同动作 → 我方 +0.5 能/回合·2026-07-04 重做首用） |
| 变化奖励 | 每回合换动作时奖励 |
| 同步奖励 | 与对手出同动作奖励 |
| 错位奖励 | 与对手出不同动作奖励 |
| 镜像 | 复制对手本回合动作（结算阶段）|

### 5.9 维度 9：概率 / 随机

| 原语 | 含义 |
|------|------|
| 动作随机替换 | 自己动作随机变 |
| 概率减伤 | 50% 概率免伤 |
| 概率翻倍 | 50% 概率伤害 ×2 |
| 抽卡式效果 | 从效果池中随机一个 |
| HP 随机 | 上场时 HP 随机化 |

### 5.10 字典开放原则

⚠️ **以上 ~40 个原语是 v2 起点，不是上限**。

每个新英雄设计时若发现现有原语都无法描述其角色形象 → **新增原语**，字典扩张，本文档同步更新。

### 5.11 v2.5 批准新增原语（2026-05-21，关键词扫描后 Eddy 拍板）

扫炉石 / 万智牌 / 游戏王 / 杀戮尖塔 / 符文之地 → 用波波攒硬过滤（无手牌牌库随从场召唤 / 同时结算无反应窗口 / 禁偷看信息 §1.4 / 快节奏 / 小 HP / 3 英雄+切换）筛出，greenlight 进设计池：

**新增进字典**：
- **过载 / 透支**（§5.1）：本回合 +X 能、下回合 -X 能（先享后还，非延迟回报）
- **易伤 / 破绽**（§5.3）：标记对手，其受到的下次/本回合攻击 +X 伤（放大队友输出 = 真跨英雄 combo）
- **变身 / 形态切换**（新维度）：消耗高能量切换到第二形态（数值/技能整套改变）。门槛别太高防延迟回报；形态 2 宜换打法非仅加数值
- **超杀 / 溢杀**（§5.4 触发）：击杀对手且有溢出伤害 → 溢出转移给被迫登场的下个敌方英雄（穿透击杀，滚雪球）。⭐ 留给**进攻 slot**。

**已在字典、本批一并 greenlight 优先做**：中毒/持续伤害(§5.5) · 附盾给队友(§5.5) · 能量预存(§5.1) · 召唤替补(§5.7) · 节奏奖励 变化/同步/错位(§5.8)

**两个特殊注解**：
- **嘲讽 reframe（Eddy）**：原字典"强制对手攻击自己"在 1v1 单出战结构下不成立 → 改为**轮转体系英雄**机制："即使切换下场，仍能为出战队友代受/分摊伤害"（伤害转移/redirect 方向）。
- **召唤**：后期可**体系化**（如专门强化召唤物的支援英雄），非单点设计。

> **方向方针**：暂停防反 / 纯加伤；优先 **A 团队支援** · **B 控制铺垫** · **C 节奏博弈**（最"波波攒原生"、几乎全空）。

## 6. 设计纪律（写卡时强制遵守）

1. **单技能精简**：一个英雄只设计 1 个技能，效果描述 ≤ 3 行
2. **原语数量**：技能由 1~2 个原语合成，不允许 3+ 原语堆砌
3. **跨维度钩子**：每个原语组合必须能为至少 2 个维度提供 combo 价值（产出可复用共享原语）
4. **角色形象先行**：从主题角色形象出发，不要从维度模板出发
5. **同时回合制约束**：禁止"预测对手动作再反应"类机制（见 §1.4）
6. **被动作用域明示**：被动技能描述必须包含主语（"自己" / "全队" / "当前出战英雄"等），杜绝"所有攻击"类歧义。默认走**单英雄层次**（仅持有者生效）；**团队层次**仅在以下三条件**同时满足**时使用——触发条件严苛（如自身死亡而非受伤）+ buff 持续短（限 N 次或 N 回合，不允许永久残留）+ 与英雄形象强绑定（非模板化）。理由：避免"开局送英雄吃 1 波激活 → 切下场永久龟 → 全队碾压"的献祭式优势。
7. **能量池视角**：能量是双方各自的**全队共享池**（`battle_core energy[2]`），非 hero-level。禁止设计"死亡传递能量"/"独享能量"/"队友死时分能量"等幻觉机制（这些原语本就跨英雄共享，无需"传递"）。

### 8.2 节奏目标

- **标准局长**：90 秒（~11 回合）
- **最长局长**：180 秒（~22 回合）
- **每回合所需平均伤害进入**：~1.88（HP=5 × 3 英雄 / 8 打击回合）

### 8.3 BP 机制（创新设计）

**联机对战模式**：
- 双方**同时盲 Ban** 3 名英雄（互不可见，撞车时该位置视为无效，有效 Ban 总数 ≤ 6）
- 双方**同时盲 Pick** 3 名出战英雄（**允许重复** — 双方可选同一英雄构成镜像对决）
- 流程：**2 步**（Ban 1 步 + Pick 1 步）
- 估算时长：20-40 秒

**本地测试模式（临时，仅个人测试用）**：
- 跳过 Ban 阶段
- 仅保留 Pick：玩家直接选择两边阵容
- 估算时长：10-20 秒
- ⚠️ 联机功能落地后撤除本地模式
