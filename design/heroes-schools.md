# 波波攒之王 — 英雄设计框架（主定位 / 原语 / 阵容定位）

> **状态**：2026-07-30 重写。英雄设计正式采用五种唯一主定位：**进攻 / 防守 / 经济 / 调度 / 控制**；旧「进攻 / 防御 / 能量 / 节奏 / 状态 / 干扰」六维不再承担英雄定位或人数配额。
> **作用**：所有现有及未来英雄设计的指导框架，也是主定位裁定的单一真相源。
> **关联**：`design/hero-design-lessons.md`（协作经验与提交前门禁）、`design/heroes.md`（玩家可见技能文案快照）、`design/heroes-redesign.md`（逐只设计理据）、`design/gdd/game-concept.md`（核心机制）。
> **兼容边界**：`HeroData.dimension` 暂时仍是道具抽取加权使用的旧技术标签，`HeroData.team_role` 暂时仍是 BP 框色使用的旧三分类。两者均不得再指导英雄机制设计；待 24 名英雄重设计稳定后统一迁移，禁止逐只随手改字段造成英雄、道具、UI 与测试错位。

## 1. 设计哲学

### 1.1 核心流程

```
角色幻想 → 基础交互联想 → 单技能机制 → combo / yomi 验证 → 主定位归类
```

- **角色形象先行**：从生肖特征、角色职能、战斗动画、漫画或影视动作中发散，不从定位配额倒推技能。
- **基础交互落地**：机制优先改写「波 / 攒 / 防 / 大波 / 大防 / 切换 / 行动」等共通规则；英雄是底层改装件，不另起一套小游戏。
- **单技能呈现**：每名英雄只有一个清晰 identity；由 1~2 个原语构成，玩家读一次便知道何时想用。
- **深度来自选择轴**：优先用一句话开放一个能被反复利用的新选择（例如“攻击谁”），让阵容与局势自然放大它；不靠追加效果、例外和结算步骤制造深度。
- **宽连携验证**：技能须产出或消费全队可复用的共享原语，能与多名英雄和道具自然相接，而不是只和指定搭档工作。
- **双向博弈验证**：使用者要选择时机，对手要有可理解的反制或重排选择；纯后台收租和自动白值不通过。
- **主定位后置**：机制先成立，再按它主要改变的基础决策归类。不得为了补某类人数而扭曲设计。
- **强度后置**：重设计阶段不因当前胜率或数值强弱否决机制，也不为平衡主动给已批准机制加尾巴；数值测试在机制实装后单独进行。

### 1.2 反模式

- ❌ **自上而下定位填空**：先定职位或人数，再找英雄填 → 模板僵化。
- ❌ **专属关键词系统**：为一名英雄新造计数物、地形或规则名，却不能被全池复用。
- ❌ **单一指定搭档**：只有和某一名英雄同队才成立，离开组合便近似白板。
- ❌ **后台自动收租**：玩家不必改变任何决定，技能每回合自己发资源或数值。
- ❌ **奖励直译机制**：兔快就直接“先手”、牛硬就直接“加盾”、鼠会囤就直接“加能”，只有结论没有新的选择。
- ❌ **动作对照表式 if–else**：整项技能只是“敌方出 X → 我方自动变 Y”，玩家既不能主动铺设，也不能组织一条进退或兑现路线。条件可以作为触发门，但不能代替技能结构本身。
- ❌ **微弱时序修补**：只把既有动作从结算前挪到结算后，若没有实质改变行动、阵位、资源或 combo 接口，影响不足以成为英雄 identity。
- ❌ **过度复杂技能**：多技能、3 个以上原语或依赖长篇例外说明。
- ❌ **双行小字**：核心机制若不能用一行玩家文案说清，或同时要求选择目标、退路并理解特殊结算顺序，即视为过度设计。每项技能只允许一个明显的规则变化。

### 1.3 参照系

| 正面参照 | 设计原则 |
|----------|----------|
| MTG Lenticular Design (Mark Rosewater) | 一张卡对不同玩家呈现不同深度 |
| Slay the Spire 通用资源原语 | 用资源比例区分套牌，不用模板区分 |
| 皇室战争 Multiple Use Case | 每张卡至少 2 种用法 |
| MTG Flexibility Theory (Reid Duke) | Power = Raw Strength × Flexibility |

| 反面参照 | 警示 |
|----------|------|
| 炉石近年"主题套牌强制绑定" | 每张卡服务单一主题，版本轮换报废 |

### 1.4 关键约束：同时回合制 ≠ 信息博弈

⚠️ **波波攒的同时回合制结算意味着没有"预测对手动作再反应"的窗口**。所有玩家盲选，双方点击确认后立即结算。

因此**禁止设计以下类型的机制**（AI 设计英雄时常见的幻觉）：

- ❌ 出"假动作"误导对手
- ❌ "试探"对手下回合动作
- ❌ 强制"暴露"对手动作
- ❌ "锁定预判"双方公开

唯一合法的"信息博弈"是**结算时的目标选择**——例如"真假分身"：攻击时必须选目标，真假位置每回合随机打乱（发生在结算阶段，非动作选择阶段）。⚠️ 此机制原由 h09 紫火承载，2026-05-21 重做后腾空，目前无英雄实装，留作未来娱乐流英雄槽。

### 1.5 玩家文案的基础战斗术语

为保证英雄技能保持一句短文案，2026-07-31 起统一使用以下含义：

- **攻击**：仅指英雄使用「波」或「大波」；附在该次攻击上的附加效果随攻击结算。
- **成功防御**：仅指「防」或「大防」完整挡下一次攻击。
- **伤害**：生命或护甲减少的结果，来源可以是攻击、独立主动技能、独立道具、反击或持续效果。
- 独立主动技能与独立道具伤害不属于“攻击”。完整目标、时序与特殊结算边界写入设计说明和测试，不重复塞入英雄小字。

玩家可见写法的单一真相源见 `design/copy-style-guide.md`。尚未重设计的英雄随逐英雄流程逐项迁移，不通过纯文案改写改变旧机制。

## 2. 设计结构

```
Layer 0: 波波攒基础交互
   波 / 攒 / 防 / 大波 / 大防 / 切换 / 行动 / 出战位 / 共享能量 / HP
   ↓
Layer 1: 英雄唯一技能
   每个英雄 = 1~2 个受控原语组合，单技能呈现 ≤ 3 行
   ↓
Layer 2: 唯一主定位
   进攻 / 防守 / 经济 / 调度 / 控制
   ↓
Layer 3: 内部机制标签与阵容档案
   触发面 / 产出物 / 消费物 / 核心-辅助-独立（均非玩家职位）
```

每名英雄对玩家只显示一个主定位。设计内部可记录 1~2 个机制标签，例如命中、挡招、切换、动作复制、能量变化、死亡触发；标签用于查重、道具联动与测试覆盖，不设人数配额，也不创造玩家必须背诵的新关键词。

## 3. Layer 2：五种唯一主定位

五类共同回答同一个问题：**这名英雄主要改变哪一种基础战斗决策的价值？**

| 主定位 | 对应的底层对象 | 核心作用 | 典型信号 |
|---|---|---|---|
| **进攻** | 我方「波 / 大波」与敌方 HP | 提高攻击兑现或制造击杀线 | 增伤、穿防、命中追压、易伤、攻击型状态 |
| **防守** | 我方「防 / 大防」与我方 HP | 避免、修复或转移损失 | 挡招收益、治疗、护甲、承伤、致死救援 |
| **经济** | 我方「攒」与共享能量池 | 增加或放大可支配能量 | 产能、得能放大、受击转能、死亡产能 |
| **调度** | 我方行动槽、动作顺序与主动切换 | 增加或重排己方行动和部署选择 | 免费切换、额外行动、动作转换、行动接力 |
| **控制** | 敌方选招、能量、行动与位置 | 减少、迫使或打乱敌方选择 | 碎能、涨价、锁招、禁切换、强制换人 |

### 3.1 裁定规则

1. **先机制、后归类**：技能通过角色幻想、底层交互、combo 与 yomi 检查后，才填写主定位。
2. **看主要改变的决定，不看奖励长相**：造成伤害不必然是进攻，获得能量不必然是经济；先判断技能围绕什么动作循环运转。
3. **去掉 rider 再判断**：移除附带的小伤害、小盾或小回能，剩下的部分就是 identity。
4. **看玩家主动围绕什么出牌**：强化成功挡招的技能归防守；以免费换人组织整队的技能归调度；强迫敌人换位的技能归控制。
5. **一名英雄只有一个主定位**：若两边同样重要，通常表示技能过载，应砍掉次要效果，而不是加第二职位。

边界判例：

- h02 的结果会强化下一次攻击，但发动机是成功挡下攻击，因此归 **防守**。
- h07 登场带伤害，但免费切换决定其所有用法，因此归 **调度**。
- h16 追击附带伤害，但发动机是“替补登场并改写我方站位”；首次触发开放，重复触发依赖切换组织，因此归 **调度**。
- h21 强拉能帮助击杀，但技能本体改变敌方阵位，因此归 **控制**。
- h22 预告下一回合的全局能量截止线，主要重排双方的资源使用时限，因此归 **控制**。

以下概念不再作为主定位：

- **节奏**：立即、延迟、连续、蓄力等时间形态，是机制标签。
- **状态**：毒、剑意、易伤等效果载体，最终仍服务于五种主定位之一。
- **combo / 连携**：所有英雄必须达到的连通度指标，不是职位。
- **支援 / 核心 / 独立**：描述英雄在某套阵容中的关系，可随阵容改变，不是固定职位。
- **反击 / 爆发 / 续航 / 先手**：触发或表现方式，不是职位。

### 3.3 覆盖与防同质化

- **不设平均配额**：24 人无需平均分给五类，也不得用人数反推技能。
- **覆盖软警报**：某类 0 人 = 真缺口；1 人 = 体系偏薄；2 人以上 = 已成立。警报只提示继续探索，不授权做填空式英雄。
- **同质化按机制查，不按人数查**：比较「主要基础交互 + 触发面 + 产出 / 消费物」。三者高度重合才是撞车。
- **同定位可以大量共存**：只要玩家的出牌理由不同，9 名进攻英雄也可以比 4 名硬凑出的“节奏英雄”更健康。
- **h04 裁定记录**：获批机制新增“攻击谁”的进攻选择轴，因此归入进攻；没有为了把调度从 2 人补到 3 人而扭曲机制。

### 3.4 旧字段兼容边界

| 层 | 当前字段 / 系统 | 现阶段含义 |
|---|---|---|
| 新设计真相 | 文档中的「主定位」 | 唯一用于设计、复盘和未来玩家展示的五分类 |
| 旧技术标签 | `HeroData.dimension` | 六维字符串；T2 道具抽取加权仍在读取，迁移前保留 |
| 旧 UI 分类 | `HeroData.team_role` | 经济 / 进攻 / 防守三色框；迁移前保留 |
| 内部标签 | 尚未落字段 | 1~2 个受控机制标签；24 人重设计稳定后再统一建模 |

禁止只改某个英雄的 `dimension` 或 `team_role` 来“跟上新文档”。最终迁移必须同时处理英雄数据、道具标签、抽取加权、BP 框色和对应测试。

## 4. 阵容档案（非英雄主定位）

> **状态注记（2026-07-30 复核）**：本节只描述某名英雄在具体阵容里承担的关系，可随搭配变化；它既不是五种主定位，也不是当前实装字段。实装组队逻辑仍由 `DraftAI` 按 HP 曲线处理。

| 定位 | 队伍中的功能 | 经典 kit 信号 |
|------|--------------|---------------|
| **核心** Core | 后期主输出，需要队友铺路 | 大量加伤 / 蓄能爆发 / 后期 Carry |
| **辅助** Support | 给队友提供资源/掩护 | 加速能量 / 切换附盾 / HP→资源 |
| **独立** Solo | 自给自足，不依赖阵容协同 | 反伤 / 受伤获能 / 高 HP 持久 |

### 阵容档案（不是英雄标签）

**阵容档案 = BP 阶段的搭配模式**，描述 3 个英雄如何组合：

- **单核体系**：1 Core + 2 Support（辅助为核心铺路）
- **双核体系**：2 Core + 1 Solo（双输出，依赖能量分配）
- **轮转体系**：3 个围绕切换打的英雄（节奏维度向）
- **独立体系**：3 Solo（每个英雄独立作战）

### 跨档使用提示

设计新英雄时考虑"在 X 档案里担 Y / 在 Z 档案里担 W"——同一英雄在不同阵容担不同角色才符合 Lenticular Design。（设计提示·不要求逐英雄成文；现状仅 redesign.md 部分英雄设计依据里有零星"不单核"标注。）

## 5. Layer 0: 机制原语字典

### 5.1 原语域 1：资源操作

| 原语 | 含义 |
|------|------|
| 能量加速 | 增加能量获取速率 |
| 能量转换 | 用 X 资源换能量 |
| 能量盗取 | 直接扣对手能量 |
| 能量预存 | 存能量到下个英雄/下回合 |
| 能量冻结 | 让对手能量本回合不可消费（🈳 2026-07-06 退回空槽：烛阴曾落地一版·大轮 29.5% 弃——锁钱锁不住免费「防」·教训=否定型干扰必须动到免费动作才有账） |
| 能量上限调整 | 改变团队能量容量；h23 按基础攻击实际伤害永久压低敌方上限（最低 3） |
| HP 回复 | 恢复己方 HP |
| HP 转移 | 把 HP 给队友 / 抽队友 HP |
| 生命链接 | 造成伤害时回血 |
| 过载 / 透支 | 本回合 +X 能、下回合 -X 能（先享后还，非延迟回报）|

### 5.2 原语域 2：动作改造

| 原语 | 含义 |
|------|------|
| 动作替换 | 选 X 实际执行 Y |
| 动作升级 | 波→大波 / 防→大防 |
| 动作降级 | 强制对手大波→波 |
| 动作复制 | 出的动作执行 2 次 |
| 动作折扣 | 某动作 -1 能量 |
| 动作禁用 | 让对手某动作下回合不可选（烛阴 h17 v4 曾落地·2026-07-09 批⑤转强制动作后此槽复空） |
| 强制动作 | 强制对手出特定动作（🈳 2026-08-06 烛阴重设计后退回空槽；旧锁招基建保留） |
| 英雄转变 | 将己方英雄替换为另一英雄并继承其本体状态（✅已落地=烛阴 h17：转变为敌方当前出战英雄；不复制团队资源） |
| 免费切换 | 不消耗切换成本 |

### 5.3 原语域 3：结算改造

| 原语 | 含义 |
|------|------|
| 加伤放大 | 普攻基于条件 +X |
| 伤害免疫 | 单回合无伤 |
| 伤害减免 | 受伤 -X（非全免）|
| 伤害反弹 | 受伤反伤攻击者 |
| 伤害延迟 | 本回合伤害下回合结算 |
| 伤害转移 | 把受伤转给队友 / 对手其他英雄 |
| 伤害固定 | 不论原数值固定为 X |
| 首次保护 | 本局第一次致死伤害不结算 |
| 致死阈值改写 | HP=0 不死，HP=负 X 才死 |
| 易伤 | 标记对手，其下次/本回合受攻击 +X 伤（放大队友输出）|
| 资源倾泻伤害 | 消耗全部/X 能量 → 造等量伤害|
| 自伤换减免 | 主动扣自身 HP → 换伤害减免（预付式防御 / 卖血流闭环）⚠️ 减免非免疫·需 cap |

### 5.4 原语域 4：触发器

| 原语 | 含义 |
|------|------|
| 登场触发 | 切换登场瞬间 |
| 离场触发 | 切换离场瞬间 |
| 死亡触发 | 自身死亡瞬间 |
| 死亡叠加 | 队友死亡获永久增益 |
| 回合触发 | 每 N 回合 |
| 临死触发 | HP=1 时被动激活 |
| 击杀触发 | 击杀对方英雄时 |
| 能量耗尽触发 | 能量=0 时 |
| 阈值切换 | HP 低于 X% 形态改变 |
| 超杀 / 溢杀 | 击杀且有溢出 → 溢出转移给下个被迫登场的敌方英雄（穿透击杀）|

### 5.5 原语域 5：状态附加

| 原语 | 含义 |
|------|------|
| 附盾 | 吸收 X 伤害 |
| 中毒 / 持续伤害 | 每回合受 X 伤害 N 回合 |
| 燃烧 | 不能回血 / 加伤 |

### 5.11 v2.5 批准新增原语（2026-05-21，关键词扫描后 Eddy 拍板）

**新增进字典**：
- **过载 / 透支**（§5.1）：本回合 +X 能、下回合 -X 能（先享后还，非延迟回报）
- **易伤**（§5.3）：标记对手，其受到的下次/本回合攻击 +X 伤（放大队友输出 = 真跨英雄 combo）
- **变身 / 形态切换**（新维度）：消耗高能量切换到第二形态（数值/技能整套改变）。门槛别太高防延迟回报；形态 2 宜换打法非仅加数值
- **超杀 / 溢杀**（§5.4 触发）：击杀对手且有溢出伤害 → 溢出转移给被迫登场的下个敌方英雄（穿透击杀，滚雪球）。⭐ 留给**进攻 slot**。

## 6. 设计纪律（写卡时强制遵守）

1. **单技能精简**：一个英雄只设计 1 个技能，效果描述 ≤ 3 行
2. **原语数量**：技能由 1~2 个原语合成，不允许 3+ 原语堆砌
3. **宽连携钩子**：每个原语组合必须能为多名英雄或道具提供 combo 价值（产出 / 消费可复用共享原语）
4. **角色形象先行**：从主题角色形象出发，不要从维度模板出发
5. **同时回合制约束**：禁止"预测对手动作再反应"类机制（见 §1.4）
6. **被动作用域明示**：被动技能描述必须包含主语（"自己" / "全队" / "当前出战英雄"等），杜绝"所有攻击"类歧义。默认走**单英雄层次**（仅持有者生效）；**团队层次**仅在以下三条件**同时满足**时使用——触发条件严苛（如自身死亡而非受伤）+ buff 持续短（限 N 次或 N 回合，不允许永久残留）+ 与英雄形象强绑定（非模板化）。理由：避免"开局送英雄吃 1 波激活 → 切下场永久龟 → 全队碾压"的献祭式优势。
7. **能量池视角**：能量是双方各自的**全队共享池**（`battle_core energy[2]`），非 hero-level。禁止设计"死亡传递能量"/"独享能量"/"队友死时分能量"等幻觉机制（这些原语本就跨英雄共享，无需"传递"）。
8. **底层交互优先**：优先改写波 / 攒 / 防 / 大波 / 大防 / 切换 / 行动；新机制若离开这些按钮便无法解释，通常过于上层。
9. **少造关键词**：优先复用现有动作、状态和事件；只服务单英雄的专属计数系统默认不通过。
10. **拒绝后台收租**：技能必须改变至少一方的出牌选择；“满足自动条件后定期加数值”不能单独成为 identity。
11. **主定位后置**：通过设计检查后再归入进攻 / 防守 / 经济 / 调度 / 控制，不按人数补位。
12. **强度不参与本轮机制裁定**：重设计按体验与连携定机制；获批后原样实装，数值强弱留到独立平衡阶段。

## 7. 与后续步骤的衔接

逐英雄工作流（2026-07-30 起）：

1. 回顾角色幻想、当前技能及与全 roster 的撞车点。
2. 只联想机制，不命名；从战斗动作与波波攒底层交互提出多个方向。
3. 检查每案的玩家决策、对手反制、共享 combo 与文字复杂度。
4. Eddy 选择并修改机制；此阶段不以强度为筛选条件。
5. 机制通过后再设计技能名；每轮 10 个，按推荐度排序，并解释命名依据。
6. Eddy 选定名字后，扫描英雄数据、技能脚本、战斗核心、UI 文案、设计文档与测试，一次性实装。
7. 运行与改动相称的测试；平衡分析只作后续独立工作，不擅自改动获批机制。
8. 根据最终机制填写唯一主定位与 1~2 个内部机制标签；不按人数配额回填。

讨论阶段不改英雄实现；只有机制与命名均获批准后进入实装。

### 8.2 节奏目标

- **标准局长**：90 秒（~11 回合）
- **最长局长**：180 秒（~22 回合）
- **每回合所需平均伤害进入**：~1.88（HP=5 × 3 英雄 / 8 打击回合）

### 8.3 BP 机制（创新设计）

**联机对战模式**：
- 双方**同时盲 Ban** 3 名英雄（互不可见，撞车时该位置视为无效，有效 Ban 总数 ≤ 6）
- 双方**同时盲 Pick** 3 名出战英雄（**允许重复** — 双方可选同一英雄构成镜像对决）
- 流程：**2 步**（Ban 1 步 + Pick 1 步）
- 估算时长：20-40 秒

**本地测试模式（临时，仅个人测试用）**：
- 跳过 Ban 阶段
- 仅保留 Pick：玩家直接选择两边阵容
- 估算时长：10-20 秒
- ⚠️ 联机功能落地后撤除本地模式
