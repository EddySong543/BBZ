# 原型：对波加载界面（wave_clash_title）

## 假设（Hypothesis）
点开游戏的**加载/进入界面**——左蓝、右红两道冲击波在屏幕中央**对撞僵持**（持续动态），
玩家**点击屏幕**后**随机一方盖过另一方**，再进入游戏主界面。
验证：能否仅用一个 canvas_item shader（无贴图）实现这种"对波"质感与"盖过"收束，且观感足够带感。

## 如何运行
- **Godot 编辑器**：打开 `wave_clash_title.tscn`，按 `F6`（运行当前场景）。
  - 加载约 1.2s → 出现「点击屏幕进入游戏」→ 鼠标点击 / 任意键 → 随机一方盖过 → 控制台打印进入（**不切场景**）。
- **命令行运行**：
  ```
  godot --path <PROJ> res://prototypes/wave_clash_title/wave_clash_title.tscn
  ```
- **重新截图**（非 headless，会短暂弹窗；headless 不跑 shader）：
  ```
  godot --path <PROJ> -s res://prototypes/wave_clash_title/_screenshot.gd
  ```
  输出 `shot_1_clash.png` / `shot_2_push.png` / `shot_3_flood.png`。

## 像素风管线（网格吸附法 · 当前方案）
**放弃"低分辨率缓冲再放大"**——上采样必然引入平滑，把方块糊成渐变（这是一直"看不出像素"的真因）。
改为在 shader 里直接做网格：
- 背景 `Wave` 是**原生分辨率** ColorRect，shader 把屏幕切成 `cells_x`(默认 32) 列正方形格
  （格高 = `cells_x/aspect`）。每片元先 `cuv = (floor(UV*grid)+0.5)/grid` **吸附到格心**，
  整格只用该中心点算一次颜色、填纯色。**同格所有片元颜色完全相同 → 一格=一块纯色**。
- **不经任何上采样**，shader 直接在原生分辨率输出方块 → 不存在放大平滑问题。
- 格内**无渐变 / 无抗锯齿 / 无抖动**；色阶量化（`color_levels`，无 dither）只是限色让纯块更干净。
- **调粗细 = 改 `cells_x`**（数值越小格越大越粗；24=粗 / 32=当前 / 更大=更细）。
- **文字层**：原生高分辨率 Label（不走网格），经项目 **FontManager**（Ark Pixel 像素字体，**关抗锯齿**，
  字号取 12 的整数倍：标题 96=8× / 提示 36=3×）→ 字形是锐利方块像素，与游戏内一致。

自检（`_screenshot.gd` 内置）：1920×1080 + 32 列 → 每格 60px；中心 300×300 区域独立色块 ≈ 16（≤~15 合格附近）。

## 元素清单（全部可调）
- **shader**（`wave_clash.gdshader`，自包含 fbm 噪声，无贴图）：
  - `clash_pos`(0~1) 对波边界；`blue_color`/`red_color` 可在 .tscn 的 ShaderMaterial 上改色
  - **竖直波列**（一波一波向中心推进，**非同心圆环** — 见研究发现）：`wave_freq` 密度 / `wave_speed` 速度
  - 压力前沿提亮 + 白热对撞缝 + 暗角（均按格采样 → 整格纯色）
  - `cells_x` 网格列数（粗细旋钮）；`color_levels` 限色（无抖动）
  - `intensity` 入场淡入 / 盖过瞬间闪光；`edge_jitter` 盖过时收紧边界抖动
- **文字**：经项目 autoload `FontManager`（Ark Pixel 像素字体 + 关抗锯齿），标题 96 / 提示 36（12 的整数倍）
- **脚本**（`wave_clash_title.gd`）：
  - 僵持期 `clash_pos` 在 0.5 附近双频率游走（互不相让的活感）
  - 加载阶段「加载中…」动态点，完成后「点击屏幕进入游戏」呼吸提示
  - 点击 → `randf()` 决定蓝/红胜 → tween 边界至 1.0/0.0（EASE_IN 加速盖过）→ 闪光收束
  - 进入游戏仅 `print` 占位，**不接入主场景**

## 研究发现
- **【美术方向 · Eddy 硬要求】冲击波是「竖直波列」一波一波向中心推进，绝不是同心圆环。**
  第 1 版误用 `length(到屏外源点)` 做成圆环，已纠正为相位只依赖横向 x 的竖直波。
- **【关键 · Eddy 诊断】"低分辨率缓冲再放大"是错路**：上采样的平滑插值会把方块糊成渐变
  （即一直"看不出像素"的真因）；用 dither 模拟渐变更是与"大块纯色"相反。**已弃用**，改为
  **shader 网格吸附法**——原生分辨率下每片元吸附到格心采样、整格填纯色，全程无上采样/无平滑/无抖动。
  这是唯一能保证"一格=一块纯色、格内零过渡"的做法。
- 粗块背景与中文像素字可读性的冲突，靠"文字层走原生高分辨率、不进网格"解决（背景格子粗细与文字清晰度解耦）。
- 验收方法（程序化自检）：截图后数一块 300×300 区域里的独立纯色数，远超 ~15 即太细。当前 24 列 ≈ 10，合格。
- 沿缝火花若用整行 y 取值会变成横向扫描条带（像故障）——已随网格化一并去除（缝改为按格的白热纯块）。
