# Battle AI —— 同时博弈短时最优 AI（2026-05-30）

> 命名约定：**v1 = 基础评估（`battle_eval.gd` / `BattleEval`，AI 现役默认）**；
> **v2 = 进阶评估（`battle_eval_v2.gd` / `BattleEvalV2`，叠加牌感项）**。
> 本文下方「初版 / 深度升级」指的是**搜索层的开发里程碑**（1-ply → depth-2 + 选人 AI），与评估档 v1/v2 是两个维度，勿混。

模拟"后期加入游戏的 AI"，并用 AI 自对弈批量积累平衡测试数据。

## 为什么不是"前瞻最优"

本游戏**双方同时盲选**（`select_action` → `resolve` 同时独立结算），不存在"看对手出招再最优应对"。
真正的短时最优 = 求**这一回合零和博弈的纳什均衡混合策略**：

1. 对每个 `(我方动作 i, 对手动作 j)` 组合，`clone()` 战局 → 提交 → `resolve()` → `BattleEval.score()` 评估 → 收益矩阵。
2. `regret-matching` 迭代解出我方**混合策略**（带概率，不可被对手稳定剥削）。
3. 按概率抽样一个动作。

因 `BattleEval.score` 关于双方反对称（所有项均为"己-对手"差 + 胜负翻转），博弈是零和的，
双方各自独立解同一矩阵 → 得到一致的均衡策略。

## 文件

| 文件 | 职责 |
|------|------|
| `battle_eval.gd` | **v1 基础评估** `score(battle, player) -> float`（己方视角，越大越好）|
| `battle_eval_v2.gd` | **v2 进阶评估**（v1 之上叠加牌感项：斩杀威胁 / 延迟伤害；profile=1 启用）|

## v1 评估权重（锁定记录，单位=半点 1HP=2半点）

| 项 | 权重 | 依据 |
|----|------|------|
| 胜/负终局 | ±1,000,000 | 绝对优先 |
| 存活英雄数差 | 600/个 | 杀一人=去身体+kit，远超残血 |
| HP 总差（含替补） | 10/半点 | 1HP=20 分 |

| 护盾差 | 6/半点 | 约半 HP |
| 出战位 HP 差 | +4/半点 | 前线存活更重要 |
| 出战位燃烧 | ±30 | 易伤+禁疗 |

## 深度升级（2026-05-30）：剪枝 depth-2 + 选人 AI（搜索层里程碑·非评估档 v2）

- **对战 AI 加深度**（默认 `search_depth=2`）：子局不再静态评估，而是再解一层 1-ply 子博弈取博弈值
  → AI 能看到"铺垫/攒→下回合收益"和"别同归于尽"，从而**会用主动技、减少换死平局、缩短对局**。
  深层用动作短名单（`_shortlist`）剪枝 + 较少迭代控成本。`depth=1` 退化为纯 1-ply（初版行为）。
- **`draft_ai.gd` 选人策略 AI**：对齐 bp 流程（BAN 3 → PICK 3，盲选）。结构化组队（HP 派生角色：
  坦克≥6 / 灵活5 / 脆皮≤4，按曲线均衡 + 温度探索保覆盖），BAN 偏高 HP 威胁。**无 per-hero meta
  偏见**（不硬编 combo 配对），避免污染平衡测量；深层成对协同留作后续。

## 已知局限

- **depth-2 仍看不到长尾**：能捕捉主动技的**短期**回报（如 h14 当回合以生命支付行动消耗），但看不到
  **多回合**链（h28 契约喂 6 回合 / h10 全队多回合蓄剑意）→ 最长 horizon 的连接件英雄仍被低估。
  ——这正是道具系统（降 combo 执行门槛）作为设计层解的价值所在。
- **drafter 偏好会影响覆盖**：择优组队会少抽弱势英雄；温度探索缓解但不消除（弱势英雄样本偏少）。
- **随机效果单次采样**：评估带随机分支的道具或技能时，克隆体重播种取单次独立样本（无偏有噪）；多次平均 EV 待优化。

## 运行模拟器

```bash
godot --headless --path <proj> --script res://tools/sim/run_sim.gd -- --games 100 --seed 42 --depth 2
# 参数：--games N / --seed S / --pool A-B（默认 1-34）/ --max-turns T / --out DIR
#       --depth N（AI 搜索深度，默认 2；1=快速 1-ply）/ --draft 0|1（默认 1=DraftAI 选人）
#       --profile 0|1（评估档 v1/v2）/ --w K=V[,K=V]（双方同权重·生态观察）
#       A/B 头对头（交替先后手）：--ab <变体> / --plan-ab 1 / --upgrade-ab 1 / --eval-ab 1 / --pick-ab 1
# 输出：sim_games.csv + sim_summary.md（胜率/回合/动作/伤害来源占比/大波拦截/各英雄胜率+主动技率/加时赛）
# ⚠ Eddy 硬规（2026-07-03）：AI 优化期一律小轮 50-100 局；500+ 大轮留收官最终确认。
```

## 测量惯例：双轨 + 交叉面板（T1·2026-07-03 Eddy 立）

**每次平衡相关改动**（数值 / 道具 / 英雄 / AI 共享层）跑一次面板（并行版·约 20 分钟）：

```bash
bash tools/sim/run_panel_parallel.sh <改动名>          # 默认 seed 42 / depth 2 / 50-50-60 局
# 串行后备：godot ... --script res://tools/sim/run_sim.gd -- --panel <改动名> --seed 42（~50 分钟·结果一致）
```

三份小轮：**v1 内战 50 局**（大众生态）/ **v2 内战 50 局**（高端局生态）/ **v1×v2 交叉 60 局**（强度追踪），
产出 `tools/sim/out_panel_<改动名>/panel_summary.md` 对照表（out_* 目录不入库）。判读三条：
1. 生态两列结论**一致** → 采纳该平衡判断；**不一致的行 = 对玩家水平敏感的设计**（新手陷阱 / 高手专属强度·单独标记）。
2. 交叉 decisive 大幅偏离 50% → 评估档强度漂移，复查最近改动。
3. 小轮噪声 ±5-8%，只对 ≥10% 的差距下结论；固定 `--seed 42` 保持历次面板可比。

速度：depth-1 ~1.3 s/局；**depth-2 ~6 s/局**（200 局≈21 min / 500 局≈52 min）。
